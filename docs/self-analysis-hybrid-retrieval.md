# 自我剖析：中文语义模型与混合检索

更新：2026-10-18。实现分支：`codex/self-analysis-hybrid`。本说明对应当前代码，操作见[自我剖析](self-analysis.md)。

## 模型选择

目标是普通 Windows 电脑一键建立中文短聊天样本库；不要求 GPU、Python 包安装、模型账号或外部 embedding 服务。模型没有专门针对本人的聊天训练。2026-10-18 已完成同一套 160 查询、480 候选的冻结合成集对照，比较三模型的词项、语义和混合检索及 CPU 延迟/内存；[正式 benchmark 报告](self-analysis-benchmark-2026-10-18.md)记录方法、结果和局限。

| 候选 | 官方规格 | 本轮判断 |
| --- | --- | --- |
| BGE-small-zh-v1.5 | 中文，约 24M 参数，原始模型约 95.8 MB，512 维，512 tokens | 继续默认；本机 hybrid test nDCG@4 0.6928，分量相加热查询 P95 55.9ms，编码进程峰值 216MiB |
| BGE-base-zh-v1.5 | 中文，约 102M 参数，约 409 MB，768 维，512 tokens | hybrid 0.7150，小幅优势 +0.0223 未达预设更换门槛 +0.03；P95 101.5ms、峰值 538MiB |
| Qwen3-Embedding-0.6B | 0.6B 参数，最多 32K tokens，最高 1024 维，支持指令与多语言 | hybrid 0.7117，与 small 差值区间跨零；P95 340.9ms、峰值约 2095MiB，下载资源约为 small 的 25 倍 |

规格来源：[BGE 官方模型说明](https://bge-model.com/bge/bge_v1_v1.5.html)、[BGE 国内模型卡](https://modelscope.cn/models/AI-ModelScope/bge-small-zh-v1.5)、[Qwen3-Embedding 官方仓库](https://github.com/QwenLM/Qwen3-Embedding)。这些通用评测不能证明中文私人聊天的质量，也不能证明关系分寸会自动改善。

采用 FP32 ONNX，避免本轮再引入量化精度变量。下载来源是 [ModelScope 上的 Xenova 转换镜像](https://modelscope.cn/models/Xenova/bge-small-zh-v1.5)，固定 revision `313386ad7ffad360a4870fd1910f8ecaf1a05151`。`model.onnx` 为 94,851,877 字节；加上分词器配置与模型卡，总计 95,292,426 字节。每个文件的完整 URL、长度和 SHA-256 固定于 `scripts/embedding-model.json`。本机实际验证了文件哈希及 ONNX 推理；没有访问 Hugging Face 下载权重。

## 一键准备与本机运行

用户点击原有建库按钮后，后台同时读取历史、提取词项样本和准备语义模型。状态查询不自动下载模型。下载只访问清单允许的国内 HTTPS 主机，逐次校验重定向；支持 `.part` 续传，完成后先校验长度和 SHA-256，再原子替换为有效文件。失败显示可重试状态，保留已完成资源，关键词库仍可使用。

资源保存在 `.local/core/embeddings/bge-small-zh-v1.5/`，各账号共享公开模型；聊天样本和向量仍按账号隔离保存在原插件数据库。暂停或清空个人知识库停止该账号的向量整理，保留共享模型缓存。重启后从已保存的样本与向量进度继续；没有实时自动学习全账号新消息。

Core 提供固定模型的 `embeddings/status`、`embeddings/prepare`、`embeddings/embed`。自我剖析不能指定任意 URL、加载任意远程模型或另配生成服务。实际推理由已有模型网关通过本机 ONNX Runtime 执行，复用现有分词器与运行依赖；本地 CPU 服务使用网关公平排队，单次运行一批、查询优先。模型启动不依赖生成服务已配置。

NumPy 数值运行时在独立后台线程预热，首次加载 DLL 不占用状态或查找请求。预热期间仍提供词项检索；失败时显示降级原因，可在重启后重试。

分词器只读取本机 `tokenizer.json` 和 `tokenizer_config.json`。BGE 使用最后一层的 CLS 向量，L2 归一化为 512 维；查询添加官方检索指令，样本不加指令。长文本截断时保留末尾的近期情境，同时保留 CLS、SEP 和查询指令。一次最多编码 16 条，样本前文最多 2400 字，再按 512 tokens 限制。

## 索引与召回

1. 样本沿用“当时前文 → 本人连续文字回复”，不将对方的文字当成本人风格。只编码前文情境，回复正文留作生成示例。Unicode emoji 随文本保留；独立表情包、图片、音视频不进入此索引。
2. 旧库进行数据库结构迁移，无需导出或重新安装。向量逐批补建，记录模型身份、编码版本、维度和前文摘要；输入变化或模型版本变化时重算。增量更新同时处理新消息。暂停、清空、来源变化或样本排除后，晚到的向量不能重新写回无效样本。
3. 词项路保留字符/相邻双字/英文词索引与场景加权。语义路将当前上下文编码，在当前账号所有符合时间、来源和排除条件的向量中独立召回，不受词项命中或其 500 条预选限制。
4. 语义扫描按 512 条向量一块进行 NumPy 计算，每块约 1 MiB；只保留前 64 个候选。单次扫描预算为 2 秒，大库超过预算会返回 `semanticPartial` 和扫描量，不把部分扫描宣称为全库检索完成。
5. 两路前 64 名通过 RRF 融合（常数 60），精确词项覆盖有小幅加权，联系人和场景作为轻权重。之后去重、限制每个联系人最多 2 条，并回查原文。建议流程最多使用 4 个样例。

向量不可用、模型失败或缺少数值运行依赖时，明确退回词项模式。向量不是对话事实；语义相近也不表示相同关系或意愿。现有当前关系资料、本人明确偏好和来源边界仍参与最终生成判断。

## 接入回复建议

自我剖析沿用 `self.context` 向已有 `kyf.message-insights` 提供表达参考。当前对话与联系人事实、用户本人资料、历史表达示例分别组织；示例只参考表达方式，不搬用其他人的称呼、经历、安排或承诺。生成前后的源版本与原文校验保持有效，构建更多向量本身不取消正在生成且原文仍有效的候选。

查询编码的网关总等待上限为 2 秒，语义扫描另有 2 秒预算；跨插件读取最多等待 6 秒并可降级。建库批量推理允许较长等待。超时取消单次请求，不关闭共享生成网关。数据只在本机编码；最终被选出的少量样例仍会交给用户配置的生成模型，输出原有三条可复制候选，不发送微信或覆盖草稿。

## 验证与边界

- [冻结合成集 benchmark](self-analysis-benchmark-2026-10-18.md)使用 120 条 test 查询、三轮 CPU FP32 测量。small hybrid 相对词项 nDCG@4 提高 0.04188，配对区间 [0.01826, 0.06527]，支持保留混合路线与现有默认。来源和标签由 AI 编写及复核，未穷举全部相关对，不能作为真人回复质量结论。主表延迟不含线上 SQLite 语义扫描、原文核对或最终生成，扫描扩容另测。
- 使用已下载的真实 ONNX 模型，对 12 组固定编写的中文改写检索做小型回归：12/12 预期情境排第一。测试位于 `tests/embedding-model.test.cjs`；没有本机权重时跳过，测试不会下载。它验证分词、池化与基本语义召回，不能作为真实私人聊天准确率。
- 核心边界测试使用合成资源和假网关，验证国内来源、文件校验、续传、身份与向量校验、账号变化和超时取消。
- 插件测试用可控编码器验证零词项重叠的跨联系人语义召回、精确关键词保留、降级、旧库补建、版本失效及清空/排除竞态。双插件集成验证只把语义命中的样例交给回复建议。
- 未读取真实聊天、未建立真实私人库，未训练或微调。没有新增图片/语音理解、模型重排、自动风格总结、人格推断或反馈训练。复杂关系分寸仍需要真实使用评价及后续改进。
