# 知己分析 v2：五个页签与统一分析需求

产品：知己微信助手 · Zhiji WeChat Assistant。更新日期：2026-10-12。品牌名称按[当前约定](branding.md)更新。

状态：2026-10-12 已在私有开发中实现，使用说明见 [知己分析](friend-analysis.md)。主聊天开关在此之前已改名为“分析与建议”，不再与“聊天分析”页签重名，因此下文“改名为逐句分析”一项不再执行。2026-10-12 用户在评审后确认四项选择：**先出近期概述、全历史分段提取证据、AI 判断与人工修正独立、人格展示以描述为主**。本文件在相关条目上取代 [知己分析多窗口与关系记忆迁移需求](friend-profile-requirements.md)（以下简称“v1 需求”）中“只有三个栏目”“各页各自有分析按钮”等规定；v1 中未被本文件改动的规则（多窗口、草稿暂存、记忆查重、证据核对、账号隔离、关系趋势口径等）继续有效。

状态复核（2026-11-02）：**原 v2 主体已实现**，包括统一分析、近期概述、全历史证据提取、AI 与人工修正分离及关系趋势。当前性格与三观展示已有后续演进，以[知己分析说明](friend-analysis.md)为准。第 9 节中的好友分期人格图表、群聊人格等仍属后续方向，统一见[需求待办清单](requirements-todo.md#future)；不能因后续方向尚未立项而把原 v2 标为未开发。

本轮要点：

- 知己分析窗口改为五个页签：**好友概述 / 关系记忆 / 人格分析 / 聊天分析 / 关系趋势**，默认打开好友概述。
- 原“好友分析”改名“聊天分析”，把我方消息也纳入分析，重点看对方如何回应我。
- 新增“人格分析”（参照旧项目“人物分析”）和“好友概述”（参照旧项目“总览”），两者都做简化与优化。
- 整个窗口只有一个“分析”按钮。首次分析需要点击开始，先出近期概述，再补齐全历史分析；之后打开窗口自动做增量分析。主界面显示进度与预估耗时，token 明细折叠，分析可以取消。
- 人格证据从全部可读历史分段提取，不用时间抽样替代；AI 判断不读取人工修正，双方以文字描述并列展示。
- 主聊天标题旁原来的“聊天分析”开关改名为“逐句分析”，避免与新页签重名。
- 界面延续简约、贴近微信电脑版的风格，没有必要的元素不出现。

## 2. 统一分析

### 2.1 按钮与步骤

- 窗口顶部、联系人名称右侧只有一个主按钮。状态依次为：“开始分析”（从未分析过）→ 运行中变为一行进度和“取消” → 完成后为“更新分析”。“更多”菜单另有“重新分析全部…”，用于换模型或分析规则升级后重做，同样先显示预估再确认。
- 一次分析采用“近期结果先出、全历史随后补齐”的流程。仍是一个统一任务，不要求用户分别启动各页：

| 顺序 | 步骤 | 处理内容 | 相关输入未变化时 |
| --- | --- | --- | --- |
| 1 | 准备聊天记录 | 本地优先读取最近一到两次对话，同时启动或复用全部可读历史的读取；不调用模型 | 核对来源与覆盖，复用有效记录 |
| 2 | 近期概述 | 用近期原文、当前目标和已有已确认记忆生成摘要与下一步，不等全历史建档或人格分析结束 | 跳过 |
| 3 | 历史建档 | 全历史读取就绪后分段更新记忆候选及独立的人格证据索引；后者不进入事实记忆库 | 跳过已覆盖且有效的分段 |
| 4 | 聊天分析 | 双方消息和互动轮次的情绪、意图与回应方式标注，见第 4 节 | 跳过已覆盖且有效的轮次 |
| 5 | 人格分析 | 基于全历史累计证据综合判断，再逐项核查，见第 5 节 | 跳过 |
| 6 | 补齐好友概述 | 本地刷新“关于 TA”等汇总；仅摘要或下一步所用输入变化时重新生成相应内容 | 跳过模型调用，保留近期结果 |

- 近期原文必须使用与完整历史相同的账号、来源、消息身份及内容校验。不能为了先出结果再建一份永久聊天库；已有历史读取的全量等待接口不能成为近期概述的前置条件。近期会话边界未读全时标明实际范围，不能声称覆盖完整对话。
- 关系趋势是本地即时统计，不算模型分析步骤，随时可看。历史读取中只展示实际覆盖，不能将未读范围记成零。
- 记忆与聊天分析只处理新增或已失效的分段，轮次边界保留必要上下文；人格分析使用“累计证据 + 新证据”重新综合，不能只用新增几条消息覆盖长期判断。历史回填、内容变化及来源重建沿用 v1 的检查点核对规则。
- 各步骤单独判断依赖：人格分析依赖原文证据、经原文核验的已确认记忆及聊天分析版本；不依赖联系目标、自己的资料或我的修正。近期摘要依赖所覆盖的近期原文，下一步还依赖目标和所用已确认记忆。“关于 TA”仅随对应人格结果与记忆做本地刷新。相关输入、证据状态、模型和规则版本都未变化时才跳过。
- 确认、编辑、删除记忆或修改目标时，仅使受影响结果待更新；不重跑全部历史。窗口内提交这些修改后也检查依赖，按自动增量门槛处理；取消、失败或中断状态优先，不能被资料变更绕过。修改我的修正只更新对照与原有助手资料版本，不触发人格重算。
- 某一步失败时不清空其他页。后续步骤可在依赖足够时使用已有结果继续，但要保存并展示旧资料的版本、范围和“使用旧资料”标记；缺少必要依赖则跳过并说明。失败步骤在任务详情提供“重试”，整次任务标为“部分完成”，不能伪装为全部完成。失败步骤重试成功后，重新检查下游依赖。
- 记忆候选的确认与忽略、手动新增记忆、我的修正，以及联系目标和自己的资料仍是手动操作，不属于“分析”。

### 2.2 何时开始

- **首次分析**：联系人从未分析过时，打开窗口可以读取本地记录，但不自动调用模型。主按钮旁优先显示近期概述与完整分析的预估耗时，token 范围与各步骤明细折叠展示；点击“开始分析”才启动模型步骤。历史未读全时，全量预估标“待历史读取完成”，不假装已知精确总量。
- **之后打开窗口**：先刷新聊天历史，再自动开始增量分析，与 v1 打开窗口时自动更新记忆的规则一致。
- **增量较大时**：例如很久没打开、积累了大量新消息，增量预估超过门槛时不自动开始，改为显示预估并等待点击。门槛默认 10 万 token，可在设置中调整（实现建议）。
- 分析规则升级（例如聊天分析改为双方标注）使旧结果需要重做时，按首次分析处理：保留并标明旧结果，显示预估，点击后才重做。
- 停止、失败或中断的分析，再次打开窗口时显示“继续 / 重试”，不自动重启。普通切页或系统焦点变化不触发；已有任务按账号与联系人复用，不重复排队。

### 2.3 预估 token 与耗时

- 开始前按步骤估算：待处理消息的字数、分段或分批数量、每次请求的固定提示词、预计输出长度，以及人格分析、好友概述的固定上下文预算，汇总成 token 范围。点开预估可以看到各步骤的明细。
- 耗时依据同一模型、相同步骤的实测吞吐，分别估算近期概述与完整分析；排队等待单独显示。没有实测时显示“耗时暂无法估算”，首批完成后更新。不为预估额外调用模型，也不写死分钟数作为性能承诺。
- 运行中和完成后记录每一步的实际输入与输出 token（优先使用模型服务返回的用量，没有时按字数估算并标“估算”），用于修正下次预估，并在任务详情中显示“本次消耗”。
- 本地 Laya 分类步骤标为“本地处理”，不计 API token 用量；不能据此声称它具备记忆提取、概述生成或人格综合能力。未配置生成模型时，这些步骤明确显示“需要配置 API 模型”，本地统计与既有 Laya 能力仍可用。

### 2.4 进度、取消与排队

- 运行中主按钮位置显示一行，例如“历史分析中 · 聊天分析 · 320 / 860 条 · 取消”；近期概述完成后可显示“近期概述已就绪”。点击进度展开各步骤状态：已完成、进行中、等待、已跳过、失败，以及已用 token、耗时与最后活动时间。统计区分消息数、互动轮次数与模型调用次数。等待模型时显示“等待模型返回”。
- “取消”停止当前步骤和后续步骤，包括仍在排队的任务，并尽可能取消正在执行的请求；取消后到达的结果不得提交。已成功提交的批次、检查点和已完成步骤的结果保留，必须手动点击“继续”才接着做，重新打开窗口不会自动恢复。
- 关闭窗口不取消分析，重新打开读取真实状态，沿用 v1 第 3.2 节。
- 多个联系人窗口同时分析时排队，默认同一时间只分析一个联系人，其他窗口显示“排队中 · 前面还有 N 位”。后台分析让位给主动提问和自动回复建议，沿用 v1 第 5.2 节。
- 应用重启后显示“已中断，可继续”，不自动补跑。
- 各页在分析进行中照常显示已有结果；某一步完成后只刷新对应页面。

## 3. 好友概述

好友概述是默认页，回答“这个人是谁、我们最近怎么样、接下来怎么聊”。它汇总其他页面的结果，只有“最近对话摘要”和“下一步”需要调用模型。

点击开始后，先使用已核验的近期原文生成这两项；全历史读取、建档或人格分析尚未完成时也能看到近期结果，并标“历史分析中”。尚不存在的历史结论留空，不用猜测补齐。后续历史步骤失败或取消不撤回已发布的近期结果；若整个任务在近期请求完成前被取消，则遵守取消语义，不继续提交该请求。

从上到下：

1. **事实行**（本地，不调用模型）：可读记录中的最早聊天日期 · 共 N 条消息 · 最近联系（例如“3 天前”）· 联系目标。数据来自可读历史和关系趋势；历史未读完时标“统计中”，不把本地最早记录说成两人实际第一次聊天。
2. **最近聊到了这里**：只总结最近一到两次对话。对话按关系趋势的口径切分，相隔 8 小时以上算新一次对话。摘要 80–180 字，标出覆盖的日期范围，可以点开在窗口内查看所依据的原文。
3. **下一步**：一句话建议，结合联系目标、最近对话和已确认记忆。最后一条消息是我发的时，优先建议等待对方回复，不催促补发。不预设恋爱或约会目的。
4. **关于 TA**：3–4 条要点，取自人格分析中把握程度较高的维度和已确认的记忆，不另外生成新的性格结论；每条可点击跳到对应页面。
5. **值得记住**：最近或最相关的 3 条已确认记忆，点击“全部”跳到关系记忆。
6. **关系变化**：一句话，取自关系趋势最近两个完整周期的对比，例如“上个月联系 12 天，比前一个月多 4 天”；数据不足时不显示。

- 摘要和下一步分别按第 2.1 节的依赖判断是否重新生成，不因“全历史任务完成”本身无条件再调用一次模型。新提取但未确认的候选不进入这两项的事实输入；用户确认后再使相关内容待更新。“关于 TA”“值得记住”“关系变化”随可用结果本地刷新。
- 底部一行小字说明来源，例如“依据 10/08–10/09 的对话与 16 条已确认记忆 · deepseek-v4 · 10/09 01:38”，不展开长说明。
- 从未分析时，第 1、5、6 项照常显示，第 2–4 项只显示一句“开始分析后显示”，不排列一堆空卡片。
- 与旧项目“总览”相比，去掉：最近三条对话（主聊天就在旁边）、话题灵感（已有自动回复建议）、英文小标题、标语与装饰性图标、页内重复的“更新分析”按钮。

## 4. 聊天分析（原“好友分析”）

### 4.1 为什么要改

现有 API 模式已经把双方消息都发给模型，但我方消息只作为上下文，而且模型给整批对方消息返回一份综合标签分布，并非逐消息或逐轮判断。本地 Laya 模式同样只分析对方消息。旧批次分布不能直接换算成“你提问后对方展开的比例”。本轮需要新增可回查到原文的消息与互动轮次结果，而不只是增加页面字段；不能把一份批次判断复制成多次独立样本。

### 4.2 分析内容

- **我方消息也打标签**：我的意图（提问、分享、邀请、关心、玩笑、请求帮助、回应等）与情绪信号。
- **回应方式**：以我方连续消息块和随后对方连续消息块组成一次互动，判断接住并展开、简短回应、转移话题、明确婉拒、与上文无关的新话题；无法判断的独立记录，不强行分类。另用独立字段记录邀请的明确接受、明确婉拒、未明确答复或无法判断，不把沉默命名为“回避”。
- **本地汇总**：按我方主要意图统计可判定互动的回应方式比例，例如“你提问后，对方约 70% 接住并展开”。一轮只计一次；混合意图无法确定主项时单列，不重复加入多个分母。显示样本数、日期范围及未判定数；可判定样本少于 5 次时不给比例，只写“仅 N 次”。每条结论可以展开查看原文例子。
- **回复率**：按我方连续消息块计算，连续发三条、对方回复一条算一次互动，不算三次机会。分母仅包含从我方块末尾起已有完整 24 小时观察覆盖的有效轮次，分子是其中在 24 小时内发生对方回应的轮次；观察时间不足的单列“观察中”，不当未回复。未知顺序、缺失覆盖等排除并记原因。每条回应只配对最近一个有效我方消息块，不能重复配对多个轮次。回复时间沿用关系趋势的我方块末尾到对方块首条的中位数规则。时间与方向统计本地完成，不调用模型；现有趋势没有回复率分母，需补齐共享口径。
- **保留现有内容**：对方的情绪信号、交流意图、高频词和互动表现；我方的情绪信号与交流意图与对方的并列，便于比较。高频词默认显示对方，可切换到我方。
- **互动评分**（原“好感度”）继续折叠在“已有分析详情”中，标明评分方法已知存在问题。
- MBTI 倾向移到人格分析，聊天分析不再显示。

### 4.3 约束

- 回应方式只描述聊天中可见的行为。不把慢回复、简短回应直接解读为冷淡、疏远或隐藏情绪；没有回复只计入回复率，不推测原因。
- 邀请只有在对方之后明确答复时才算接受或婉拒；没有明确答复的标“未明确答复”，不当作拒绝。另有表情等回应也不能误写为没有任何回复。
- 只回复表情、图片、语音或视频也算发生了回应；内容未读懂时，回应方式标“无法判断”，不能按占位文字推测情绪或意图。微信已有语音转写可以作为文字输入，须保留来源和识别误差标记；本轮不新增媒体理解模型步骤。
- 引用、转发的内容不作为发言人本人的自述，但引用消息中本人新写的正文可单独分析。回应是否发生与表达内容能否归因分开处理；同秒歧义、未知方向或时间的消息不参与回应方式和回复率。
- 互动结果保存双方消息身份、内容版本与对应轮次，支持跨批次边界的必要上下文及去重。只计完整提交且有效的轮次；一轮不能因切段、重试或续跑被重复计数。
- 分析规则改为双方标注后，旧结果需要按新规则重做全部历史，按第 2.2 节首次分析处理。重做完成前继续显示旧结果并标“旧版结果，需重新分析”。
- 回应方式需要 API 模型。本地 Laya 模式保留现有的对方情绪与意图统计，回应方式一栏显示“需要配置 API 模型”。

## 5. 人格分析

### 5.1 维度

| 类别 | 维度 | 结果形式 |
| --- | --- | --- |
| 类型 | MBTI | 区分本人自述与有依据的聊天倾向；推测标把握程度 |
| 相处观察 | 对联系频率、回应延迟、亲近与距离的明确表达及可见行为 | 用具体行为描述，不据此自动判定依恋类型；如本人自述依恋类型，单列原话与日期，不作诊断 |
| 议题观点 | 本人明确表达过的公共议题观点 | 按议题归纳原话、时间与来源，不推断整体政治身份或阵营；无明确表达时不生成标签 |
| 行为倾向 | 表达方式（直接—委婉）、社交偏好（独处—社交）、安排习惯（随性—计划）、尝试偏好（熟悉—尝试）、情绪表达（含蓄—表达）、边界表达（灵活—明确）、分歧沟通（暂缓—及时讨论） | 简短描述、说明与把握程度；无数字分值或位置条 |

- 行为倾向沿用旧项目“人物分析”的七个维度和两端名称。
- MBTI 的四个轴分别给出把握程度；某个轴证据不足时该位显示“?”。既有四轴统计可作辅助，但它不是原文引证，须通过本轮证据索引回查，不能只凭旧分数生成字母。
- 相处观察只描述聊天中可见的行为及局限，不把联系频率或回复快慢归因为稳定心理类型。议题观点不从地区、职业、年龄、姓名、头像等身份信息推断，也不绘制政治光谱。
- 每个推测输出把握程度，分为四档：**较有把握 / 有一定依据 / 把握较低 / 无法判断**。“较有把握”需要不同时期的多条原文一致支持，不能把模型自报置信度当成准确率；本人明确自述单独标“本人自述”。没有足够依据时写“无法判断”，不用中点 50 填补。

### 5.2 依据范围

- **全历史分段提取，再综合分析**：首次扫描全部可读历史中的有效本人正文，双方上下文按需保留。按实际上下文与输出预算切段，长消息继续拆分，不静默截断，不用按年抽样、最近 N 条或 Top-N 片段替代扫描。对媒体占位、引用等不可归因内容记录排除原因，不宣称理解了未读的媒体。
- 每段提交覆盖范围、输入内容版本、完成状态和结构化证据；无有效证据的分段也保存“已处理、无证据”检查点。证据至少保留维度、原文身份、时间、上下文引用、支持或反例及模型和规则来源。该索引与已确认关系记忆分开保存，不自动把推测写成事实。
- 汇总采用有预算的分层处理：每个已完成分段的结构化结果都进入汇总链，保留支持、反例及早期与近期差异。摘要可辅助压缩，但不能替代可回查的证据索引；超过预算时继续分批，不静默丢弃低频或早期证据。最终展示可挑选代表性引文，不等于分析阶段只读这些引文。
- 页面顶部写明实际覆盖，例如“已处理 2020–2026 年 1,240 条有效对方原文”，详情区区分已读消息数、已处理有效原文数、排除数和引用数。尚有未完成或失败分段时显示“历史分析未完成”，不声称全量完成。
- 后续从有效检查点继续提取新证据，再和已有证据综合；历史回填、原文变更或证据失效需要使对应分段与下游判断待更新。已确认记忆只有经有效对方原文核验的部分才能辅助人格分析；用户手工判断、自己的资料、联系目标和我的修正不得绕道成为人格证据。
- 早期与近期表现明显不同时，在该维度说明里分开描述，保留时间范围，不平均成单一位置。
- 沿用先生成、再逐项核查的两步做法：系统先核对证据归属、身份和内容版本，再由模型核对原文是否支持判断。核查不通过的维度改为“无法判断”，详情记录原因；两次模型判断不等同于已证实事实。
- 每个推测至少引用两条不重复的对方本人原文，并保留相反证据；本人明确自述可由一条原文支持“本人自述”，不据此证明客观人格。引用、转发和我方消息不能作为对方的人格依据，但我方消息可以作为理解对方回应的上下文。

### 5.3 布局

- 每个维度一行：名称 · 简短描述 · 把握程度，例如“表达方式 · 偏直接 · 有一定依据”。不显示 0–100 分值、刻度或位置条；有人工修正时，用独立的“我的观察”文字并列展示，窄窗口可在同一项内上下排列。类型维度例如“INFP 倾向 · 把握较低 · 推测”或“ENFP · 本人自述”。
- 点击一行展开：说明、依据原文（复用窗口内的证据查看组件，可看前后各 5 条上下文）和“修正”。
- 判断为“无法判断”的维度合并成一行“证据不足：分歧沟通、边界表达”，点开再逐项查看，不排成一墙空卡片。
- 页面不放单独的生成按钮，由窗口顶部的统一分析生成。

### 5.4 我的修正

- v1 的“我的观察”和旧项目的“我的修正”合并为一个功能，放在人格分析页。
- 修正可以关联某个维度（填写文字判断与依据备注），也可以不关联维度，作为“其他观察”列在页面底部。现有观察数据原样迁入：已关联维度的挂到对应维度，其他的进入“其他观察”；若原数据有数字位置，只保留原数据供兼容，不作为新判断依据或默认展示。
- 模型重新分析不覆盖修正；同一维度同时显示 AI 结果与我的修正。修正是我的主观看法，不进入已确认事实库，沿用 v1 第 6.1 节。
- **独立对照**：人格证据提取、综合生成及逐项核查都不读取我的修正；其 AI 输入版本与缓存键不包含修正版本。修改或删除修正不触发人格重算，也不改变 AI 原有结论。主动助手和自动回复建议仍可依 v1 使用明确标为“我的观察”的资料，本条不撤销该既有行为，但这些意见不能回灌人格证据链。

### 5.5 约束

- 人格分析的 AI 推断均标“推测”，不写入关系记忆，不当作对方已确认的事实。明确自述与议题原话整理标“本人自述 / 观点原文”，与推断分开；独立的记忆提取流程仍可按 v1 保存有证据的自述候选。
- 不推断心理疾病或作临床诊断；不根据单条消息或一次行为定型。
- 推断只描述可见的聊天表现及其局限，不用于设计操控、施压或针对对方的话术。
- 自述以本人原话为准，引用、转述、玩笑、疑问句和“以前是”不算自述；多条自述互相矛盾时显示最近一次并注明存在差异。

| V2-DATA-01 | v1 的记忆、观察、画像缓存、聊天与助手记录全部保留；清除账号时新增证据、各代结果、检查点与 token 记录一并清理，迟到任务不能写回 |

自动化测试使用合成账号与消息，仓库中的测试、文档和截图不提交真实聊天或密钥。体验验收可以直接使用本机既有资料。
