# 自我剖析

自我剖析通过顶部统一入口整理本人资料、标签、经历时间线、性格分析、性格时间线、三观时间线、三观分析和表达知识库。八项输出共享当前账号的聊天快照、前后文与增量同步；资料、标签、性格和三观还共用一次证据提取，再分别汇总。每个账号独立保存，历史表达样本可以跨联系人检索。

## 第一次使用

1. 点击软件左侧的人像图标“自我剖析”，打开独立窗口。再次点击会回到已有窗口，主聊天保留当前会话。
2. 标题行右侧是“开始分析”按钮，旁边的下拉菜单里勾选要更新的项目并选择“基础／标准／深度”（默认深度）。上述八项输出可单选或多选，选择按账号保存；未保存过选择时默认仍选本人资料、标签、性格、三观和表达知识库。可选先在“本人资料”填写背景、自述和表达偏好；资料仍与原有“自己的资料”共用，AI 生成初稿供你审阅后保存。打开页面、改选项目或保存偏好都不会自动开始分析。
3. 一次任务先同步聊天，再运行已选项目。本机可读的私聊与群聊只由统一读取器同步，包含隐藏但仍有历史的聊天。任一 AI 项目需要共同证据时，统一提取事实、表达、标签和性格证据并保存；后续只汇总选中的项目。之后再选另一项目可复用相同证据。单选表达知识库不提取 AI 证据、不调用生成模型；知识库只从私聊有效原文提取表达样本，语义索引仍在本机完成。
4. 首批样本出现后即可打开“聊天试用”tab：左边检索历史回复，右边以好友身份给自己发消息，看看“我”会怎么回（见下文“聊天试用”）。也可回到私聊，开启该好友的“分析与建议”，再从好友消息菜单生成三条回复建议。剩余历史继续整理，不需要停留在页面。
5. 后续从顶部“更新分析”同步新增或变化的聊天；可暂停全部，也可在步骤旁单独暂停或继续一项，其他已选项目继续。需要共同证据的 AI 项目都暂停后，共同提取也暂停。当前请求退出并保存进度后才能继续；关闭页面不停止后台任务，程序退出后保留已完成批次。各页展示结果、依据及人工校正；“表达知识库”页底部可恢复已排除样本和清空知识库。

分析开始后，标题行下方弹出进度浮层，只列出本次实际执行的步骤；正常完成后自动收起，点击标题行的状态文字可再次打开。浮层逐步显示同步、各项分析及索引状态，同时显示实际处理数量和已用时间。同步区分本轮新读取的消息数、当前聊天读取位置和本地累计快照；模型步骤显示调用次数和当前调用耗时。提取与复核按整条本人原文完成量计数，长消息的所有片段完成后才计入；汇总阶段改用批次计数。各阶段工作量不同，不按步骤数平均计算总百分比。只有当前提取与复核阶段有多次实际处理记录后，才显示基于实测速率的剩余时间范围；它不包含后续汇总或其他阶段，读取聊天数也不用于推算模型耗时。语义索引可以与模型分析同时进行，单独显示样本完成量。

没有变化时复用已有原文、分析批次和最终结果，不调用生成模型。某个模型步骤失败时显示“部分完成”，其他可用结果保留；没有配置生成模型也能整理知识库及本地索引。旧聊天原文或上下文变化时重读相关聊天并使对应分析失效，人工内容保留。来源切换时保留旧资料并停止，避免混合不同来源。单个大聊天的来源准备允许持续超过三分钟；连续三分钟读取位置未推进时才按超时停止，已保存资料与断点保留。

首次建库自动准备约 95.3 MB 的中文语义模型，不需要安装数据库或运行命令。下载只获取公开模型资源，不上传聊天；语义向量计算、索引和查找均在本机 CPU 完成，不调用生成模型。模型准备期间，已整理样本仍可按关键词查找，语义索引可用后自动结合两路结果。下载失败从顶部继续；已验证完成的模型文件会复用，未完成文件支持续传。

生成三条建议仍使用核心“模型设置”中的连接。选中的少量历史样例会随当前对话交给该生成模型；本地语义模型没有代替回复生成模型。生成模型未就绪时，也能先建库与查找。

页面在打开、再次显示窗口或进入“聊天试用”时读取核心是否已保存回复模型配置，只在明确“尚未配置”时于对话区下方提示“去设置”；配置无法确认时不提示，实际生成时再确认连接。模型配置不影响建立知识库和检索历史回复。

“全部处理完”表示本次发现的可读取历史处理结束。软件无法恢复本机已经缺失的聊天；无法解析的消息分片和会话会作为缺口呈现，不算作已完成。已读消息数量包含双方消息；可用样本是实际提取出的“前文 → 本人回复”对数，两者不同。

## AI 初稿

统一分析的“本人资料”步骤调用核心“模型设置”中的回复模型，归纳“我是个什么样的人”和“我的表达习惯”，分别作为“背景与自述”和“表达偏好”的初稿。深度位于顶部，同时控制标签与性格分析的处理投入，不改变全部可读本人文字或本地索引的覆盖范围。

- 需要可读取的聊天来源和已保存的回复模型配置，不要求先建立回复知识库。首次读取本机可读的全部私聊和群聊，把你本人发过的文字保存在按账号隔离的本地数据库，包括主动发言、短回复和较早记录；之后生成只同步新增或变化的聊天，复用已保存的文字。不会只选最近 1500 条，也不限制总批次数。长消息分段后完整分析，不截掉正文。
- 外部聊天导入中已确认保存的记录也会同步：属于当前微信账号的好友和没有微信的外部好友，每个导入来源算一个聊天，名称标为“好友（来源·外部聊天）”。只取你发的文字作为本人原话，对方的文字作上下文；截图通常没有时间，上下文按画面顺序取前后相邻的消息。每次同步都从核心重建这部分，导入里更正、删除或隐藏的内容随之更新；外部聊天不进入表达知识库，也不做微信原文核验。外部聊天暂时读不到时保留上次同步的内容，并显示为读取缺口（2026-10-25 起）。
- “分析深度”提供三个档位，按账号保存选择，默认“深度”。基础档共同提取后汇总；标准和深度档共用同一份原文证据，其中的明确兴趣、明确特征、本人自述和三观证据经过一次联合复核，切换这两个档位不重复提取同样原文。深度差异在各项汇总中体现，深度档更细致地保留不同时期、关系、差异与矛盾。三个档位覆盖相同的全量本人文字，不按长度、重复或是否主动发言筛选原文。
- 模型逐批提取尚未处理的共同证据，再分别汇总为资料、标签和性格结果；相邻消息在同一批里的重复上下文只传一次，通过引用还原，不缩小上下文窗口。批量随模型容量调整，输出容量不足时对未提交批次减半处理。空证据结果也缓存；新增消息、正文或后文变化只重提取对应输入。分层汇总按内容指纹缓存，未变化分组继续复用。文本框里已有的内容只在资料最终整理时交给模型，其中的事实以你写的为准；仅修改这些自述不会重新提取聊天证据。其他人的发言只作上下文，不当作你的自述；聊天正文中的指令不改变分析规则。
- 同步先比较聊天目录中的最新消息位置：与上次读完的位置相同，且已读前缀签名（消息数量与编号统计）未变时，直接跳过该聊天，不重读也不逐条核对原文凭据。只要有任何一项不同（来源、版本、读取位置或前缀签名），就按原流程检查来源元数据，并核对本人文字及其上下文的原文凭据；只重读需要更新的聊天。跳过的聊天里，如果早已读过的旧消息被原地改了内容，要等该聊天下次有新消息时才会发现（2026-10-25 起）；知识库样本在被检索到时仍会逐条核对原文。消息或上下文变化会使关联分析批次失效，其他有效批次与分层摘要继续复用。核验暂不可用时保留本地语料和摘要，暂停生成，避免把旧事实当成新资料。旧版本缺少完整上下文或校验凭据时，首次升级会补齐一次；不会清空已有资料库。
- 每条本人文字结合同一聊天前最多十二条、后最多六条有效文字，限定在前后各六十分钟内；前后文保留说话者、时间和消息标识，群聊区分不同发言人。上下文来自本次已读取的聊天快照，便于识别较早说明的动机、后续的澄清和撤回。
- 上下文有明确边界：邻近文字每条最多六百字，长段保留首尾并标明省略；模型容量不足时还可能缩短或省去整条前后文，并保留裁剪标记。时间未知或顺序不可靠的邻近文字不会直接接入已知时间的对话，会标明语境有缺失；缺少关键语境、短句指代不清时保守判断。本人正文仍逐字分段分析，每段同时带原消息首尾提示，帮助识别末尾的转述、否定或撤回，不能只凭局部片段认定爱好。
- 提取时对照本句和前后文，区分“仅提及”“偶尔参与”“明确兴趣”“明确特征”和“待判断”；标准与深度档再复核其中的强结论。例如在篮球场碰头、陪客户打球、转述朋友的爱好，都不能直接写成自己的兴趣；后面说“开玩笑的”“其实不喜欢”时，也要回看前句。分层归纳须保留原消息依据及否定、陪同、转述、不确定等限制，不能因同一主题在多份摘要或多个聊天中出现就升级为爱好；最终整理为第一人称初稿，弱线索可以省略或保留限定说法。
- 页面显示截至最近同步的本地累计快照，包括聊天数、双方消息数、本人文字总量、累计分析量、私聊与群聊数量、长消息分段和已完成批数；另外区分复用已有分析量和本轮新分析量，避免把累计数量误认为本次重新处理的数量。尚未完成同步时明确标明总量待确认，不把建库完成当作模型分析完成。完成、暂停或失败后仍保留覆盖统计与缺口；有聊天、历史文件或原始消息未能读取时，只显示“已完成可读部分”。本机已经缺失的记录无法恢复，无法据此声称微信全部历史均已覆盖。图片、语音等非文字和无法可靠归属的内容不参与，另行显示未参与数量。
- 可以“暂停分析”，已经完成的读取和分析批次保留断点，尚未完成的当前批次在继续时可能重新读取；关闭页面不会重新发起同一任务，再次打开会恢复查看运行状态。点击“继续分析”从已保存进度继续。更改档位会复用本地文字与该档位仍然匹配的摘要，再处理尚未分析的部分；不会因为切换档位或修改自述而从头读取聊天。聊天来源或原文版本变化时重新核对相关语料与分析，避免沿用过期证据。失败只显示简短原因，不显示模型服务的原始响应。
- 空着的栏目直接填入初稿；已有内容的栏目不会被改动，初稿显示在下方，点击“替换”才会覆盖该栏。初稿只是未保存的输入，点击“保存”后才写入。再次生成需要再点一次按钮。
- 插件只把初稿返回给页面，不能保存本人资料。各步骤共享一次后台核心任务及执行令牌，调用记录分别标明资料、标签与性格阶段。

## 标签

“标签”tab 汇总本人聊天中的主题与个人特征，例如“篮球”“象棋”“战略类游戏”“不吃香菜”“夜猫子”，按类别分组：运动健身、游戏棋牌、影音娱乐、阅读学习、美食饮食、旅行出行、工作技能、身份生活、性格习惯、观点态度、其他。每个标签同时标明你与它的关系，避免把谈过的话题直接当作爱好。

- 标签步骤直接使用统一快照中的全部本人文字及前最多十二、后最多六条、前后各六十分钟内的上下文，包含主动发言和短回复，区分私聊与群聊发言人。图片、转发、系统消息不作为本人文字。完整正文保存在本机，请求容量不足时保留首尾并明确标记截断或语境缺失，仅作“待判断”。
- 回复模型分批阅读这些消息，为每条证据区分“仅提及”“偶尔参与”“明确兴趣”“明确特征”“待判断”，同时返回支持原话和判断理由。例如“这部电影票价多少”只说明提及，“陪朋友看了一次”只说明参与；明确的喜欢、偏好或持续投入才支持兴趣，自述身份、习惯或能力等支持个人特征。转述别人、开玩笑、反问和代问需要结合前后文辨别；“对啊”等短认可也会结合它回应的内容分析。否定的偏好写成“不喝咖啡”这样的标签。
- “仅提及”“偶尔参与”和“待判断”都不能因为消息多、跨聊天或跨天出现而升级成兴趣。支持原话必须逐字引用本人消息：引用了同批另一条本人消息时归到那一条，只差空白字符（如 @ 后的特殊空格）时按原文字符保存，对不上的那一条证据单独丢弃，不连累同批其他证据；短认可可以用它回应的前后文解释，引用不能来自他人文字。明确兴趣、明确特征等强结论提取后再独立复核原话及前后文，只允许降低语义强度或剔除无依据的证据，不能升级、增加标签或补造证据。内容截断或语义不清时保留“待判断”。之后按类别整理同义名称，例如“打篮球”并入“篮球”，合并不把弱线索变成兴趣；不同事物和粗细不同的标签不合并。
- 语义类型与可信等级分开显示：已确认（你确认或手动添加的，绿色）；较可靠（有未截断、可核对本人原话支持的明确兴趣或明确特征）；可能（其他待核实线索，虚线框）。人工确认只改变可信等级，不把“仅提及”改成“明确兴趣”。标签旁的条数、聊天数与日期只是关联消息统计，不作为爱好或稳定特征的判定阈值。手动添加的标签标明“手动添加”，无需替你推断语义类型。
- 点击标签，右边显示关联原话：聊天名称、日期、前后文、你说的话、该条证据的语义类型、支持原话和判断理由，按时间从新到旧，最多显示 50 条；截断内容另有提示。可以“确认”、“取消确认”或“删除”；删除后可以立即“撤销”。“添加”可以手动加标签并选择类别。
- 你的确认、删除和添加按标签名保存，重新分析、合并或换到其他聊天来源都不会覆盖：删除的标签不会再出现，也不会作为已有名称推荐给模型；确认过的标签不会被合并到别的名称下。
- 标签由顶部任务统一调度，只消费共同提取的标签证据，不再单独逐批重读原文。基础档提取，标准与深度档对强结论共用一次联合复核；复核不能增加标签、改引用或升级语义。原文、前后文、模型或提取规则变化时对应输入重新提取，新增后文也会使受影响旧消息的自动依据失效。当前输入没有变化时复用证据和同义汇总缓存，消失原文的自动依据被移除；人工确认、删除和添加继续保留。
- 统一分析遇到聊天来源切换时保留旧资料并停止，不自动混合来源。“清空知识库”不影响标签或性格人工修改。

标签目前只显示在这里，还没有用于回复建议或聊天试用。

## 依恋问卷的首版边界

ECR-RS 问卷的题目、依恋时间线输出和专用测评入口暂不随首版交付，原因是软件转载与分发许可尚未确认；[许可核查](scale-sources-and-permissions.md)列出作者原始说明。一般性格／依恋倾向的聊天推断、自述和图表仍保留，不等于标准问卷测评。其他性格、三观与经历时间线继续提供。

## 性格时间线

性格和三观都会随时期变化，只给一个总体结果不够。“性格时间线”把聊天按日历分期（默认半年，见“分析时间颗粒度”），用标准问卷逐题调研每一期，显示在“性格分析”页顶部。它在分析菜单里单独勾选，默认不勾；只读本人发言，不依赖共同证据。目前只做大五和由此推算的 MBTI，政治光谱等以后再加。

- 问卷用 IPIP-50（Goldberg 1992，公有领域），基础档用其中的 Mini-IPIP 20 题（Donnellan 等 2006）。
- 每题在这一期的本人发言里搜正反两组词，再加随机片段，共约 75 条交给模型。模型看不到日期、对方姓名、维度、计分方向和你的答卷，提到 MBTI 等字样的片段会先删掉，所以不同时期互不影响。本人明确自述过的类型不再单独显示一行（2026-11-01 起）；自述仍优先显示在 MBTI 卡片上，时间线上的结果直接点色条校正。
- 模型给每条相关片段标“自述”“行为”或“处境”。被当时的事情推着来的算处境，比如为了找对象多社交，不计入答案；发起次数、活跃度这些统计也不参与计算，因为忙碌或焦虑的一段时间不代表性格变了。问内心感受的题，程序要求至少两条自述才算有答案，只看到行为时记为无依据，模型给的答案不算数。
- 三个档位是嵌套的，升档只补缺的部分：基础 20 题各问 1 次，标准 50 题各问 1 次，深度 50 题各问 3 次且片段互不重复。
- 深度才有阴影范围，它是 3 次调研的最低到最高。字母只看分数在中线 3 哪一侧，离中线再近也给一个字母，正好落在 3 上算高端；阴影跨过中线说明这一项不稳，不再用两个字母表示。
- 相邻两期算“看得出的变化”，要同时满足：范围不重叠、差值至少 0.3、两期都有至少 3 个聊天提供依据。下一期留在新位置才算确认，否则标“待后续确认”。
- 从最新一期往前跑，跑完一题存一题，所以暂停或中断不丢进度，页面边跑边更新。旧的时期不会再问；进行中的时期发言增长不到 10% 时沿用已有答案。切换模型路由不会让答案失效，改提示词才会。
- 点击时间线上的某一期，MBTI 卡片换成那一期；点击维度名，列出每道题怎么答、理由和原话。
- 每个维度一种颜色，用在线、阴影、名字和底色上。下面色条里结果相同就用同一种颜色，超过 8 种的保持灰色。怎么读这张图放在右上角的问号里。“看得出的变化”只留在结果数据里，页面不再单独列出。

聊天看得到外在表现，看不到内心，也更容易留下热情和抱怨，所以绝对分可能偏外向、偏宜人、偏不尽责。这张图看时期之间的相对变化比看绝对分可靠。

## 分析时间颗粒度

插件设置里的“分析时间颗粒度”决定一期多长，可选 3 个月、6 个月、1 年、2 年、5 年，默认 6 个月。时期按日历对齐：季度、上下半年、自然年，2 年从偶数年起，5 年从逢 0、逢 5 的年份起。

- 性格时间线、三观时间线都按它分期，“时间线”tab 的总览格子和事件分组也按它分段。
- 每种长度的答案、修改和依恋对象各存一份，互不影响，切回用过的长度不用重算。
- 换成没跑过的长度后，性格与三观时间线是空的，页面提示去勾选；时间线 tab 只是重新分组，立刻生效。
- 一轮分析开始后用的是开始时的长度，中途改设置下一轮才生效。
- 长度越短，每期能用的聊天越少。一期不足 300 条本人发言不算。2026-11-01 用真实聊天只数关键词（不调模型）：半年一期时，经济和自由—威权两条轴的题几乎都搜不到足够的聊天，求变—守成、利己—利他、道德基础约一到两成的题够用；2 年一期时分别升到约 2 成和 4–7 成。五项文字在半年以上基本都够。

性格与三观时间线都显示当前时间尺度、所选时期与覆盖进度，尚未分析或没有分数的时期也可选择。状态分别为“尚未分析”“调研未完成”“调研完成”“证据不足”“未选定亲密关系”“分析失败，待重试”；证据不足表示材料不足以得出结论，无对象表示依恋分析尚未选定关系，二者都不冒充模型失败。题目已处理但回答为无依据，也算处理完成，不等于得到了有效分数。失败题最多补问两轮，只补尚未缓存的题；仍失败时保留已有答案并显示待重试。

## 三观时间线

“三观时间线”显示在“三观分析”页顶部，在分析菜单里单独勾选，默认不勾；只读本人发言，不依赖共同证据。

- 2026-11-02 起政治分析使用 MIT 许可的 **8values 题库**：原题库中对经济轴或公民自由轴权重非零的全部 54 题（经济轴 22 题、公民自由轴 37 题，5 题影响两轴）。保留英文原题、原题号、原权重和固定来源版本，使用本项目简体中文译文。问卷不是经过验证的标准心理量表，聊天推测答案也不等于本人实际答卷。
- 政治题回答为 1 强烈反对、2 反对、3 中立、4 同意、5 强烈同意。汇总方向为经济左—右、自由—威权；全题有答案时与原题库加权算法等价，仅将坐标变换到 1–5。缺题不算中立：有效题数和权重均达到本轴一半才给分，并只对已答权重归一化，因此缺题结果不等于完整 8values 测试结果。深度档跨轮区间继续显示抽样不确定性。
- 价值观保留求变—守成、利己—利他两轴各 6 道自拟题，尚未替换为 PVQ。标准题集的中文版本、计分与许可见[题集调研](worldview-questionnaires.md)。这些题没有人群常模。
- 自我剖析已移除“个人—集体”道德基础图表、时间线行及对应 6 道调研题。原则与底线由“价值底色”的文字与原话依据表达。
- 调研方式和性格时间线相同：搜正反两组词加随机片段，模型逐条标“自述”“行为”“处境”，3 次重复只在深度档。除了 4 句能从做法看出来的，其余都是看法，只认本人说出的话。
- 看法在聊天里说得少。一期里搜不到 5 条相关发言的题不调模型，直接记为无依据；一半以上的题无依据，这条轴就是空的；政治轴还检查完整题集的权重覆盖，未调研的题不能缩小分母。
- 政治那一行取经济和自由—威权所在的象限，价值观那一行取求变—守成和利己—利他所在的象限，离中线再近也定下来，名称和两张图的象限相同。任一条轴没有分数时留空。
- 感情观、家庭观、金钱观、人生规划、价值底色每期各写一句话，最多引 4 条原话；没引到原话的句子不显示。
- 点一列，下面的两张图和五项文字一起换成那一期；本期尚未分析或证据不足时显示对应状态，不用全部历史的结论填补本期空白。时期图表只开放该期实际调研的维度，五项文字分别显示本期结论及引用。分数、政治、价值观、每道题和每句话都能改，规则见下一节，存在 `worldview8Edits`。
- 下方原有的五项“本人自述”“AI 推测”“我的修正”仍然保留在可展开的历史汇总区，它们是全部聊天的总体结论，来自共同证据，与本期结果分开显示。

题集切换后需重新勾选“三观时间线”运行。新答案和修正单独保存；旧 `worldview` 表和 `worldviewEdits` 原样保留在本机，不混入新时间线，也不继承旧政治分数、类型或修正。旧版总体证据结论仍可查阅。

## 修改时间线上的值

性格时间线和三观时间线上 AI 生成的值都能改：点色条改字母或类型，点右边的分数改这一期的分数，点题目的“修正”改这道题的答案。

- 用户的值存在 `periodEdits`、`worldview8Edits`，模型的答案原样不动，页面显示用户的值，打开修改框能看到 AI 判断，也能恢复。带小圆点的是改过的。
- 改题目会进入分数，改分数会带动字母，直接改了字母就以字母为准。
- “看得出的变化”只按模型自己的分数算。用户的值不进提示词，重新分析也不会覆盖。
- 对象换了之后，这一期的修改一起作废，因为那是上一段关系的。AI 认出的对象按聊天现算，显示在选择框里。
- 加载下一页依据时保留正在编辑的时期、字段、未保存文字和光标位置，不因详情重绘丢失草稿。

## 结论什么时候更新

聊天记录有更新时，已发布的性格和三观结论保持不动，只提示待更新，下一次分析发布时才替换。2026-11-01 之前读取页面时会直接删掉结论，已经修正。

## 性格分析与三观分析

两个页签与知己分析共用图表组件；自我剖析不再展示道德基础卡片（`plugin-sdk/web/persona-charts.js`，维度目录在 `plugin-sdk/python/kyf_plugin/persona.py`）：

- 性格分析：大五人格（开放性、尽责性、外向性、宜人性、情绪性）五条轴；依恋用“焦虑 × 回避”平面（Brennan、Clark 与 Shaver 1998），四个象限对应安全、痴迷、疏离、恐惧。MBTI 不再单独推测：有本人明确自述时显示自述，否则按 McCrae 与 Costa（1989）的对应关系由大五人格推算，依据不足的字母显示“?”。
- 三观分析：上方两张图——政治光谱为“左—右 × 自由—威权”罗盘（左—右看对财富与分配的明确观点；自由—威权看对管制与强制的态度；四个区域标注所靠近的派别：社会民主主义、保守自由主义、社会主义、保守主义，靠近不代表就是该派别；文化立场“进步—保守”与立场强度“温和—极端”继续提取，在点开卡片后的维度里列出）；价值观为 Schwartz 的“求变—守成 × 利己—利他”平面（四个区域标注理想派、守护派、进取派、务实派）。下方保留感情观、家庭观、金钱观、人生规划和价值底色五项文字，每项分别显示“本人自述”“AI 推测”“我的修正”；本人自述必须是第一人称表态，推测只看明确态度和稳定做法，一次消费、单次决定或玩笑不算观念，观点随时间变化时注明适用时期并保留反例。

图上的维度和五项文字都来自同一次共同提取（见上文“第一次使用”），只是分别汇总：图表维度存于性格结果，五项文字存于三观结果。每条图表证据只标明偏向维度的哪一端，点的位置由偏向两端的证据条数计算（证据少时向中间收缩），不让模型直接给分；只有通过综合与核查的维度才画点，实心、浅色、空心分别表示较有把握、有一定依据、把握较低，虚线表示证据不足，方框是本人自述（依恋类型、政治自我定位）。点一张图，下方展开它的维度：AI 推测、支持与相反证据（含消息、时间、关系范围和前后文）以及“我的修正”。引用必须逐字匹配本人正文，本人自述和三观证据提取后联合复核，综合推测再核查；政治与价值观只依据明确表达的观点和谈论方式，不按语气、年龄、性别、职业、地区或社交圈推断。依恋推测注明适用关系和时期，不因单次慢回复、失联或争执定型。2026-10-25 之前的 MBTI／政治光谱／依恋结果无法画图，升级后标为待更新，下次分析时重算；共同证据的提取规则随之变化，首次分析会重新提取。

- “我的修正”单独保存，每项最多 2000 字，重新分析、切换深度、原文变化都不会覆盖，也不会把它回填成聊天原文或模型证据。保存校验版本，发生冲突时先保留输入，再读取最新内容对照。清空人工文本并保存可移除该项修正。
- 已完成的原文批次按正文、前后文、规则与深度复用。原文变更后更新对应证据与综合结果，暂停后也保留已完成批次。共同证据还区分模型身份和临时路由状态：模型接口、实际模型及规则不变时，单纯路由修订不会让全部证据重算；接口、模型或输入变化仍会使相关缓存失效。旧缓存只有通过完整身份、原文及证据校验后才复用，失败批次不算作已分析。
- 支持与相反依据、时期逐题依据都可按需继续加载，首屏数量不代表完整依据数量；三观每期五项文字最多引用 4 条，当前接口一次返回这些引用。长期推测分页补充的同维度记录若未被这段结论直接引用，会明确标注，不能把相关记录都称为该句的直接依据。分页期间分析版本变化时停止追加并提供重新读取入口，避免混合新旧依据；只有依据变化、结论文字未变时也会更新版本。

性格、三观结果和人工修正目前仅在自我剖析中展示，不自动写回 Core 本人资料或注入回复建议。

## 时间线

“时间线”tab（标签与性格分析之间）按一条时间轴展示本人亲身经历的事件与人生重要节点，设计见[时间线需求](self-timeline-requirements.md)。提取采用方案 B：与共同提取分开，复用同一份已读语料快照、窗口打包、断点与缓存机制，但用独立的提示词与缓存表，不改动资料/标签/性格/三观的提取结果。相对时间（“去年”“上个月”等常见说法）由程序以消息日期为基准计算，覆盖模型值；“已发生”却晚于说话时间的候选降为待判断，早于本人出生年份的候选丢弃；标准与深度档只复核重要节点且只能降级或删除。归并按主线与时间相近分组后交模型合并，保留全部依据、时间取最精确的一条并在详情列出其他说法；时期由 start/end/state 条目与用户确认过的事件构建。自定义主线（含名称、说明、颜色）按账号保存，用户改过主线的事件不参与改归。

- 顶部“分析内容”菜单在“标签”和“性格”之间新增“时间线”复选框；进度浮层新增“时间线提取”“整理时间线”两步，排在“标签分析”之后，可单独暂停/继续。时间线不依赖共同证据：只选时间线时不运行共同提取；既有账号未保存过选择时默认仍为原五项，勾选时间线后才开始提取。
- 用户的确认、编辑、删除按依据消息集合锚定：重新分析后依据重叠且主线相同的事件沿用用户的字段；已删除事件的依据集合不再出现；手动添加的条目永远保留。编辑保存校验版本，冲突返回 `conflict`。“清空知识库”不影响时间线与人工修改。
- `self.timeline`：返回 `version`、`events`、`periods`、`tracks`、`coverage`（聊天最早/最晚时间与语料覆盖）和 `run` 状态。事件含 `id`、`title`、`track`、`kind`、`status`（occurred/planned/cancelled/uncertain）、`importance`、`startMs`/`endMs`、`precision`、`whenText`、`phrase`、`saidMs`、`level`（confirmed/strong/possible）、`manual`、`edited` 字段列表、`evidenceCount`、`conflicts`。
- `self.timelineEvidence`：接收 `id`，返回最近 50 条依据（`chat`、`isGroup`、`time`、`text`、`phrase`）与 `total`、`resolvedWhen`。
- `self.timelineEdit`：接收 `target`（`event`/`period`/`track`）、`action`（`confirm`/`unconfirm`/`edit`/`delete`/`restore`/`add`/`visible`）、`id`、`fields`、`expectedVersion`；时期删除按依据集合锚定，内置主线只能隐藏、自定义主线可增删改。`edit` 只需给要改的字段，其余保留；`fields` 里可用 `when` 字符串代替 `startMs`/`endMs`/`precision`。返回完整视图并附 `editedId`、`editLabel`。
- `self.timelineUndo`：接收 `expectedVersion`，撤销最近一次修改，返回完整视图并附 `undone`（被撤销操作的说明，没有可撤销时为 null）。撤销日志保存在账号库的 `timeline_undo` 表，最多 200 步；页面的 Ctrl+Z 和 MCP 共用。
- 事件合并（merge）与从事件移除单条依据（detach）在 v1 未提供入口；分期调整用编辑起止时间或删除后新增实现。

## 聊天试用

“聊天试用”tab 分左右两栏：

- 左栏“历史回复”：输入一个情境，按 Enter 或点击“检索”，查看知识库里相近情境下本人当时的回复（Shift + Enter 换行）。前文中本人的话显示为“我：”；语义命中会标“含义相近”。每条可以“排除”，排除后不再用于检索和生成，可在“表达知识库”恢复。
- 右栏“模拟对话”：以好友的身份发消息，一次输入可换行分条（Shift + Enter 换行），连续几条一起作为好友消息发出，贴近真实聊天里对方连发的情形；回复模型以“我”的口吻回复，可拆成一到三条连续短消息。对话可以多轮继续，最近 20 条一起交给模型；“清空”重新开始。每次回复后，左栏换成这条回复参考的历史回复。

回复依据核心保存的本人资料（背景与自述、表达偏好）和按最近几条对话检索到的最多四条本人历史回复；样例按本人当时真实分条发送的结构呈现，供模型模仿拆分习惯。历史回复里的人名、称呼、时间和承诺只作表达参考，不当作当前事实。回复只显示在页面，不发送、不保存，切换账号即清除。每次回复作为一次核心任务执行，失败只在对话中显示简短原因。

回答检索深度默认为「自动」：生成前先做一次轻量调用判断，选出基础、标准或深度档；当好友问到近况、打算、感受或变化这类问题时，同时从时间线目录选出相关的事件与阶段（合计最多 12 条）作为可信事实进入回复，并给出补充检索短句。时间线还没建立或问题不需要调研时不查时间线；判断失败按标准档、不调研地直接回。插件设置里仍可固定基础/标准/深度，固定后跳过判断。回复里参考了时间线时，左栏标题会注明条数。

真实私聊里的三条建议目前只读取“表达偏好”和历史样本，不读取“背景与自述”和时间线记录，所以试用回复可能比真实建议知道更多本人背景。

评价时多试几类场景：邀约、求助、关心近况、玩笑、需要拒绝的请求等，逐条看是否回应了对方这句话、措辞和长短像不像你、关系分寸是否合适。不合适的历史表达在左栏排除，或修改本人资料后再试。

## 历史样本如何使用

当前使用关键词与语义混合检索。中文字符、相邻词项与聊天场景负责词项匹配；BGE-small-zh-v1.5 负责寻找意思相近但措辞不同的情境。语义索引编码样本的前文情境，保留关联的本人回复供生成时参考。两路独立召回，按排名融合，再结合联系人、场景及样本多样性选择。相关样本可以来自不同私聊；没有适合的样本时，继续使用当前对话和明确填写的表达偏好。

检索先汇总匹配词项，再读取前 500 个候选的正文。入选候选分小批核验，同一轮跨联系人的证据合并读取；Core 按原始消息分片和精确定位批读，避免逐条扫描所有分片或重复加载通讯录。核验仍检查当前原文、消息身份、来源与账号，结果返回前复核样本排除和修改；核验结果不跨查询缓存。

页面显示“词项检索”表示模型或有效向量暂不可用；“混合检索”表示已有语义样本可用，不代表全部向量已补完。大库的单次语义扫描有时间上限，查找结果会提示本次仅扫描部分语义索引。效果仍需根据真实建议校正；模型不是专门训练过本人的聊天模型。

知识库整理连续的本人回复。文字中的 Unicode emoji 随文本保留；独立微信表情包、图片、视频、语音、系统消息、引用、转发、无法可靠归属的内容和相隔过久的前后文不会直接作为表达样本。本建库流程不做图片理解、OCR 或语音转写。历史聊天并不总能证明文字最初由谁撰写，仍应通过查找结果和真实建议校正效果。

样本只用于学习表达方式，不证明当前联系人说过什么，也不授权搬用其他聊天中的人名、亲密称呼、地点、经历或承诺。表达参考与当前对话证据分开，仅检索目标消息之前的样本。建议保存前再次核对已选样本；清空知识库、切换来源或原文变化会阻止旧参考的建议被保存。

接入回复建议时，历史表达检索只使用当前上下文中的文字消息。上下文只有空白、标点、emoji 或媒体消息时，跳过历史表达检索，继续使用当前消息、可用媒体观察、微信已有转写及明确填写的本人偏好。有前文文字时，后续 emoji 或图片不会阻止检索。建库流程仍不会将图片或语音作为文字表达样本。

生成建议的原有请求中还要求模型先检查谁向谁提出要求，以及接受、拒绝、澄清、许可与承诺的方向；关系或意图不兼容的样例应弃用。这是生成时的适用性要求，没有新增一次模型调用，也不能保证每次都正确判断分寸，仍需通过真实建议试用校正。

三条建议供你选择与复制；自我剖析不发送微信，不覆盖手写草稿。停用自我剖析后，现有回复建议仍可使用。

## 资料和维护

- 本人资料由 Core 维护。保存会校验版本；其他窗口已修改时保留当前草稿，读取最新资料后合并。
- 同账号切换 tab 或联系人会保留未保存输入；切换账号或关闭独立窗口前，需要先点击“保存本人资料”。
- 索引、本人文字、分析摘要、性格修正和断点按账号保存在本机 `.local/plugin-data/kyf.self-analysis/accounts/<账号摘要>/self-analysis.sqlite3`，不放进代码仓库。统一读取器同时保留完整本人正文、有界前后文和可作表达样本的私聊规范文字；其他内容仅作样本配对屏障，不复制媒体载荷。各模块共享读取，分别维护结果与缓存，资料摘要不能充当标签或性格的原文证据。
- 同账号共用一个数据库，原文只同步一次，共同证据只提取一次，资料、标签和性格分别汇总。证据按来源、原文、上下文、规则、模型与容量校验；切换已选项目、修改人工内容不会使共同证据失效。首次从旧分析升级需要建立共同证据，旧的三类摘要不能直接充当经过原话校验的新证据；已有人工内容和旧缓存保留。全量历史很大时，首次仍可能耗时较长，具体时间由实际批量与模型速度决定。阶段计数使用随每页事务维护的聊天统计，不在每次进度更新时反复扫描全部原文。
- “清空知识库”删除本账号的样本、词项与语义索引和进度，保留微信聊天、自己填写的资料及 Core 共享的公开模型缓存。之后可以重新建立。暂停整理不取消其他账号也可复用的共享模型下载。
- 可以在“聊天试用”的检索结果中排除不想学习的样本，在“表达知识库”页底部查看、恢复已排除项（没有排除项时不显示）；排除会影响后续检索，增量更新与重新整理仍尊重该选择。清空知识库会同时清除排除记录。
- 知识库代表截至上次读取的本机历史快照。第一版通过按钮更新，不宣称实时同步所有联系人的新消息。
- 更新时，目录最新位置与已读前缀都未变的聊天直接跳过；其余聊天统一检查来源元数据、已读前缀与原文凭据，跳过未变化历史；私聊样本涉及的行（包括配对屏障）也参与校验。源数据变化时重读受影响聊天，在本机原文上重新提取样本并保留未变化样本的有效向量及排除选择。检索时仍逐条核对原文。
- 旧版词项库会自动迁移；点击更新后从现有样本补齐向量，同时继续增量读取新消息，不要求从头重读全部聊天。模型版本和样本前文摘要一起校验，过期向量会重算。
- 固定中文语义模型为 BGE-small-zh-v1.5，512 维、最多 512 tokens，CLS pooling 与 L2 归一化。长前文保留末尾；没有微调。AI 初稿只在点击时生成，保存前由你修改确认，不会自动更新本人资料。选型、资源与验证边界见[混合检索实现说明](self-analysis-hybrid-retrieval.md)。

## 开发接口

插件 ID 为 `kyf.self-analysis`。桌面入口由独立的 `self-analysis.html` 宿主窗口承载，内部以 sandbox iframe 加载 `ui/index.html`；浏览器仍可使用导航页。后台为 `backend/main.py`。插件随现有打包流程分发，不要求普通用户单独安装开发运行时。账号切换或清空会销毁旧账号的页面和未完成宿主请求；同账号切换联系人不重建窗口。

- `self.status`：连接、建库、覆盖和样本数量。
- `self.analyze` / `self.analysisStatus` / `self.analysisPause` / `self.analysisResume`：统一开始、查询、暂停与继续。开始接收 `depth`、`outputs`（`profile/tags/timeline/persona/periods/worldview/values/library` 非空子集）、当前 `background` 和 `style`；可选布尔参数 `refreshHistory=true` 会重新核验全部聊天来源并保留有效分析缓存。时间尺度取本轮开始时的插件设置；同账号运行中只有输出选择、深度和时间尺度一致的重复启动才复用任务，不一致时返回 `analysis-busy`。暂停不传参数控制全部，传 `output` 控制单项；继续传 `output`（任务已结束时还接收 `background` 和 `style`），运行中恢复该项，任务已结束时仅启动该项；单项继续不改变保存的分析内容选择，只有 `self.analyze` 和 `self.analysisSettings` 会保存。状态为 `idle/running/done/partial/paused/interrupted`，返回 `outputs`、`pausedOutputs` 和同步、知识库、共同证据、资料、标签、时间线提取与整理、性格、性格与三观时间线、三观、语义索引各步骤状态，未选步骤为 `skipped`，单步暂停为 `paused`。没有生成模型仍完成已选的本地知识库分支。旧单模块启动接口为兼容保留，页面只使用统一入口；统一任务运行时阻止并发修改同一语料或重建索引。
- `self.analysisSettings`：读写按账号保存的 `outputs` 偏好，允许空数组；空选不能开始任务。读写偏好不启动分析。
- `self.persona` / `self.personaEdit`：读取性格与三观图表结果，或保存人工修正；编辑接收 `key`（`kyf_plugin/persona.py` 中的 17 个维度之一）、`text`（最多 2000 字）、`expectedVersion`，冲突返回 `conflict`。返回 `version`、17 项 `dimensions`（`inference` 含 `position`（-1…1）与各端证据条数 `counts`）、`selfReports`（`mbti/attachment/politics`）和 `coverage`。
- `self.values` / `self.valuesEdit`：读取三观结果，或保存人工修正；接口与性格相同，`key` 为 `love/family/money/plan/core`，返回五项 `dimensions`。
- `self.periods` / `self.worldview`：返回当前 `months` 下的时期列表及 `coverage`，包含尚未产出答案的计划时期。每期的 `status` 为 `pending/partial/complete/insufficient/no-target/error`，另有 `answered`、`expectedAnswers`、`failedAnswers` 和处理完成标志 `complete`；`coverage.failed` 单列失败期数。`worldview` 每期另含 `love/family/money/plan/core` 五项 `views`，各带状态、文字、引用及 `item/evidenceTotal/evidenceNextOffset/evidenceVersion`；摘要题号 101–105 同样通过 `self.worldviewEvidence` 读取。正常摘要最多 4 条引用仍一次全返，只有返回数量小于总数时显示继续读取入口。统一任务选中三观但尚未执行该步时，页面显示排队状态。
- `self.periodDetail` / `self.worldviewDetail`：按 `period`、维度 `key` 返回逐题详情；各题首屏依据最多 6 条，并返回 `evidenceTotal`、`evidenceNextOffset` 和 `evidenceVersion`。对应的 `self.periodEvidence` / `self.attachmentEvidence` / `self.worldviewEvidence` 按 `period`、`item`、`offset`、`limit`、`expectedVersion` 继续读取，预期版本取该题的 `evidenceVersion`。
- `self.personaEvidence` / `self.valuesEvidence`：按 `key`、`kind`（`selfReport/inference`）、`side`（`evidence/counter`）、`offset`、`limit` 读取完整已保存依据，`expectedVersion` 取对应分析面板的 `version`。推测支持项中的 `cited: false` 表示同维度相关记录，未被当前结论直接引用。
- 上述依据分页统一返回 `items/total/nextOffset/version`，`limit` 默认 50、范围 1–100；版本不符返回 `stale-evidence`。客户端也核对响应版本，冲突时重新读取当前分析或题目详情后再分页。
- `self.build` / `self.start`、`self.pause`、`self.resume`、`self.reset`：建立和维护本机索引。`mode: "semantic"` 仅补充语义索引；`self.resume` 在历史已完成时也只恢复语义整理。
- `self.search`：查看实际命中的历史表达。
- `self.compare`：同一场景下对比仅关键词与生产混合检索；词项分支只关闭语义能力，复用原来的检索、去重和原文核验实现，不维护另一套排名公式。页面不再提供入口，保留给评测脚本。
- `self.exclude` / `self.exclusions`：排除、恢复与查看不参与学习的样本。
- `self.draft` / `self.draftStatus` / `self.draftPause`：启动、查询与暂停 AI 初稿。`self.draft` 接收文本框当前的 `background`、`style`（各不超过 4000 字）和 `depth`（`basic` / `standard` / `deep`，默认 `deep`）；同账号运行中的任务复用，同条件暂停或失败后继续断点，完成后再次开始则增量同步语料并复用有效分析摘要。状态为 `running`、`done`（带 `result`）、`error` 或 `cancelled`，附阶段、累计覆盖量与读取缺口；`coverage.reusedMessages` 和 `coverage.newlyAnalyzedMessages` 分别表示复用已有分析与本轮新分析的本人文字数。读取语料、分析摘要和断点保存在账号本机数据库中。
- `self.draftSettings`：读取或保存当前账号的分析深度；传入 `depth` 保存，空参数读取，返回 `{depth}`。不设置插件独立模型或并发额度。
- `self.reply` / `self.replyStatus`：启动与查询一次聊天试用回复。`self.reply` 接收 `messages`（1–20 条 `{from: "friend"|"me", text}`，每条不超过 1000 字，最后一条须来自好友），同一账号已有回复运行时返回该任务；完成时 `result.messages` 为一到六条回复（条数上限由程序从本次参考的历史回复里随机抽取，模型可以少发，不能多发），`sources` 为本次参考的历史回复，只保存在插件进程内。深度默认跟随插件设置（auto 先判断是否调研时间线），`research` 为本次参考的时间线条数。
- `self.tags`：标签列表（`key`、`name`、`category`、语义类型 `relation` 为 `mention`/`occasional`/`interest`/`trait`/`uncertain`、可信等级 `level` 为 `confirmed`/`strong`/`possible`、`manual`、关联消息条数、聊天数、天数和首末时间）、运行状态 `run`（`idle`/`running`/`paused`/`complete`/`failed`，运行时带 `phase`、`done`、`total`、`stopping`；`needsReview: true` 表示旧分析待复核）、读取计数和可选类别。人工确认和手动添加不推断或提升语义类型。
- `self.tagsAnalyze` / `self.tagsPause`：开始或继续分析，暂停正在运行的分析；都返回 `self.tags` 的结果。需要已保存的回复模型配置，不需要知识库样本。
- `self.tagEvidence`：某个标签依据的原话，接收 `name`，返回最近 50 条和总数；每条包含聊天、时间、本人原话、前文 `context`、后续文字 `followup`、语义类型 `relation`、支持原话 `quote`、判断理由 `reason` 和截断标记 `truncated`。
- `self.tagEdit`：接收 `action`（`confirm`、`delete`、`reset` 撤销确认或删除、`add`）、`name`（1–20 字）和添加时的 `category`，返回 `self.tags` 的结果。
- `self.context`：有界表达上下文，支持 `validateOnly` 核对已选样本。
- Core `GET /plugin-api/v1/history/conversations`：实际消息表支持的聊天发现与快照分页，群聊带 `isGroup: true`；知识库只取私聊，标签读取全部聊天。每个聊天带 `latest`，即最新一条消息的来源位置；它与该聊天 `history/status` 的 `highwater` 相同，说明上次已经读到最新。有分库读取失败时一律为空，不据此跳过。
- Core `GET /plugin-api/v1/history/status`：`sourceRevision` 是不读取正文的来源变化信号。`audit=1` 额外返回 `sourcePrefixCeiling` 与 `sourcePrefixSignature`，可传 `auditHighwater` 核对之前读完的同一前缀；未知元数据为 `null`，不能据此断言历史未变。普通状态查询不扫描历史前缀。
- Core `POST /plugin-api/v1/history/status-many`：一次最多 500 个聊天的普通状态，共用一次来源身份核对，不读来源元数据。每轮同步先用它批量确认：目录 `latest` 仍等于上次读完的位置、且 Core 的纪元/版本/水位线都没变的聊天直接跳过，不再逐个做前缀审计；只有其余聊天才逐个读取。代价是最新一条没变时，中间被删除或插入的消息要等这个聊天下次有新消息才会发现。旧版 Core 没有这个接口时退回逐个审计。
- Core `POST /plugin-api/v1/history/verify-many`：在同一账号下合并最多 16 个联系人、总计 500 个证据引用的原文核验，固定使用当前来源，按联系人返回逐项核验结果。建库时有新消息的私聊按组用它核对已存的末尾证据。
- Core `GET /plugin-api/v1/account/self-profile`：插件只读本人资料。
- Core `GET/POST /api/account/self-profile`：宿主读写本人资料，保存需要 `expectedVersion`。
- Core `POST /plugin-api/v1/services/self-context`：仅对持有效任务令牌的 `kyf.message-insights` 开放；固定调用自我剖析的只读接口，不是任意跨插件 RPC。
- Core `GET /plugin-api/v1/embeddings/status`、`POST /plugin-api/v1/embeddings/prepare`、`POST /plugin-api/v1/embeddings/embed`：固定本地模型的状态、异步准备和有界推理；本轮仅向自我剖析开放，校验插件及账号，推理通过 Core 模型网关调度。

回复仍由 `kyf.message-insights` 生成，单独装配 `personalReplyStyle`，不把检索例子加入好友分析的事实证据。所有实际生成请求继续通过核心模型网关。

发行运行时的 staging 会离线检查捆绑 Node 的 ONNX CPU 后端、tokenizer 以及捆绑 Python 的 NumPy，缺失或借用开发目录依赖时阻止生成发行清单。检查不下载模型；它验证依赖可加载，不代替最终安装包的建库验收。
