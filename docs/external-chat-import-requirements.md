# 外部聊天导入需求

产品：知己微信助手 · Zhiji WeChat Assistant。日期：2026-10-18（Asia/Taipei）。状态：v1.2，已在当前工作区实现首版。核心导入、核对、保存、资料管理与默认识别插件已接入；合成测试验证流程和数据边界，不同来源真实素材的识别质量仍待用户样本验收，尚未据此发布正式版本。使用方式见[外部聊天导入](external-chat-import.md)，品牌名称按[当前约定](branding.md)更新。

状态复核（2026-11-02）：**首版功能已实现，真实素材质量和运行资源验收未闭环**。第 7.3 节所列手工新增／合并／拆分气泡、区域裁剪及单条备注仍为后续建议，不作为已完成能力，也不自动扩大首版交付范围。当前验收与后续提案分别汇入[需求待办清单](requirements-todo.md#validation)及[后续方向](requirements-todo.md#future)。

目标是把用户可访问的其他软件聊天截图或屏幕录制，整理成可核对、可搜索、能回查来源的逐条聊天记录。来源名称由用户填写，不设软件枚举或预置名单；没有聊天导出入口是用户描述的使用场景，不将其作为支持范围的限制。

本功能作为软件内置的数据导入能力，与分析功能解耦，核心边界见[软件插件架构需求](analysis-plugins-requirements.md)。导入只负责识别、核对和保存外部聊天记录，并支持备注；分析模块另外读取聊天资料，按自己的规则生成报告、候选和判断。导入流程不选择分析方案、不提供启动分析的操作，也不因保存成功而触发分析任务。

已进一步确认：导入入口、核对和保存由核心内置；AI 识别流程由默认附带的导入插件负责。插件通过 core 的统一模型路由调用模型并纳入监控，core 不定义提示词、识别策略或分析业务。后台自动将截图／录屏整理成逐条聊天，并区分无疑点候选和待核对疑点；用户重点处理疑点，再按批次确认，由核心保存。用户所说的自动处理指这一转录流程，不包括后续知己分析报告。

2026-10-18 交互更新：从好友顶部进入独立窗口，只保留“聊天记录／导入任务”两个主标签，来源由用户自行填写。以下与该更新不一致的早期流程建议以本段为准，使用说明描述当前交互。

## 1. 已确认的需求

| 事项 | 决定 |
| --- | --- |
| 当前使用场景 | 导入用户指定来源的聊天；以截图、长截图和滚动聊天界面的录屏作为设计输入 |
| 来源填写 | 用户填写来源名称，可复用已有来源；不硬编码软件名称、不设有限支持名单 |
| 导入入口 | 仅从好友顶部“外部聊天”进入独立窗口，窗口固定属于打开时的好友，不重复提供好友选择 |
| 后台整理 | 截图／录屏自动识别、整理成逐条聊天；只将转录中的不确定部分交用户判断，不自动生成知己分析报告 |
| 核对方式 | 用户重点核对疑点，无疑点记录可直接进入批次确认范围；按批次点击一次确认保存，保留查看全部记录的入口 |
| 部分保存 | 先按批次保存无疑点和疑点已解决的范围；未解决疑点留在原导入任务，之后继续核对和保存 |
| 导入产物 | 保存为外部聊天记录，可以添加备注 |
| 备注层级 | 首版分别提供来源会话说明与导入批次备注，均可留空、后续修改；追加不覆盖已有说明或备注，单条记录备注留待后续 |
| 疑点保存条件 | 正文与发言人明确、仅缺时间的消息可以未知时间确认保存；发言人不明或内容截断的候选继续待核对 |
| 记录归属与浏览 | 外部记录归到好友名下，按用户填写的来源分别查看 |
| 无微信好友 | 可以新建没有微信的好友，保存和浏览其外部聊天记录 |
| 批次范围与身份关联 | 一批对应一位好友、一个来源会话；由用户明确选择本人账号、来源会话与好友，不按昵称自动合并，关联错误可以修正 |
| 同来源追加 | 后续导入追加到该好友对应来源的聊天记录，明确重复复用原记录，疑似重复由用户核对；每批素材仍可回查 |
| 纠错与重新识别 | 保存后可以纠错、改关联和撤销本批新增；保护其他批次共享的消息及人工修正，新识别差异先对照，不静默覆盖 |
| 素材留存 | 软件在本机留存原截图、录屏和清晰证据画面，之后可以手动清理 |
| 分项清理 | 原素材副本、证据画面、导入任务与正式记录分别处理，清理前说明影响，保护未完成任务和共享素材 |
| 任务继续与优先级 | 关闭页面或切换好友后继续；停止保留进度及核对编辑，失败只重试未完成范围；交互助手优先，应用重启后由用户手动继续 |
| 日常查找 | 好友内关键词搜索，支持来源与批次筛选；没有可靠时间的记录仍可按可核对的会话顺序浏览 |
| 与分析解耦 | 导入只负责取得和保存记录；分析是另一个读取这些记录的模块，不由导入流程启动 |
| 功能归属 | 微信接入以及外部导入入口、核对和保存保留内置；AI 识别由默认附带的导入插件负责，核心保管已保存资料 |
| 模型调用 | 导入插件统一使用 core 的模型路由与监控，识别业务由插件定义 |
| 插件启停与入口 | 停用外部聊天识别插件后隐藏好友页入口；已打开的独立窗口与草稿保留，识别显示不可用，重新启用后恢复入口 |
| 本轮交付 | 在已接受规则和交互原型基础上实现首版：核心页面、素材与证据管理、后台识别、核对及部分保存、聊天浏览与纠错；真实素材质量仍待验收 |

第 1 节、正文明确标注的已确认规则及第 7.2 节已接受规则共同描述交互决定。此前独立原型使用虚构资料；当前首版的实现范围和限制见第 7.3 节，仍未实现的建议与未验收的识别质量不因原型或代码接通而自动成立。

## 3. 导入入口与五步流程

### 3.1 选择对象

- 好友顶部只提供“外部聊天”入口，在独立窗口查看该好友的聊天和导入任务；不增加全局导入面板或窗口内好友选择。
- 已确认以好友为主入口：从当前好友进入后填写来源名称；通常复用当前好友的来源会话，账号、会话标识与批次备注放在更多选项，所属好友固定为打开时的对象。
- 已接受首版提供来源会话说明与导入批次备注，两者分别保存、均可留空和后续修改；追加不覆盖已有说明或备注。单条记录备注留待后续。
- 已确认外部好友可以独立建档，无须先连接微信；同一好友下按来源分别浏览。跨软件同一个人由用户明确关联，不按相同昵称自动合并；关联错误可以修正。
- 已接受一批素材对应一个来源会话和一位好友。混入其他联系人时提示拆分，不自动把多个人的消息合成一人。
- 已确认后续导入选择该好友已有来源并追加：明确重复关联已有消息，疑似重复进入核对。每次导入保留批次及素材来源，不因追加丢失回查入口。

### 3.2 添加素材

- 接收批量截图、长截图和聊天屏幕录制，展示素材预览。
- 已确认原素材和清晰证据画面由软件在本机留存，供后续回查、纠错和重新识别；保存路径、容量和清理界面仍待设计。
- 截图可以调整顺序；录屏标记滚动顺序，允许“不确定”。聊天区裁剪的具体操作形式待确定。
- 录屏应提取清晰且具有重叠内容的画面，再复用文字及气泡识别流程。看不清或快速滑过的片段标出缺口。
- 图片、语音、视频等聊天气泡只能先记录实际可见的类型和信息。截图中的语音图标不等于已取得音轨，缩略图不等于原图。

### 3.3 后台整理

- 已确认启动导入处理后，由后台自动进行识别和对话整理，并提出转录疑点；用户不需要手工逐条录入或逐条启动识别。人物概述、关系记忆候选和其他知己分析报告由另一模块负责。
- 建议任务状态为：排队、识别、整理、待核对、已保存；另有停止、失败、中断、部分完成。
- 已确认允许部分保存；任务同时保留已保存记录及待核对部分的状态，仍有疑点时不能标成整批处理完成。具体状态文案建议为“部分已保存，待核对”。
- 显示当前步骤和可验证的完成量，尚无实测依据时不承诺精确剩余时间。
- 已接受切换好友或关闭导入页面后任务继续，结果仍归原批次；不抢占当前聊天或覆盖草稿。
- 已接受停止时保留识别进度和核对编辑；应用退出后不继续执行，保留已完成部分及必要检查点，重启显示中断，由用户手动继续，不自动重跑。与[插件停止与恢复原则](analysis-plugins-requirements.md)保持一致。
- 已接受失败只重试未完成范围，保留已确认内容；重试和重复提交不应重复创建已保存的消息。检查点格式、版本兼容及片段恢复机制由工程细化。
- 已接受资源调度优先满足交互助手，导入作为后台任务；并发、排队和重试参数需在实施时验证，不在原型中承诺吞吐量。

### 3.4 核对记录

**已确认：后台自动识别整理，用户重点核对转录疑点，允许查看全部记录，按批次一次确认保存。**

- 桌面采用原素材与识别记录联动的布局；点击一条记录定位到截图区域或录屏时间点。
- 默认突出文字不清晰、发送者不明确、气泡截断、时间不完整、疑似重复、顺序不确定等疑点。
- 无疑点候选不要求用户逐条点击确认，可直接纳入本次批次确认范围；用户仍可选择查看和修正任意记录。未解决疑点保持待核对，不自动混入保存范围。
- 用户可以编辑转录文字、发送者和可确认的时间。已接受正文与发言人明确、仅缺时间的消息可以未知时间确认保存，不要求补出具体日期；发言人不明或内容截断的候选继续待核对，不能仅点击确认就混入正式记录。
- 建议允许对照全部素材手工补录、合并或拆分气泡。疑点列表无法替代完整对照：整条漏识别的消息可能没有对应的疑点条目。
- 建议在保存前展示本批候选数量、待处理疑点、忽略项及最终保存范围。不能把“未查看”标成“人工逐条核对”。
- 已确认可以按批次保存无疑点及用户已解决疑点的范围，其余疑点留在同一任务。后续打开任务可继续核对，再保存新确认的部分；已保存消息保持记录身份，不重复入库。
- 部分保存仍保留可核对的原素材顺序及未解决位置；后续补入记录按已知原顺序归位，不能按保存时间全部放在聊天末尾，未解决缺口也不能被展示为完整连续对话。
- 视频的播放位置只是证据位置，不作为消息发送时间。部分日期保留其实际精度和原始标记，不能补写缺失年份。

### 3.5 确认保存

- 确认后将用户选定范围保存为带识别来源的聊天记录，并能从聊天浏览回查素材。
- 同时保存可选来源会话说明和本批备注；完成页展示保存数量、来源、备注及“查看聊天记录”。导入记录的浏览和备注编辑属于数据管理能力。
- 已确认保存后的记录从所属好友进入，并按平台来源分别查看；已接受好友内关键词搜索及来源、批次筛选，缺时间记录按可核对的顺序浏览。来源切换控件、默认来源及搜索结果布局由交互设计细化。
- 转录记录的保存不等于确认人物事实；关系记忆候选仍需经过知己分析中的确认流程。
- 已确认无疑点候选与用户已解决的疑点一起纳入批次确认，未解决疑点留在原任务；保存反馈同时显示本次保存量、已保存情况和待核对量，并提供“查看聊天记录”和“继续核对”。批次确认不会把全部记录标为人工逐条核对。
- 没有剩余待处理内容时可以完成本批导入；部分保存时保留待核对状态。两种保存反馈都不要求选择分析方案，不添加“开始分析”或自动生成分析报告的步骤。
- 已接受保存后可以修正转录、修正所属好友或来源会话，并撤销本批新增记录。操作前展示影响范围；不得误删其他批次仍引用的共享消息，具体改关联及撤销交互由设计细化。

## 4. 转录、顺序与去重原则

- 保留可核对的逐条内容和来源，缺失的文字、身份、引用或时间保持未知，不让 agent 补写聊天事实。
- 发送者归属应结合气泡位置、软件界面和用户确认；不能把左侧气泡在所有界面中一律当作某个已知人。
- 建议一条聊天记录对应一个实际气泡，正文换行不拆成新消息；引用框与正文分别标明，日期分隔条、已读提示、匹配提示和撤回提示作为界面或系统信息处理。滚动切开的同一气泡需要拼接，不能只处理完全重复的文字。
- 同一气泡在连续截图或录屏画面反复出现时可以合并；真实连续发送的相同文字应保留。不能只按文本相等删除记录。
- 用素材重叠、相邻消息顺序和发言人共同判断；无法区分重复气泡与重复发言时列为疑点。
- 去重应支持同批画面重叠、重复上传和后续批次重叠；跨批次不确定的匹配需要核对，不能静默吞掉新的发言。
- 已确认同来源多批次持续追加，明确重复复用原记录；同一消息可由多个导入批次提供证据，素材归属和回查关系仍分别保留。已接受新识别正文与已保存版本不同时展示差异供用户对照；新结果不静默覆盖人工修正，保留版本及修改关系，具体差异界面和版本结构由工程设计。
- 识别来源、原素材、位置、转录版本及人工修正关系可回查。用户填写的软件来源名称与素材类型（截图／录屏）分别保存。
- 来源会话说明及批次备注属于用户填写的外部记录说明，与转录正文分别保存和展示；不能插入原气泡、冒充聊天双方说过的话或自动变成已确认人物事实。后续追加不覆盖既有说明和批次备注，单条记录备注不纳入首版。
- 建议“今天／昨天”等相对日期保留原始显示；用户确认了录制日期等依据后才能解释。导入时间、文件创建时间、录制时间和消息发送时间分别处理。
- 没有可靠发送时间的记录仍可按会话内顺序浏览，但不作为精确回复耗时、按日联系频率等统计的完整依据。

## 5. 与分析插件、自动建议的关系

- 分析模块通过软件提供的聊天资料读取能力取得外部记录，知道来源、覆盖范围和时间缺失情况；读取范围和执行时机由分析模块管理。
- 部分保存后的正式聊天资料只包含已确认保存的记录；未解决疑点仍是导入任务中的待核对内容，不能混作已保存的对话。后续确认保存后才成为可读取的聊天资料。
- 导入任务不依赖所选分析方案，不调用方案任务入口。识别可以使用 OCR、视觉或文字整理模型，但生成分析报告、关系结论和记忆候选不属于导入任务。
- 导入历史产生“历史资料更新”，不冒充对方实时发送的新消息，不触发新消息自动回复任务。
- 保存或纠正记录可以更新资料版本，供其他模块判断原有结果是否过期；这一数据变化本身不由导入模块启动分析。分析模块如何检查资料变化、何时执行增量更新，在分析模块中另行定义。
- 不要求安装知己分析插件才能浏览导入记录或回查原素材；分析方案切换也不改变聊天原文。

## 6. 本地资料与生命周期

- 延续本项目约定：真实素材、转录、联系人资料和运行数据只保留本机，不进入公开或私有代码仓库。
- 优先使用已有的本机或用户配置的局域网推理能力。模型、视觉能力及识别工具的选择在实施前验证，不在需求中硬编码机器地址、模型或凭据。
- 使用配置的远程模型时明确数据去向；“本地优先”不自动等于全部推理都在本设备执行。
- 已接受停止或删除导入任务、删除本软件的正式转录记录、清理原素材副本和证据画面分别处理；不修改来源软件中的聊天。
- 已确认软件本机留存原素材及清晰证据画面，允许后续手动清理；日常回查不只依赖用户最初选择的文件路径。证据画面保留发送者、引用及日期等核对所需的上下文，具体截取方式仍待设计。
- 已接受按原素材副本、证据画面、导入任务和正式记录分项显示占用及操作影响；清理本软件副本不删除用户最初选择的原文件或来源软件记录，也不隐含删除其他类别的资料。
- 清理留存的录屏副本但保留证据画面时，正文和保留画面仍可查看；明确标示完整录屏不能回放、不能再补抽未保留画面。证据画面也被清理后保留正文，并标示对应证据已清理，不能继续声称可回查该画面。
- 已接受保护未完成核对任务及跨批次共享素材：清理单批不能破坏其他批次仍依赖的消息或证据；清理前展示受影响任务、记录及回查能力，未完成任务需要的素材不得在不处理其依赖的情况下直接清掉。依赖识别、清理限制及提示交互由工程细化。
- 保存路径、容量显示细节、存储配额与回收实现仍待设计和实测；本轮不设自动清理时限。

### 7.3 首版范围与验证前提

- 首版已实现一批一好友一来源会话，接受截图与最多一段录屏混用；不接受一批多个录屏。混入其他对象时保留疑点，用户应拆分批次。此前原型的 3 张截图加 1 段录屏是演示；当前组合范围是本轮实现采用的工程选择。
- 首版格式为静态 PNG、JPEG、WebP 截图与 MP4、MOV、WebM 录屏；每批最多 20 份素材、单文件最多 128 MiB（界面标作 128 MB）、单段录屏最多 180 秒。截图不得超过 8000 万像素，录屏不得超过 1600 万像素，最短边至少 32 像素；具体文件还须可成功解码。开始识别后固定素材顺序，追加素材新建批次。
- 原素材、证据画面和 SQLite 数据保存在应用本机数据目录的 `core/external-chat/` 下（开发环境为 `.local/core/external-chat/`）。长截图按重叠区块保留证据；录屏按有限采样提取画面并保留视频位置，用户选择从较早到较新或相反方向。采样会跳过完全相同的连续画面，不能保证捕获快速滑动之间的全部内容。
- 默认插件调用应用配置的视觉模型，截图或录屏抽取的画面会发送到该模型服务地址；通过核心模型网关计量与监控。仅声明或探测模型支持图片，不能证明实际转录准确。没有已配置的可用视觉模型时，任务可能失败，需要修改配置后继续。
- 核心已实现疑点优先核对、服务器保存校验、未知时间保存、幂等部分保存、来源与批次筛选及关键词搜索。明确相同素材与位置可复用记录；相同文字本身不会自动去重，疑似重叠须明确选择复用或保留为另一次发言。跨批重叠以共享记录对齐；缺少重叠证据时保留导入分组并提示，顺序冲突显示不确定性。
- 已实现保存后纠错与版本保留、改关联、撤销本批保存关系；共享消息及人工修正受到保护。一个来源身份含多个批次时，不会通过单批操作静默修改全部归属，需要为拆分的批次选择不同会话标识。来源说明与批次备注分开保存。
- 已实现后台任务、停止、未完成范围继续和启动时中断恢复；切换页面不终止任务，应用退出后不继续执行。导入按后台任务使用核心模型调度，交互请求优先；未承诺吞吐量或剩余时长。重新识别保留人工编辑和正式记录，差异进入核对。
- 分项清理先展示影响并检查依赖。未完成且未移出列表的任务所依赖素材、其他批次共享素材不能直接清理；停止后可将任务移出列表，再单独清理素材。移出任务不删除正式记录，未保存缺口标记保留。清理素材副本不删除用户最初选择的文件。
- 手工新增、合并、拆分气泡和手动聊天区域裁剪仍属于后续建议，首版没有提供这些编辑工具；单条记录备注也未纳入首版。首版允许修改识别候选、明确忽略非消息内容，并回查仍保留的证据。
- 先在本机验证不同来源实际界面里的常见字号、主题、日期条、引用、长气泡及不同滚动速度；交互草图和合成检查不能代替真实素材的识别质量验收。
- 首版容量与时长限制不代表识别质量保证，不承诺准确率或速度。应观察文字、发言人、气泡边界、顺序、重复／漏消息和来源定位是否正确，而不只核对模型是否返回了文本。
- 完成页只说明实际识别和保存范围、可检测的缺口；识别了可见素材不代表拥有完整聊天历史。快滚、遮挡或不连续素材中的未见内容不能恢复。
- 保存可见图片、语音、视频气泡时明确它是素材里的显示信息；没有原件就不呈现为可播放附件。以后补原件的关联规则待定。
- 来源软件界面改版、多主题、快速滚动与长气泡跨画面的识别、拼接和漏检质量仍需真实样本验证；首版并发与资源占用也需结合实际模型持续验证。
