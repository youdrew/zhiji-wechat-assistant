# MCP 插件使用说明

产品：知己微信助手 · Zhiji WeChat Assistant

MCP 插件让运行在**同一台 Windows 电脑**上的 AI 客户端（如 Claude Desktop 等支持 MCP stdio 的应用）通过 MCP 协议使用知己的资料与业务能力：读取已保存账号的聊天与记忆、编辑人工资料、运行分析任务和管理本地内容。本版不提供微信发送工具。知己主窗口未打开时，客户端会按需拉起无界面的后台 Core，无需先启动主窗口。

技术方案见 [MCP 插件实施方案](mcp-plugin-implementation.md)；进程与安全边界见[插件架构](plugin-architecture.md)。

## 1. 前置条件

- 已安装知己微信助手（安装版）。MCP 只在本机回环地址通信，不开放远程接入。
- 至少一个已配对的 AI 客户端档案（见下文配对）。
- 微信是否运行只影响实时读取；已保存资料始终可以按账号离线读取。

## 2. 配对一个客户端

1. 打开知己主窗口，进入 **设置 → 插件 → MCP**（管理页）。
2. 点击“新建客户端”，填写展示名（仅用于界面显示，不作为身份凭据）。
3. 选择授权模式（新建客户端可用“完整授权”或“逐联系人授权”，默认预选项在插件设置中配置）。
4. 生成凭据：`clientId` 与 `zmc_` 开头的配对密钥**只在生成时展示一次**，之后不可回显；请立即保存到客户端配置中。重新生成凭据会使旧密钥立即失效。
5. 配对前可先阅读同一页面的“**安全与数据说明**”（外部模型数据流向、提示注入风险等都在这一页集中说明）。

## 3. 配置本机 AI 客户端

客户端以 stdio 方式启动适配器。适配器位于安装目录的 `resources\client\scripts\mcp-stdio-adapter.py`，用安装自带的 Python 运行：

```json
{
  "mcpServers": {
    "zhiji": {
      "command": "D:\\Path\\To\\Zhiji\\resources\\client\\runtime\\python\\python.exe",
      "args": [
        "D:\\Path\\To\\Zhiji\\resources\\client\\scripts\\mcp-stdio-adapter.py",
        "--root", "D:\\Path\\To\\Zhiji\\resources\\client",
        "--config", "D:\\Path\\To\\mcp-client.json"
      ]
    }
  }
}
```

- `--root`：知己安装目录（含 `bridge/`、`scripts/` 与 `runtime/` 的那层）。省略时适配器默认使用自己所在的安装。
- 凭据文件 `mcp-client.json` 内容为 `{"clientId": "...", "credential": "zmc_..."}`；也可以改用环境变量 `KYF_MCP_CLIENT_ID` / `KYF_MCP_CREDENTIAL`。**不要把凭据写进命令行参数**（进程列表可见），也不要提交到任何仓库。
- 同一台机器可以配对多个客户端；每个客户端有独立、可撤销的授权。

连接成功后，客户端会看到 `zhiji_ping`、`zhiji_list_accounts`、`zhiji_search_messages`、`zhiji_list_memories`、`zhiji_update_memory` 等工具；列表只显示当前档案已开放的能力。

## 4. 授权模式

| 模式 | 行为 |
| --- | --- |
| **完整授权** | 覆盖本安装与当前数据根中所有已保存账号、当前与以后新增的联系人，以及全部已登记业务能力与应用管理。模型密钥明文读取和 MCP 自身授权设置是固定排除项。 |
| **逐联系人授权** | 只能访问逐个勾选的账号×联系人；新账号、新联系人不自动加入。可在档案上另开“全局管理”开关（默认关闭）以管理模型/插件/应用设置。 |

- 模式切换、增删联系人、停用或撤销客户端会立即提升授权版本：旧游标、排队任务、一次性确认与在途操作全部失效；已经交给外部模型的内容无法收回，撤销只阻止后续提供。
- 每次工具调用都由 Core 在服务端重新核验权限，客户端本地的工具列表只是展示。
- “立即断开所有连接”会一次性丢弃全部连接令牌；已配对客户端可重新握手。

## 5. 运行行为

- **无界面 Core**：首个 MCP 调用按需启动后台 Core（同一安装复用同一实例）；主窗口关闭不影响仍被 MCP 使用的 Core，最后一个使用方退出并空闲后才停机。
- **高影响删除**：删除整个账号、清空本机数据是两段式——AI 发起后必须由**本机确认窗**（独立 Electron 窗口，不需要主窗口打开）人工确认，确认一次性、短时有效；无可交互桌面或超时一律不执行。
- **总开关**：MCP 管理页的总启停关闭后立即拒绝所有新握手并断开现有连接；重启后仍保持关闭。

## 6. 禁用与卸载

- 在知己的插件设置中**停用** kyf.mcp 插件，或删除 `plugins/kyf.mcp` 目录（卸载）后，MCP 的所有入口随之关闭：新握手、既有连接令牌与设置通道都以稳定错误拒绝，没有残留可调用入口。重新启用插件后原配对档案继续有效。
- 撤销某个客户端（管理页“撤销”）只删除该档案及其联系人授权；该客户端标识永不复用。

## 7. 常见错误码

| 错误码 | 含义与处理 |
| --- | --- |
| `mcp-unauthorized` | 凭据无效或连接令牌过期；重新配对（凭据重置需在管理页重新生成）。 |
| `mcp-disabled` | MCP 总开关已关闭；在管理页打开。 |
| `mcp-plugin-disabled` | MCP 插件已被停用或卸载；在知己插件设置中启用。 |
| `capability-not-open` | 当前档案未开放该能力（模式或全局管理限制）。 |
| `contact-not-authorized` | 逐联系人模式下该联系人未授权；在管理页勾选。 |
| `stale-authorization` | 授权已变化（模式/名单/凭据变动），请重新握手。 |
| `version-conflict` | 写入的预期版本与当前不符；重新读取后再提交。 |
| `core-unavailable` | 本机服务暂不可用；显式启动一次知己后再试。 |

## 8. 安全须知（摘要）

完整说明以 MCP 管理页的“安全与数据说明”为准：

- 外部 AI 客户端会把工具返回的资料交给它配置的模型服务，可能因此离开本机；请在配对前确认你信任该客户端及其模型服务商。
- 聊天内容中可能存在诱导客户端调用工具的文本（提示注入）；知己侧的授权检查不受影响，但客户端自身的安全策略取决于该客户端。
- 同一 Windows 用户下的其他进程原则上可以读取该用户可访问的本机文件；MCP 权限系统约束的是受支持的调用与误用，不是操作系统级恶意程序隔离。
- 凭据与配置文件只放在本机；不要把 `mcp-client.json`、日志或调用记录提交到 Git。
