# 开发者模式实现与验收

当前状态（2026-11-02）：全局模型调用入口、常开用量账本、好友筛选和汇总、独立窗口以及按需诊断采集均已在本地 `dev` 实现。入口位于左侧导航栏设置上方，默认查看当前账号全部好友；基础归属、状态、耗时和用量常记，完整提示词与回复由开发者模式单独控制。详见[需求状态](developer-mode-requirements.md)、本文末尾“调用记录与诊断记录合并”及[插件架构实现说明](plugin-architecture.md)。

开发者模式在本机保存模型请求与响应等诊断内容，用于查看实际请求、原始响应、模型正文、应用处理结果及失败阶段。在「设置 → 模型设置」开启采集；左侧“模型调用”入口常驻，关闭诊断采集后仍可查看用量和已有记录。它打开独立于主页面的桌面窗口。

下文保留历次采集设计和验证记录，旧的聊天头部入口、跟随联系人及 Laya 采集描述属于历史版本；当前用法以上述说明及文末为准。真实客户端、前台焦点和发行环境等未闭环验证统一见[需求待办清单](requirements-todo.md#validation)。

默认关闭，默认保留 7 天，可选 1／7／30 天。记录保存在运行根目录的 `.local/model-traces/`，不进入分析数据库、普通日志或发布包。正文可能包含聊天内容；复制到系统剪贴板的内容不受记录清理管理。

## 采集与展示

- Python 业务执行创建诊断任务、执行编号及可信账号／联系人作用域，经私有工作进程管道传递生产端能力。重复执行创建新任务，并在可得时关联原业务任务和前次执行。
- 直接连接器在 SDK 的最终 HTTP 边界观察请求与响应；助手通过固定 OpenCode 1.18.34 引擎的常驻回环中继观察实际 provider 请求，包括工具定义和工具结果。开关不改变引擎配置、进程、会话或请求路由。
- Laya 在实际设备推理批次边界记录问题组、消费的上下文、裁切预算、设备和概率；WebGPU 失败后 CPU 重跑为同一步骤的两次尝试。初始化 probe 不计入模型调用。
- 传输、应用处理、采用情况和采集完整性分别保存。失败尝试不被后续成功覆盖；准备、缓存命中和原生工具事件显示为零次请求。
- 独立窗口默认 960×760px，最小 600×480px，可移动和调整大小，重复打开聚焦已有窗口。采集内容在「调用记录」展开后的请求、响应和过程与错误页查看，支持正文查找、复制和 64KiB 正文分页；打开或关闭窗口不改变主页面布局和助手可见性。

## 身份和生命周期

查看能力由受信 Electron 主进程通过现有控制凭据换取，不把凭据交给页面；IPC 验证受信主窗口或独立记录窗口、主框架和操作白名单。独立页面使用最小 preload 接口。后端根据当前有效账号及切换代数鉴权，账号参数和记录编号不构成访问凭证。后台生产任务保持创建时作用域。

记录窗口默认跟随主页面的账号和联系人；切换账号立即清空旧列表、详情及缓存，迟到读取不能进入新账号。切换主视图时窗口保持打开。主窗口退出、关闭或重新载入时关闭记录窗口并撤销读取；仅关闭记录窗口不停止采集。

启停使用采集版本与进程确认；关闭立即拒绝旧版本内容，业务继续。断流、磁盘故障、拥塞和预算不足均只暂停诊断，保留缺口和可确认的状态；按有上限退避检查存储，恢复只影响新的尝试。

清空、账号删除、助手会话删除以及联系人记忆清空先持久化删除约束，再清理正文及数据库副本。重启先完成未结束的删除。窗口关闭或切换联系人不触发删除。窗口收到删除版本变化后撤销正文缓存，迟到读取不能重新显示已删内容。

查看删除版本与采集删除版本分离。保留期、容量回收和按作用域删除只使相关记录失效，其他有效任务继续采集；全局清空才推进全局采集隔离版本。已删除记录的编号保留有界失效标记，生产任务退休后释放，拒绝迟到开始、正文和解析结果重新创建记录。某个任务的采集凭据撤销，以及该任务旧请求的迟到传输失败，不会暂停同进程其他任务或清掉它们的队列。

容量限制为 10,000 条实际尝试、500MiB 总存储、单侧 16MiB 脱敏 UTF-8 文本。任务事件另有 10,000 条上限并计入存储。大内容以 8KiB 内容块传输，每个信封不超过 64KiB；重复、冲突、缺块、字节偏移和结束标记均验证。

新增内容缓冲采用统一预算：每个获准 Node 进程 6MiB（采集工作 4MiB、发送队列 2MiB），最多 8 个进程；Python 队列与待关联结果共用 8MiB，余下 8MiB 为有界在途信封余量。第九个进程使采集暂停。此口径为内容字节预算；完整进程堆还包括业务对象、SDK、运行时和元数据，不能用内容预算冒充整个进程内存。

凭据在第一次诊断序列化前脱敏，涵盖允许列表外请求头、已知密钥跨网络分片／响应增量、等价转义、URL 编码和签名参数。Python 业务解析结果按明确尝试编号关联，先脱敏再进入队列；较大应用结果以明确省略说明替代，原始响应仍受独立正文上限管理。

## 历史验收与复现（嵌入面板版本）

本节及下文「首次开发复核」保存改为独立窗口之前的验收数据。性能基准中的「面板」指当时嵌入主页面的查看界面；这些数值不能代替独立窗口版本的界面、生命周期及性能验收。独立窗口变更见文末。

2026 年 10 月 12 日，Windows 11 build 26200，i7-13700K（24 逻辑处理器），内存约 95.7GiB；测试数据位于 D 盘 aigo NVMe SSD P7000Z 4TB。项目 Node 24.11.1，Python 3.14，Electron 44.4.3（内置 Node 24.21.0），OpenCode 1.18.34。

| 操作 | 应用就绪后首次 | 中位数 | p95 | 最大值 | 阈值 |
| --- | --- | --- | --- | --- | --- |
| 首批列表可操作 | 124.1ms | 98.8ms | 149.7ms | 198.4ms | ≤500ms |
| 概览及首块正文可操作 | 102.9ms | 118.2ms | 172.8ms | 438.7ms | ≤1s |

## 保留边界

固定引擎目前只提供可靠的原生会话关联，自动压缩通知可能晚于实际 provider 请求。所有 provider 请求、原生工具和压缩事件均归正确任务；无法确定具体内部请求目的时保留未知，不通过提示词文本或请求先后猜测。自动压缩事件中的原生消息编号可在同任务详情查看。

超过 128KiB 的单个协议 JSON 事件使用有界增量词法处理，保存脱敏原文至单侧 16MiB 上限；该路径不保证能派生累积正文或用量，缺失字段显示未采集，可查原始内容，不伪造数值。

本地 Laya 验证使用合成推理执行器覆盖 probe、批次和设备回退；本机没有安装 Laya 权重，因此未把真实 ONNX 模型推理质量列为已通过项。固定联系人筛选，以及跨重启记忆窗口位置、大小和筛选仍为需求中约定的增强项。

## 首次开发复核（2026-10-12，嵌入面板版本历史记录）

本轮直接在 `dev` 继续已有未提交实现，保持需求中的默认容量、保留期限和核心范围。没有修改真实账号的采集偏好，没有使用真实聊天作为测试数据，也未提交或推送代码。

补齐的关键边界：

- 同任务查看解除原有状态、功能和日期筛选，能够看到前次失败和后续重试；UTF-8 正文翻页保留实际字节边界。迟到列表、详情或打开操作不会覆盖新选择或重新打开已关闭面板。
- Gemini、Responses 请求按实际字段显示消息、工具和参数；服务不可用与记录已删除分开显示。设置保存失败后可重试，不再永久停留在「正在开启」。
- 回复预测兼容 HTTP 入口的位置参数，保留账号、联系人和本次执行关联；缓存命中和共享在途推理以零请求任务事件说明。
- 启动时存储故障解除后恢复持久化偏好；故障期间关闭后不会自动重新开启。重启遗留请求标记业务结果未知，关闭时不再遍历或序列化 Python 应用结果正文。
- 异常 provider JSON、诊断解析错误与不可序列化结果不会中断业务响应；混合 URL／Unicode 编码和跨分片的测试密钥正确脱敏，大 JSON 中非字符串敏感字段同样处理。
- 引擎初始化失败、退出和事件通道断开后关闭对应中继；旧消息不会绑定新执行。窗口销毁撤销在途读取，重复销毁不会移除新窗口接口，记录面板刷新不会留下隐藏助手的空白侧栏。
