# 从 SuperDatingApp 迁入能力的对照与计划

调研日期：2026-10-09。本文依据两个项目的源码，区分旧项目已经实现的能力、Know Your Friends 已有基础，以及本轮新增与后续计划。它不是实际数据迁移记录，也不代表后续能力已经上线。

状态复核（2026-11-02）：本文是迁移起点的历史对照。自动建议、本人资料与联系目标、结构化关系记忆、关系趋势、媒体显示与有限视觉理解、外部聊天导入及 Windows 文字发送均已有后续实现；下文“本轮只实现”“暂未交付”等措辞保留 2026-10-09 的范围，不代表当前待办。当前能力以各使用说明为准，未完成事项统一见[需求待办清单](requirements-todo.md)。实际旧私人数据迁移仍未据此执行或验收。

本轮只实现按联系人开启的自动回复建议：发现对方新消息后，在聊天输入区域独立生成 3 条可复制候选，由用户决定是否采用。候选不进入主动聊天助手的对话，也不使用其讨论作为事实。旧项目保持只读；本轮不导入旧联系人、聊天、长期记忆、媒体或个人配置，不操作微信发送。

## 结论与复用边界

保留 Know Your Friends 的微信读取、账号隔离、历史持久化、分层摘要、模型连接和聊天助手。优先迁入旧项目在这些基础之上的产品规则与可靠性设计，不再并列维护第二套聊天数据库、模型客户端和聊天助手。

旧项目**没有收到新消息后自动生成建议的联系人开关**。它已有手动触发的独立回复草稿任务，本轮自动监听、去重、合并连续消息和开关生命周期属于新增连接逻辑。旧项目的后台历史建档、批量任务和“一键更新聊天”也不等于新消息自动建议。

源码证据的路径约定：表中的 `superdating/` 和旧项目 `tests/` 相对于 SuperDatingApp 根目录；可点击的本项目链接相对于本文所在目录。行号只作为调研时的定位提示，后续修改以函数名为准。

## P0：本轮自动建议的交付边界

自动建议接入现有 Advisor，行为以[聊天助手说明](advisor.md)为准。这里记录设计来源和必须验收的约束，不替代实现测试报告。

1. 开关按微信账号和联系人隔离，初始关闭，使用独立生成任务与已保存的模型配置，不绑定主动助手。仅支持可识别的个人私聊，不将群聊或服务号混入。
2. 应用运行且来源可用时检查已开启联系人。切换聊天和关闭助手面板不应丢失监听；关闭应用后不执行。不能将“当前页面每几秒刷新一次”包装成全局后台监听。
3. 显式开启时检查最新一轮：最后一条有效聊天来自对方且用户尚未回复，就生成一轮候选，不逐条补跑旧历史。重复开启请求不重启任务；主动关闭再开启可重新生成。应用重启或来源重新连接仍只建立当前消息起点，不补跑离线积压。单纯窗口变化、旧正文补齐或重新排序不等于新来信。
4. 连续来信短暂合并，同一联系人不并发生成；已有手动助手任务时等待。用户已经回复、关闭开关、切换账号、来源失效或清除账号时，待处理自动任务必须取消或失效。完成前重新检查归属，旧结果不能冒充当前可用建议。
5. 固定任务是生成三条“我下句话应该如何回复”的候选。自动任务沿用当前微信会话的可信资料和模型配置；保留用户手动草稿，独立保存候选，不把建议写进主动问答、微信聊天或公共事实摘要。
6. 建议只供用户选择，不自动发送，不编造用户经历、共同经历、时间安排或承诺；不把转发、引用当作发送者自己的事实；目标和风格不能覆盖对方明确边界。
7. 媒体消息可以作为新消息信号，但仅有占位时不得声称知道媒体内容。没有可靠文本依据时可以说明缺少信息，而不是补造回复前提。
8. 失败保留可理解的状态，同一批消息不无限重试。处理速度取决于微信本地同步、可读快照和所选模型，不承诺手机端消息即时触发。

两个容易混淆的已有能力：

- `Laya 回复预测`（历史模块，已退役） 判断的是**对方下一次回复的可能用途**，不生成对方原话，也不是“替我拟下一句”；不能把 `/api/predict-reply` 结果直接当成自动草稿。
- 旧项目 `generate_drafts` 每批生成 20 个候选再审计，必要时补一批，最多经过四次模型调用。这适合用户主动索取多个选项，不宜原样套到每条新消息。本轮复用模型运行时和旧版任务可靠性规则，独立生成三条候选并验证格式；后续再评估事实审计流程。格式验证不等于事实核验，本轮尚未迁入旧版全部审计能力。

## 后续分期

**P1：先补用户可控制的资料层。** 在本项目身份模型上加入联系人目标、用户自身背景与表达风格，再加入可编辑事实、确认与否定状态、证据回查、排除规则及版本失效。已有历史摘要继续复用；不要为了提取结构化记忆再复制一份不受同一清理流程约束的全部聊天。历史建档需要单独的可续跑任务与覆盖进度。

**P2：按需求增加媒体、互动趋势和联系人回收。** 优先确定媒体原件归属与来源适配，再实现微信转写补齐；独立 ASR、图像/视频理解属于另行选型和验证。互动趋势应展示计算范围，人工判断与模型猜测分开。回收站需覆盖任务、资料和文件的完整生命周期。

**暂未交付的方向：** 其他聊天平台适配、跨平台同人身份合并、GUI 自动读取或代发、独立语音识别、图片/视频内容理解。旧项目的通用平台字段或导入格式，不代表已经有其他平台的实时连接器。跨平台身份也不能凭相同显示名自动合并。

## 验证准则与以后迁移数据的前置条件

本次文档工作没有运行真实数据迁移、模型调用或服务；下列是需要由实现测试满足的验收准则，不是本文件声称已经通过的结果。

| 范围 | 最低验证要求 |
| --- | --- |
| P0 自动触发 | 默认关闭；开启时为最新未回复消息生成一轮；重复开启与轮询不重复触发；重启不补跑离线积压；连续消息合并；非当前可见联系人仍可检测；仅自己的消息、群聊和服务号不触发。 |
| P0 并发与生命周期 | 手动任务不被自动任务抢占；关闭开关、已回复、账号切换、来源重连、清除资料后不发布过期结果；异常不无限重试；不改用户手动草稿，不自动发送。 |
| P1 资料与记忆 | 目标不是事实；引用不误归因；证据不能跨联系人或账号；编辑、否定、清空记忆后旧模型结果不能重新写回；无变化重跑不制造重复记录。 |
| P2 媒体与转写 | 路径越界与错误文件头被拒绝；缺失原件明确标记；同消息重导入不重复登记；转写保留原文、来源与消息身份，普通正文冲突继续拒绝；输入变化使已有分析失效。 |
| P2 删除与恢复 | 删除一个联系人不影响其他人或微信源数据；迟到任务不能复活资料；恢复不重启旧任务；共享文件和清理失败正确处理。 |

可参考旧测试的行为而非直接复制环境依赖：`tests/test_reply_jobs.py`、`test_reply_drafts.py`、`test_history.py`、`test_clear_memories.py`、`test_contact_trash_jobs.py`；本项目已有的 `Advisor 边界测试`（历史模块，已退役）、`来源身份测试`（历史模块，已退役）与`共享上下文测试`（历史模块，已退役）继续保留。

以后若执行实际数据迁移，先另行确定范围并备份，再建立“旧联系人 → 本项目账号/会话、旧消息 UUID → 原生消息身份”的明确映射。逐条核对记忆证据、确认/否定状态、目标与备注、转写来源、媒体可读性和删除标记。缺失映射留待处理，不能猜测挂到同名联系人，也不能为方便导入清空或覆盖本项目已有资料。迁移统计、去重与回滚必须可核验；真实资料及运行配置始终留在本机，不进入代码仓库。
