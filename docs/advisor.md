# 助手仓库与聊天助手

> Know Your Friends 修改说明（2026-10-09）：按联系人自动生成回复建议，结果改为聊天页内 3 条独立候选；主动助手支持切换会话后继续生成，保留上游历史与权限边界。

## 分析与建议

2026-10-12 起，逐句解读和三条回复合并到好友姓名右侧的 **分析与建议**。开启后每条好友新消息分别登记任务，结果默认收起，点击消息旁入口在原消息下查看。每条候选有独立复制操作，不修改手动草稿，不发送微信。

解读和候选可以分别完成或失败，支持按部分重试。用户回复或收到后续消息后，较早候选标为历史参考，保留在本机。关闭总开关取消未完成任务；重启不补跑全部离线消息。旧开关保持原有范围，明确操作新总开关后再迁移，不把按轮候选冒充逐条结果。

具体触发、上下文、历史留存、复制和四种旧设置迁移规则见[分析与建议说明](message-analysis.md)。主动助手仍是独立提问空间，自动结果不进入助手讨论或已确认关系记忆；聊天助手可使用“模型设置”中启用的外部搜索和网页阅读，默认关闭（见“外部搜索源”）。模型并行数量同样由“模型设置”统一管理，所有插件共用模型网关的调度额度；插件只保留各自的业务设置。

左侧助手图标进入“助手仓库”，可以启用预设或创建自己的 Agent，编辑名称、欢迎语、提示词和 Skills。聊天输入区的“聊天助手”按钮为当前好友打开一个可移动、可缩放的独立窗口，每位好友各一个，可以同时打开多位好友的助手窗口。窗口固定在打开时的好友，切换主聊天不会更换助手讨论；在另一位好友处点击入口会另开那位好友的窗口。重复打开同一好友会聚焦已有窗口；关闭窗口会先隐藏并保留页面，最近关闭的三个窗口再次打开时立即恢复，更早关闭的会释放，讨论和草稿仍按账号保存。停用插件、切换或清除微信账号时，相关窗口随之关闭。预设“狗头军师”的模板名称独立于聊天入口。空会话显示自定义欢迎语和居中输入框，已有记录时显示时间线。对话、草稿和已生成结果按微信账号、会话及 Agent 保存。

仓库不显示引擎状态或预设标记。每张助手卡片都提供编辑和删除，包括内置助手；删除内置助手后重启不会自动恢复，删除正在运行的助手会停止其当前任务。仓库可以删空，并可再次新建助手。

顶部提供“历史”“新建”“更多”。`/new` 或兼容别名 `/reset` 新建讨论，不停止原会话的任务；`/sessions` 打开历史，`/compact` 压缩当前讨论。只有整条输入完全匹配命令时才执行，其他 `/` 开头的内容仍作为普通问题。点击当前 Agent 名称可以切换仓库中启用的模板。助手回复下不再显示“复制”按钮，文字仍可选中。

应用保持运行时，已经提交的助手提问在切换联系人、切换助手模板、隐藏助手窗口或打开知己分析窗口后继续在后台生成。切回原会话会读取最新进度或完整结果，不重复生成；不同联系人的任务可同时进行，对话和草稿保持隔离。只有点击对应的“停止”按钮才主动结束该任务。对方在回答期间发来新消息不会中断回答：微信读取短暂不可用、知己分析资料在导入期间的变化都不算账号或资料变更，新消息和资料更新从下一个问题起生效。关闭应用、切换或清除账号、修改模型配置、修改助手模板或数据来源确实改变等情况仍会结束相关任务。首次加载尚未提交成功的提问会保留为原会话的可重试草稿。

两类助手都会读取单独标明的“知己分析资料”：已确认的关系记忆、联系目标、本账号的自身背景与表达风格；有当前原文和发言人依据的自动提取候选可作为“待确认资料”补充，用户观察单列为主观看法。待确认资料和观察不能被当成已确认事实，已忽略、已删除、原文失效的候选及未保存草稿不会进入。资料变化后，原生模型会话换代，旧的自动候选显示为过期，可重新生成。详见 [知己分析说明](friend-analysis.md)。

聊天标题旁的“分析与建议”统一管理逐条解读和候选；它与主动助手的提问及讨论分别保存。

新建或编辑助手时，技能按每列五项、每组两列排列，后续项目向下延续并通过列表滚动查看。“技能”标题右侧的“移除技能”切换移除模式；点击已选择技能旁的 × 从当前助手取消选择，保存后生效。取消编辑不会删除共享资料，也不会影响其他助手。

## 导入助手

仓库只有“新建助手”入口，点击直接打开导入窗口，没有自定义创建模式或模式切换。导入支持 GitHub 仓库、tree 或 SKILL.md blob 地址，以及本地 SKILL.md、技能目录和 ZIP。可以先读取预览并编辑名称、说明、欢迎语和提示词，也可以在填写有效 GitHub 来源后直接点击“导入并创建”。导入失败保留表单，取消不创建卡片，重试不会重复创建；已有助手继续可以编辑。

导入器解析安全 YAML 元数据、包内引用与许可证，保留完整入口和参考原文，记录固定提交或内容摘要。脚本、ChatLab、技能长期记忆及二进制资料不执行；存在这些依赖时需要确认“使用只读适配版本”。这一状态表示分析方法与允许的文本资料可用，不表示原仓库所有工具功能都已接入。

每轮通过本地检索提供最多三篇预算内的完整参考资料，不额外调用模型分类，也不将整个资料包拼入系统提示词。超出本轮预算的参考不截断、不伪称已读。模型仍只允许读取当前托管微信资料文件，没有增加命令、文件写入、网络或任意文件读取权限。

助手和固定版本的技能包原子保存。重复导入同来源、同版本会复用已有助手，不覆盖其编辑和历史；新版本建立新的助手。旧版配置首次修改前在 `.local/advisor/config.v1.backup.json` 保存备份，旧助手与技能 ID、删除标记和对话关联保持不变。

发送的问题由后台持久接收后按当前讨论顺序执行。正在回答时仍可“加入队列”，待处理列表支持编辑正文、移除、暂停和继续；当前轮开始后显示持续更新的等待、思考或回答状态，正文逐步显示。提交失败保留原问题和草稿，重试沿用原请求编号；切换会话或重开窗口时使用已保存结果恢复，不重复添加同一提问。停止或失败会暂停后续队列；应用重启后未开始的问题保留，等待手动继续。详见[消息排队说明](advisor-message-queue.md)。

输入框左下角的“深度思考”默认开启，选择按设备保存。该开关控制下一次正式回答及图片观察；聊天摘要、讨论恢复摘要和原生讨论压缩始终请求关闭思考。该选项通过聊天模板参数生效，适用于 vLLM、SGLang、llama.cpp 等 Chat Completions 兼容服务；其他协议保持服务默认。服务拒绝该参数时会明确报错。自动回复建议和逐句分析不受此开关影响。

## 跨好友讨论（@好友，2026-10-14）

从好友聊天中打开助手，新讨论的输入框默认填入 `@当前好友`，输入区上方也常驻显示该好友，表示每轮自动带入其上下文。已有草稿不会被覆盖，主动删除默认文字后不会反复填回；删除文字不会移除当前好友的固定上下文。

输入框中输入 `@` 会列出已添加的单聊好友，不含群聊和当前好友；继续输入可按备注名筛选，用方向键、回车、Tab 或点击选择。选中后输入框插入“@备注名”。发送时，只有文字中仍保留“@备注名”的选中项会加入讨论；手动输入的 @ 文字按普通文字发送。

选中的好友身份随草稿保存在本机，重开或重载窗口后仍引用原好友，不按姓名猜测同名联系人。仅保存草稿不会加载额外好友资料；提交问题后才将选中的好友加入讨论。

每条提问下方显示“上下文”及本轮涉及的好友，默认显示两位，多出的折叠为 `+N`，点击可展开完整名单和聊天记录、好友资料的提供情况。当前好友的资料属于必读上下文，其他好友的资料供模型按需读取；空资料、不可用和准备中分别标明。这里记录提供给模型的资料范围，不表示模型已经逐条阅读，也不作为回答引用的证明。

名单按每条问题开始执行时的联系人身份与称呼保存，之后修改好友备注、增删讨论成员或重新打开窗口，都不会改变旧消息的名单。排队中的问题在实际开始执行时才确定本轮范围；历史消息没有快照时显示“上下文未记录”，不会根据当前名单补填。

好友加入后显示在输入框上方，之后在这段讨论里提问无需再次 @；点击 × 移出，只影响之后的回答。讨论仍保存在当前好友的历史中，加入人数不设上限。

当前好友的资料仍按原方式每轮完整读取。被 @ 的好友不压缩进这份资料：每轮为每位好友生成完整聊天记录和知己分析资料两个文件，并附一份索引，列出消息数、双方各自条数、时间跨度和按月的行号位置。助手按问题自行决定读哪些文件、读哪一段、读多少；对比不同好友时，提示词要求先考虑各自的记录量。首次 @ 一位尚未整理的好友会先读取其全部历史，期间显示“正在准备 xx 的聊天资料”。好友已不在已添加的会话中时，本轮索引注明资料不可用。

这些文件只在本轮回答期间保存在引擎工作目录，回答结束即删除。被 @ 好友的图片不做新的视觉识别，只使用文字和微信已有的语音转写。他们的资料变化不会使原生会话换代：每轮重新生成文件，上一轮的读取内容会被清理。本轮的模型用量仍记在当前好友名下，Core 的“多好友任务”记账尚未开放给插件任务。

## 聊天未读提醒（2026-10-18）

会话列表仅在头像上显示聊天消息的未读标记。点击好友会话后，本应用立即标为已读；刷新或重启后保持已读，后续收到新的未读消息再提醒。当前可见的会话更新后保持已读，后台窗口或其他页面不会自动清除聊天未读。已读记录按微信账号保存在本机，不修改微信数据库。

聊天助手回答完成、失败或其他讨论尚未查看，都不会再在好友列表或「聊天助手」按钮上显示红点。回答内容和运行状态仍在对应讨论中查看。

## 从聊天消息问助手（2026-10-17）

在聊天窗口右键任意一条消息，菜单提供「复制」和「问聊天助手」。选中消息中的一部分文字再右键，两项都只用选中的部分。「问聊天助手」打开面板，把原话放进当前讨论的输入框末尾，写明是“我发的”、群成员“某某的”还是“对方”的消息，等你补充问题后再发送，不会自动提交。媒体消息没有文字时只提供「问聊天助手」；没有启用聊天助手时只有「复制」。

## 重新生成与修改问题（2026-10-17）

最近一轮回答完成后，鼠标悬停在最后一条回答下方显示「重新生成」，悬停在最后一个问题下方显示「编辑」。重新生成用原问题再回答一次；编辑把问题放进输入框，上方显示“修改上一个问题 · 取消”，修改后发送即替换这一轮，取消或按 Esc 恢复原来的草稿。修改提交成功后也恢复原草稿，提交期间新输入的文字一并保留，合并超出长度限制时可切换或复制两份草稿；提交失败保留修改后的问题供重试。停止或失败的一轮只能编辑，没有回答可重新生成。回答进行中、有问题排队或会话只读时不显示这两个操作，只能替换最近一轮。

被替换的回答或问题不删除，而是在原位置折叠为“上一版回答”或“修改前的提问”，点开可查看全文；它们不再进入后续的上下文、讨论整理和历史列表预览。引擎先把原生会话回退到被替换的问题之前再提问，与本地记录保持一致；找不到对应的原生轮次（例如较早版本的记录或已重建的会话）时，改为按本地讨论记录受控重建一次。

## 外部搜索源（2026-10-15）

聊天助手默认不联网。在「设置 → 模型设置」的「统一调度与联网」分组里，「联网搜索来源」可选：

- **关闭**：默认值，助手只根据聊天资料回答。
- **SearXNG**：填写本机或自建服务器的「SearXNG 地址」（默认 `http://127.0.0.1:8080`）。SearXNG 需要在它的 `settings.yml` 里把 `json` 加入 `search.formats`，否则搜索会提示这一步。

搜索关键词会发送到所选 SearXNG 搜索源；助手应只使用公开主题关键词，不把聊天原文、联系人标识或私人资料放进搜索词。配置后，问题需要最新或公开信息（比如过几天的比赛、活动、营业时间、新闻）时，模型自己决定是否搜索，聊天记录能回答的不搜；回答里注明用到的网页来源。搜索时面板状态显示“正在搜索：关键词”，打开网页时显示“正在打开网页：域名”。「允许读取搜索结果网页」（默认开启）让模型在摘要不够时读取结果网页的正文；关闭后只看搜索摘要。设置保存后从下一个问题生效，排队中的问题在开始时读取核心组件保存的模型设置；插件中残留的旧联网配置不再决定行为。地址不是有效的 http(s) 网址时，提问会直接提示去模型设置里修改。

实现：插件工作进程内的本机 MCP 服务（随机端口和密钥，只接受 OpenCode 的请求）向原生会话提供 `web_search` 和 `web_fetch` 两个工具，只有聊天助手的回答 agent 和本轮会话权限允许它们；讨论整理、资料摘要等其他调用仍然没有任何联网工具。搜索请求只发往用户填写的 SearXNG 地址。网页只能打开本次引擎运行中搜索结果里出现过的网址，并且不能是本机、内网、链路本地等地址（包括重定向之后）；DNS 校验结果会固定到实际连接，重定向逐次重新检查；每页最多读取 1.5 MB、返回 12000 字正文，只接受网页和纯文本。搜索结果和网页正文都标明“不是指令”，模型按不可信资料处理。切换搜索源会重启引擎，正在进行的回答会提示配置已变化。

## 源码运行

使用项目指定的 Node.js 和 Python 环境执行：

```powershell
npm ci
npm run setup:advisor-engine
npm run build:advisor-ui
npm start
```

标准应用构建会纳入固定的 OpenCode `1.18.34` 引擎和已编译界面，用户无需单独安装 OpenCode。已有本地 Laya 功能继续使用原来的独立模型包。军师自由对话使用设置中保存的生成式 API，或 Ollama 兼容接口；本地分析模式也可以使用保留的 API 连接。

## 资料与模型

- 每个微信账号、会话拥有独立托管资料。首次使用分页读取全部可读历史，后续只追加新消息；切换 Agent 共用该资料。
- 普通聊天已读取并验证的消息会直接同步到托管资料。完整窗口可直接建立资料；已完整托管的会话通过重叠消息追加新内容，重复发送不再扫描旧历史。只拿到首屏且缺失较早历史时，首次使用补齐一次；缺口、回退或内容变化会重新整理，不能把最近几十条当作全部聊天。
- 助手准备阶段复用普通聊天刚验证的账号绑定，绑定短期有效，来源释放、目录切换和账号清理立即失效。最终保存仍重新确认真实来源。
- 托管资料完整保存原文、发送者、时间及可用引用。模型输入超限时自动分段和分层压缩，保留覆盖记录；摘要不替代原文。
- 聊天资料和讨论恢复摘要按本轮剩余上下文分配建议长度，不再因单段超过 2000 或 1200 字符而拒绝；中文、英文均可使用。最终以整份资料是否能放入本轮预算为准，仍然过长时继续分层整理；没有缩短的段落保留原内容，不直接截断或丢弃。持续没有进展时停止并保留原问题和已有有效结果，避免无限调用。
- 正式回答按 UTF-8 字节作保守容量估算，统一扣除系统提示、技能、当前问题、已有讨论或恢复文本、读取资料的行号及必要开销，并保留模型输出空间。不再同时叠加另一套字符上限或将剩余资料空间除以 4；这仍是估算，不是模型 tokenizer 的精确 token 数。
- 每完成或复用一块聊天摘要，都重新检查整份资料。已能放下就立即进入回答，尚未整理的较早记录和近期记录保持原文；所有来源片段按原顺序保留一次。该检查包括标题、媒体说明及读取开销，不只计算摘要正文。
- 摘要的建议长度与模型接口的输出 token 上限分别处理。上下文需要容纳输入、输出及思考内容，不能将全部上下文都预留给输出；继续保留模型输入检查和输出预留。
- 主动聊天助手仅在用户提交问题时生成回答，必要时压缩；失败或停止保留已生成片段及上次可用资料。自动候选使用同一份微信资料基础，但有独立的任务、结果与模型会话。
- 系统提示要求每轮通过 OpenCode 原生 `read` 工具读取当前会话资料，截断后按实际返回的末行继续。读取与回答由模型处理，程序不以是否读取或分页覆盖情况拦截回答，正文正常流式显示。模型可能跳页；读到文件末尾不等于连续覆盖全文，测速需同时核对实际读取范围。模型需要支持工具调用。
- 一轮运行固定上下文版本，新消息供下一轮使用。Agent 自己的建议和推测不会写入公共事实摘要。
- OpenCode 保存军师多轮对话；本机 SQLite 还保存业务会话、当前选择、草稿、逐次资料版本、用量、压缩状态和恢复摘要；界面缓存不作为持久化真源。取消或失败的未完成轮次从后续原生历史中排除。

## 权限与隔离

军师仅使用当前会话资料、本段讨论中 @ 的好友资料和用户选定的 Skill 文本，生成建议和可复制回复。原生会话仅精确允许读取本轮资料文件和本轮列出的 @ 好友文件，其他文件读取、命令、文件修改、OpenCode 自带网页工具、任意插件或 MCP、子代理及微信发送均禁用。用户配置外部搜索源后，仅聊天助手回答额外允许插件自带的 `web_search` / `web_fetch`（见“外部搜索源”）。模板和聊天内容不能扩大这些权限。

引擎只从项目内固定路径加载并校验大小及 SHA-256；账号数据、HOME、配置、缓存及运行目录独立。不会继承开发用 OpenCode、Claude 或其他工具的认证文件和全局配置。引擎服务使用随机本机端口和密码，界面只访问受控业务接口。

每位好友的助手使用独立 BrowserWindow 和最小权限的 preload；窗口只能向主窗口请求提示、回到原聊天和确认已读三项操作，且只针对自己的好友，会话运行在仅允许脚本的隔离 iframe 中，不直接联网或接触密钥。它不能调用主窗口的软件更新、目录选择或退出接口。Markdown 经过严格净化，图片、链接、脚本和 HTML 事件均不能触发外部动作。复制由用户点击执行。

清除账号时会先停止该账号的任务与引擎，排空写入，再删除托管资料、摘要及军师原生会话；其他账号与微信源数据库不受影响。

## 验证范围

合成检查覆盖首次全量读取、过滤空页、跨分片、长消息、共享压缩、取消、账号及模型切换、原生权限拒绝、持久化恢复、HTTP 边界与界面桥接。原生引擎使用本地合成服务验证五种协议映射和停止后的历史恢复。

真实服务商的摘要准确度、响应速度及真实聊天建议质量仍需实端验收。输入大小采用保守估算，模型实际 token 容量和原生对话压缩由所选模型及 OpenCode 管理。减少摘要调用可能增加正式回答读取的原文量，不能据此保证每轮总耗时都缩短。


## 会话、上下文与恢复（2026-10-10）

同一联系人、同一助手可保留多段讨论。新建与切换不停止后台回答；不同讨论可同时生成，同一讨论的回答与压缩互斥。历史列表保存上次选择，后台结果不会改变当前会话。草稿和滚动位置按讨论保存到账号数据库；冲突或保存失败会明确提示。历史正文分段加载，浏览不会调用模型。

已停用或删除助手的讨论保存在历史列表的“其他助手历史”折叠区，只读查看，也可以改名或删除。全部助手删除后该入口仍保留。右键删除需要确认；生成、停止收尾或压缩状态待核对时不可删。删除会清理该讨论及它使用过的原生会话，失败时显示待重试，不删除微信原文、共享资料摘要和关系记忆。

输入区显示最近一次推理输入与当前窗口，例如“24k / 128k”。这是单次输入，不是累计消耗；没有可信读数时隐藏，估算有“约”标记。点击后可看上次输入、窗口与最近压缩。“更多 → 压缩上下文”始终可找到；回答中禁用，不排队执行。压缩完成后可展开查看真实摘要，原问题和回答保留。停止或超时后先核对原生结果；“核对中”不会被当作成功或空闲。压缩不会额外生成回答。

窗口统一从用户配置、已提供的模型元数据、默认 32768 依次解析；当前模型设置未持久提供元数据时使用统一默认。输出和工具开销预留参与同一份预算。推理模型的思考计入服务商的同一输出上限，因此输出预留取窗口的四分之一，最多 28672 tokens：正文 4096，其余留给思考，思考不再挤占正文。小窗口仍按四分之一预留，32768 窗口为 8192。五种支持协议的非零缓存归一化已用固定 OpenCode 1.18.34 与合成服务验证；真实网关若遗漏统计字段，数字会隐藏。这些验证不能证明真实网关报告的 token 精度或摘要质量。

### 摘要与等待时间（2026-10-16）

聊天资料摘要、讨论恢复摘要及原生讨论压缩默认请求关闭深度思考；正式回答仍遵循输入框的“深度思考”开关。关闭思考是否被服务端执行取决于所选模型的接口支持，程序不通过删除原始聊天来缩短等待。

在“设置 → 模型设置”中填写“生成超时（分钟）”，允许 1–180 的整数，默认 60 分钟。它统一控制模型生成、摘要及图片理解的等待时限，保存后供新请求使用；只修改等待时间不会使已有会话或摘要失效，也不会终止已经开始的请求。旧配置未填写时按 60 分钟读取，无需重新输入密钥。连接测试与模型列表查询仍有较短的检查时限。

等待时限包含本次调用的排队、预填充、思考和正文输出；助手一轮可能含多次工具及模型调用，整轮也有相同的总时限。分段摘要每段单独计时，不代表整理全部聊天一定在一次时限内完成。底层通信不再用更短的首包、断流或固定五分钟限制提前结束模型生成；停止操作仍随时有效，超时后允许少量取消和状态核对的收尾时间。服务端或用户自己的代理仍可能有独立的更短限制。

更换模型先兼容续用；原生会话缺失、资料换代或无法容纳历史时，在下次提问时受控重建。长讨论有界分段整理，优先保留目标、决定、待办和证据归因；失败则保留问题供重试，不通过自动丢掉早期讨论继续回答。摘要有信息损失，不保证逐字记忆。仅修改普通聊天 revision 不会重建整个讨论。手动压缩遇到明显更小的模型窗口而无法装下时会提示失败，可在原会话提问时使用分段恢复流程。

已失效版本的助手建议及无法核验来源版本的升级前旧回复不会作为现行事实或指令回放，历史用户问题明确标为历史讨论；原文仍在界面可读。删除关系记忆不会从仍保留的微信原文中抹掉相同信息。原生自动/手动摘要的业务覆盖范围无法核验时，仅供回看；重建改用本地带可靠边界的讨论记录或摘要，避免重复或漏掉已覆盖段落。

账号数据库升级至 v8 前，在相同账号目录保存 `advisor.v7-backup.sqlite3`（版本较早时按原版本命名）。原消息与原生绑定保留，旧本地草稿仅迁移到升级前的最新讨论。应用重启后核对未完成的压缩，恢复任务标为中断，不自动重问或重压。手工备份不会被单会话删除一并移除。

本轮验收对应、复现命令和实测限制见[会话管理验证记录](advisor-session-validation.md)。
