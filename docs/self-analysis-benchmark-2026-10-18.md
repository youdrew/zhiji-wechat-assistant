# 自我剖析：中文聊天检索 benchmark（2026-10-18）

完成日期：2026-10-18。默认决定与实测结果如下，适用范围为本机 CPU FP32 和短消息合成集。

**决定：继续以 BGE-small-zh-v1.5 的关键词＋语义混合作为默认。** BGE-base 在本套短聊合成集上的排序质量略高，但收益未达到事先设定的更换门槛；Qwen 的小幅提升区间跨零，下载与运行成本更高。

## 实测结果

效果取 120 条 test 查询；延迟取全部 160 条查询×三轮。内存为独立的 16 条热查询期间，排序与编码**进程树合计 RSS 采样峰值**，包括 Windows 启动器和辅助进程，详见下文口径。延迟是编码与 RAM 排序分量相加估计。

## 为什么保留 small

| 比较（hybrid） | test nDCG@4 差值 | 配对 95% 区间 | 解释 |
| --- | ---: | --- | --- |
| BGE-base 混合 − BGE-small 混合 | +0.02225 | [+0.00006, +0.04343] | base 有小幅优势，但不足预设 +0.03；下界也非常接近零。 |
| Qwen3-0.6B 混合 − BGE-small 混合 | +0.01895 | [-0.01109, +0.04510] | 在 0.02 实用近似范围内，区间跨零。 |
| BGE-small 混合 − 关键词 | +0.04188 | [+0.01826, +0.06527] | 本集支持 small 混合优于词项基线。 |

三者都通过本机预设资源门槛。base 的混合 P95 约为 small 的 1.8 倍，Qwen 约 6.1 倍；编码进程峰值分别约 2.5 倍和 9.7 倍，下载资源分别约 4.3 倍和 25.3 倍。不能说 base 完全没有收益，但本轮没有达到用这些成本替换默认的条件。Qwen 也没有胜过 base 的可靠证据。

small 混合比 small 纯语义高 0.08401 nDCG@4，配对区间 [0.04273, 0.12420]。因此保留关键词路有本次实测依据。平均收益也不意味着每个场景都改善，下面的误例包含融合把正确样例挤出前四的情况。

## 输入表示、阈值与误例

| 混合模型 | raw 主测 nDCG@4 | 保留角色标签 nDCG@4 |

| BGE-small | 0.6928 | 0.6727 |

保留角色标签没有普遍提高本集分数，局部场景会改善；消融同时改变词项和语义输入，不能据此说角色标签本身伤害 embedding。不能在看完结果后改用消融分数选择默认。固定 0.2 阈值未过滤任何 test 正例，当前漏召回不能归咎于这个阈值。

以下为冻结标签下的典型问题，未标候选仍可能存在合理但未被发现的参考：

- **q0110，昵称方向**：需要本人停止叫对方“小胖”，多个方法却找出“本人拒绝被叫昵称”或“本人喜欢家人昵称”。三个 hybrid 前四均未命中；Qwen 纯语义第 4 位有强例，融合后首个强例降至第 10。角色和许可方向仍会混淆。
- **q0013，想去但须改时间**：三种纯语义前四都未命中，混入已确认赴约或等排班的样例；词项及 small/base 混合可命中，Qwen 混合的正确样例到第 5 位。相同活动主题不能替代改约意图。
- **q0068，安静区不能接通话**：small 混合命中；base 纯语义的强例在第 2/4 位，融合后移到第 7/5 位。Qwen 纯语义只有弱命中，说明 Hit 与 StrongHit 的区别确实有用。

分类切片多数只有一个家族、四条查询，仅作描述，不用小分组的退化区间宣称某模型赢下某类关系。下一步应优先检查角色/动作方向的重排能力，并在取得真人反馈后另建评测版本，而不是因本次误例调整 test 标签。

## 测什么

比较当前聊天情境能否找回值得参考的历史本人回复情境。关键词作为共同基线列一组，三种模型分别跑纯语义和混合检索，共七组；关键词排序也重复三轮测量。同一套语料、查询、相关性标签和过滤规则全程固定。

本轮不评价最后生成的回复是否像本人。模型只编码回复之前的聊天语境；历史本人回复不进入词项或语义相似度计算，只用于固定的回复去重及相关性复核。少量召回样例最终仍需由生成模型结合当前事实、本人偏好和关系边界判断。

## 数据与盲审

采用 40 类情境、160 条查询、480 条历史候选，全部为新编的中文合成聊天，不读取真实聊天或联系人。候选分到 60 个虚构联系人，每人八段历史；查询联系人使用另外的 ID，专测跨联系人参考，未验证同联系人加权的收益。每个查询检索全部 480 条候选，不按类别或家族缩小候选池。

覆盖改约、工作、金钱、安慰、感谢、道歉、不同关系的称呼、隐私许可、建议与玩笑边界、回复节奏、数字单位、地点纠正等。含反话、否定范围、emoji、中英夹杂，以及同主题但意愿相反的干扰样例。按家族划分 10 个 dev 家族/40 查询和 30 个 test 家族/120 查询；不拿 test 调模型指令或融合参数。

全部查询和来源由 AI 起草，一位未参与这些文本创作的 AI 复核者在不知道模型排名或分数的情况下逐条读审，并定向检查跨家族相关性。最终 797 条正相关中，597 条为强相关（2），200 条为部分相关（1），294 条跨家族。具体人物、日期、物品不同不自动降分；关键行动、立场或许可相反不能算相关。没有人类标注，亦未穷举 160×480＝76,800 对。

冻结时间为 `2026-10-18T09:14:17Z`，数据 SHA-256 为 `a5e0fbcd962b37d5321741e684aaafd79e39ea0ff92fa06f682c0abaa00d9013`。结果出现后不修改本版标签。数据、数据卡、独立审查记录和源码哈希见 [benchmark 目录](../benchmarks/self-analysis-chat/README.md)。

## 输入、排序与指标

主测使用当前回复建议的实际输入形式：查询按消息顺序拼正文，去掉行首的本人/对方标签；候选保留建库时的角色标签。另做保留查询角色标签的消融，使用同一套候选和标签，但不参与默认模型选择。这样能区分模型变化与输入信息变化。

词项和混合检索直接调用当前产品的 `self_retrieval.py`：单字权重 0.22，双字/英文词权重 1，词项 SQL 最多预选 500 条；两路各取 64 条，RRF 常数 60，保留当前精确覆盖、联系人和场景小权重。语义路独立扫描，不受词项预选限制。三模型沿用 cosine ≥ 0.2，并单独报告该阈值过滤正例的比例，避免把不同分数尺度的影响都归因于模型能力。

排序后保留原先的前 16 条核查窗口、每联系人最多两条、回复归一化去重和时间/来源过滤。冻结合成样例的原文核查恒通过，不访问运行数据库或真实消息。主指标取前四条，与回复建议最多用四个样例一致；@10 只作诊断，不是线上展示数量。

- **nDCG@4**：考虑强弱相关和先后顺序，作为主选择指标，越高越好。
- **Recall@4**：前四条覆盖全部已标相关样例的比例。相关样例超过四条时，最高值也可能小于 1。
- **Hit@4 / StrongHit@4**：前四条是否至少有一条相关/强相关；不能称为最终回复准确率。
- 完整结果还含 @1/@10、MRR、强相关召回、分类切片、少于四条结果比例及联系人限制下可行召回上限。

差异区间采用按情境家族配对的 10,000 次 bootstrap，避免把同一家族的四个变体当四个独立场景。区间未作多重比较校正，只描述有限合成样本的抽样差异，不覆盖 AI 标注偏差或真实用户分布变化。

## 性能口径与事先决策规则

CPU FP32 ONNX，ORT 两线程、NumPy/BLAS 两线程，最多 512 tokens，候选 batch=8，查询 batch=1。BGE 使用官方中文查询指令和 CLS 池化，Qwen 使用固定英文聊天情境检索指令和最后有效 token 池化，均 L2 归一化。三模型各启动三个新进程，轮换模型顺序，每轮用相同随机查询顺序。

延迟主表是独立编码 IPC 测量与排序测量按查询配对相加的估计，不是完整应用请求的实测端到端延迟。它不含 Core HTTP、队列等待、原消息核查和最终生成。加载是进程冷启动，未清空操作系统文件缓存；建库吞吐只算已提取语境的编码，不算历史读取、样本提取或完整数据库落盘。测量时使用共享开发机，保留环境及三轮差异。

主表排序使用预载入内存的冻结向量矩阵计算相似度，再注入生产排序器，没有包含线上 SQLite 语义分页、BLOB 读取和逐块向量归一化扫描。该成本另见扩容实验，没有直接加回延迟主表；知识库扩大后不能沿用主表数值估计完整响应时间。

内存分别报告独立编码器进程的 Windows OS 工作集峰值，以及七种方式在同一组 16 个热查询期间，同时存活的排序/编码子进程 RSS 合计采样峰值。后一项包括 Python/NumPy、冻结数据及向量等测量程序开销，不含协调进程或完整应用，共享页可能重复计算；private 内存为 10ms 采样峰值。

事先固定的模型选择规则是比较 **hybrid 的 test nDCG@4**：差距在 0.02 内视为实用近似，优先低成本；更重的替换至少需提升 0.03、配对 95% 区间下界大于 0、Hit@4 下降不超过 0.02。还需满足本机 all 查询三轮分量相加的 P95 ≤500ms、编码器峰值 ≤4GiB、资源下载 ≤3GiB。证据不足则保留现有默认，不根据结果改阈值或权重。

另用重复的冻结向量构造 480/5,000/50,000 条 SQLite 负载，检查分页扫描、两秒预算和存储开销。仅泛化生产扫描器固定 512 维的字节长度校验，其余分页/过滤不变；产品本身没有因此新增 768/1024 维支持。这是扩容成本实验，不能证明五万条独立聊天的召回质量。

## 适用范围

这是一次有冻结协议、可复跑脚本和逐查询证据的本机合成集评测。样本主要是 2–4 条短消息，canonical 查询最长 105 字、候选前文最长 74 字，比真实长历史规整。未检验长上下文质量、媒体理解、低配电脑、量化、GPU、真实使用满意度或人格风格还原。

未标注的候选按 0 评分，定向跨情境盲审仍可能漏掉合理参考；不同 AI 作者也可能共享表达偏好。应结合强相关命中、误例与区间解释分数。`annotationRationale` 包含起草解释；最终相关等级以冻结的 `qrels` 和盲审裁定记录为准。
