# 聊天助手消息排队

Know Your Friends，2026-10-16。新增代码沿用 Apache-2.0。

## 使用方式

聊天助手回答期间，可以继续输入并点击“加入队列”。输入区上方的“待处理”列表显示等待中的问题，按提交顺序逐条执行。每条开始时接上之前已完成的回答；等待中的问题不会提前进入正在生成的这一轮。

- 等待中的消息可以编辑正文或移除；已经开始处理的消息使用正常的停止操作。
- “暂停队列”只暂停后续问题，不中断正在进行的回答。“继续队列”恢复顺序处理。
- 点击“停止生成”、生成失败或结果状态无法确认时，后续队列暂停，内容保留。可以先重试失败的回答，再继续队列，也可以直接继续处理后续问题。
- 切换联系人、助手、讨论或收起面板，不停止后台队列。每个账号、联系人、助手和讨论的队列相互隔离。
- 退出应用后再次打开，未开始的问题仍在列表中，先保持暂停，点击继续后才运行。已经开始但被中断的问题保留在原讨论中，通过原问题的重试入口处理，不自动重复发送。
- 确认删除一段讨论，会同时删除它未发送的队列；不会删除微信聊天原文或其他讨论。

发送和停止是两个独立按钮。只有后台确认接收成功，才清空当时提交的输入；发送途中继续输入的新草稿保留。编辑队列使用独立编辑框，不覆盖当前草稿。已经选中的 `@好友` 和深度思考选项随每条问题保存，不随之后切换界面改变。队列编辑仅修改正文，保留该条提交时的好友引用和思考选项。

排队适用于“分析完后再给我三个回复”等后续提问。它不改变当前回答，也不实现生成中的即时插话。如果要马上纠正当前要求，仍需停止当前回答后重新提问。

`/new`、`/sessions`、`/compact` 等命令仍按原来的界面操作处理，不进入消息队列。新建讨论不会搬走原讨论的队列；手动压缩不能与同一讨论的回答并行。

## 持久化与执行约束

队列由 `kyf.advisor` 后台管理，不依赖面板持续打开。待处理记录与讨论正文、输入草稿分开保存；只有实际开始执行的问题才成为讨论的一轮。队列只保存本机，沿用账号数据库的生命周期和清理规则。

插件账号数据库升级到 v9 前会按原有迁移机制保存备份，例如 v8 对应同目录中的 `advisor.v8-backup.sqlite3`。原有讨论、草稿和运行记录保留。完成且没有待处理消息的讨论，在重启后仍可正常发送；手动暂停的状态继续保留。

入队请求有稳定编号，重试同一次提交不会重复排队，即使之前的条目已经被编辑、移除或执行。编辑、移除和开始执行使用同一套互斥与版本检查；其他窗口已更新或后台已开始时，旧操作不能覆盖新状态。

实际执行时重新检查账号、助手和资料访问范围，读取当时可用的聊天及关系资料。排队不增加权限，不触发微信发送；未发送的问题不参与当前轮的模型输入。遇到配置、权限或资料失效，保留尚未开始的问题并暂停，修复后由用户继续。

## 验收重点

使用合成账号、聊天和模型验证以下行为，不使用真实用户资料：

1. 连续提交多条问题，后台按顺序执行，同一讨论不并发，不同讨论相互独立。
2. 第一条未完成时，后续问题不进入它的讨论上下文；下一条能接续上一条结果。
3. 等待项可编辑、移除；版本冲突和刚刚开始执行的条目不会被错误覆盖。
4. 停止、失败和手动暂停都保留队列；继续后不重复已开始的问题。
5. 切换讨论、关闭面板及程序重启后，内容与所属讨论保持一致。
6. 断网重试、重复点击及迟到响应不会重复入队，也不会清空新的草稿或其他讨论的输入。
7. `@好友`、思考模式、只读历史、压缩、删除及账号清理沿用原有隔离规则。

真实模型的回答质量和延迟不属于合成测试能证明的范围。
