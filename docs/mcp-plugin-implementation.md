## 1. 目标和已确认决定

让运行在同一台 Windows 电脑上的外部 AI 客户端，通过 MCP 使用知己微信助手的资料与业务能力。知己主窗口未启动时，MCP 调用仍可按需拉起无界面的 Core；无需用户先打开主窗口。远程云端客户端直接连入本机不属于本期范围。本机 AI 客户端可能把工具返回的私人资料交给其配置的模型服务；聊天内容还可能被恶意联系人用来诱导外部客户端调用工具（提示注入）。这类说明集中放在专门的安全说明页展示，不在设置页或配对界面散落披露。

| 事项 | 已确认行为 |
| --- | --- |
| 授权对象 | 每个已配对的本机 MCP 客户端有独立、可撤销的持久授权；未配对的进程不能因 MCP 插件已安装而读取资料。 |
| 默认模式 | 新客户端的授权模式为“完整授权”：覆盖本安装下所有已保存微信账号、当前与以后新增的联系人，以及本方案列出的客户端业务和管理能力。调用须明确指定账号；授权持续到用户修改或撤销。 |
| 另一模式 | “逐联系人授权”按账号和联系人逐个开启。已开启联系人拥有该联系人范围内的全部业务能力，不含微信发送；新账号、新联系人不自动加入。 |
| 全局管理 | 完整模式可调用应用管理能力。逐联系人模式有独立“全局管理”开关，默认关闭；账号级汇总和管理不能借一个已授权联系人绕过范围。 |
| 知己关闭 | 外部客户端可按需启动/复用无界面 Core。知己主窗口关闭不应结束仍被 MCP 使用的 Core。 |
| 微信关闭 | 已保存的资料仍可按明确账号离线读取；人工资料可在版本核验下修改，基于缓存的分析必须标示数据时间与覆盖范围。实时微信读取、媒体原件获取及发送按实际依赖返回不可用。 |
| 密钥 | MCP 可修改、测试模型配置，但不得返回已保存模型密钥明文。 |
| 高影响删除 | 删除整个账号或清空本机数据，每次都须经独立的本机确认界面；未确认、超时或无交互桌面时不执行。普通记忆编辑和删除遵守授权及版本校验，不逐次弹确认。 |
| 授权控制 | 连接配置、授权模式、逐联系人名单和“全局管理”只能在知己的 MCP 插件设置界面更改；MCP 工具不能修改自己的授权或取得 Core/桌面控制令牌。 |

“完整授权”是已配对客户端的默认**授权模式**，并非开放无身份验证的本机端口。新工具若加入已声明的能力目录，完整模式按定义覆盖它；涉及新型外部副作用时，发布说明和设置页须清楚展示其归属。使用者可以随时切换模式或撤销客户端。

## 2. 现状、缺口和分层

现有聊天助手已有仅供自身使用的网页搜索 MCP，位于 [web-tools.ts](../plugins/kyf.advisor/engine/web-tools.ts)；它只提供网页搜索与网页读取，不是对外的知己资料入口。当前进程和资料边界见[插件架构](plugin-architecture.md)。

| 现有机制 | 本方案需要补齐 |
| --- | --- |
| [无界面启动器](../scripts/start-real-client.py) 支持 `--no-open`；Core 由 [real_http.py](../bridge/real_http.py) 提供回环服务。 | 本机 MCP stdio 入口按需启动/复用 Core，经现有回环 HTTP 的专用认证路由访问（每连接短时令牌），并与 GUI 共享运行租约。 |
| GUI 退出时的[当前逻辑](../scripts/real-client-shell.cjs)会请求停止安装目录下的 Bridge。 | 若 MCP 连接或任务持有租约，GUI 退出只释放 GUI 租约并提示一次后台仍在运行；最后一个租约结束且空闲期到达后再停 Core。 |
| [Core 资料服务](../bridge/core_services.py)拥有账号、历史、人工资料和插件监督；[插件 API](../bridge/plugin_api.py)的令牌属于受监督插件。 | Core 增加专用 MCP 能力代理和认证入口（复用回环 HTTP，不引入新 IPC 机制）；不得把插件令牌、桌面控制令牌、普通 HTTP 路由或任意插件 RPC 透传给 MCP。 |
| [人工资料入口](../bridge/friend_service.py)和现有账号检查依赖实时微信身份；每账号数据库已有本机持久资料。 | 新增显式“已保存账号”离线作用域，读取缓存时携带来源、覆盖范围和新鲜度；实时操作仍核对当前微信账号。 |

目标调用路径：

```text
本机 AI 客户端
  └─ stdio → MCP 启动器/协议适配器
                └─ 回环 HTTP 专用认证路由 → Core 能力代理
                                     ├─ 已保存账号与微信资料服务
                                     ├─ 人工资料与插件业务服务
                                     ├─ 统一模型网关/任务管理
                                     └─ 受控后台发送与本机确认
知己 MCP 插件设置页 ────────→ Core 授权存储与调用记录
```

MCP 插件承担连接和授权的产品入口；运行时适配器是可以被本机 AI 客户端启动的独立进程。当前插件设置 schema 只有有限的静态字段，客户端×账号×联系人矩阵应使用 MCP 专属管理页，而不是塞入通用字段列表。设置页可从“设置 → 插件 → MCP”进入；另设独立的“安全与数据说明”页，集中承载外部模型数据流向、提示注入风险等说明，设置页和配对流程只保留一个入口链接，不在页面内散落披露文字。权限判断始终由 Core 执行，不能只在插件页面隐藏按钮。

## 3. 进程生命周期与离线资料

### 3.1 无界面 Core

1. stdio 适配器识别安装实例：安装位置由本机 AI 客户端配置中的显式路径参数传入，不做注册表或固定路径探测；通过现有启动器的安装 ID、端口占用和 PID 创建时间检查按需启动或复用**同一实例** Core。并发冷启动以安装目录锁文件互斥，未取得锁的一方等待后重试复用。正常启动不打开 Electron 主窗口。
2. Core 为 GUI、每个 MCP 连接和继续执行的任务分别持有租约。租约有进程死亡回收和有界空闲退出（空闲期默认值在实现时明确、可配置）；GUI 退出不得停掉 MCP 活动连接，MCP 退出也不得停掉 GUI 正在使用的 Core。GUI 退出时若仍有 MCP 租约或活动连接，提示一次“知己仍在后台运行”；后台状态与活动连接数显示在 MCP 设置页。
3. 停机、应用更新和账号清理先阻止新请求，再等待/取消在途操作，并按现有 request lease 与任务代次规则排水。迟到结果不得在重新启动或切号后写回。
4. 账号清理后的“禁止自动恢复”闩锁必须对 MCP 自动拉起同样生效。现有 `--no-open` 属于显式启动，会清除该闩锁；实现时应增加区分自动 MCP 启动的路径，不直接把 `--no-open` 当无条件恢复命令。
5. 发送执行器与全量删除确认窗作为按需启动的后台组件，随操作持有独立租约；执行器租约计入 Core 的“最后一个租约”判定，执行中不因空闲期停机。它们不能依赖知己主窗口存在。若无法启动执行器或没有可交互桌面，相应动作明确报不可用，普通资料读取仍可继续。
6. 运行时和新适配器进入安装包的显式 staging 清单；源码启动、干净 staging 和安装版分别验收。

### 3.2 两种资料来源状态

| 状态 | MCP 能力 |
| --- | --- |
| 知己主窗口关闭、微信运行并登录 | 后台 Core 可读取当前微信账号的实时资料；其他已保存账号仍按缓存处理。发送只对当前已登录且可核验的账号开放。 |
| 微信未运行、未登录或资料读取未就绪 | 按调用指定的已保存账号读聊天投影、关系记忆和已保存插件结果；允许带版本校验的人工资料编辑。不能把缓存回答说成实时完整历史。 |
| 模型服务不可用 | 已保存资料仍可读写；需要模型的分析与助手任务返回明确的模型不可用状态，不转用其他配置。 |

离线账号由本机已保存账号目录识别，不用“最近在线账号”代替调用参数。每个查询结果至少标示 `accountId`、`sourceMode`（live/cached）、资料时间、覆盖状态和来源版本；缓存缺口、媒体缺失和证据失效分别报告。微信重登、数据根切换或来源指纹变化时，使旧消息游标与发送证明失效；逐联系人授权需要绑定安装/数据根身份，不能把旧授权悄悄用在另一份同名账号资料上。

## 4. 授权模型与设置页

### 4.1 客户端档案

用户在 MCP 插件设置页创建/配对客户端档案。每个档案包含随机凭据的校验值、展示名、启停状态、授权模式、授权版本、逐联系人名单、全局管理开关及最近使用时间。展示名和 MCP 协议中的 `clientInfo.name` 只用于界面显示，不作为身份凭据。客户端配置不写真实聊天、联系人或密钥；运行秘密放在本机受保护的凭据存储，Core 只保存必要的校验材料。撤销或禁用档案立即拒绝后续调用并使在途未提交操作失效；重新生成凭据使旧凭据立即失效。

同一 Windows 用户下的恶意进程原则上可能读取该用户可访问的本机文件；本权限系统约束受支持的 MCP 调用和误用，不宣称提供操作系统级恶意程序隔离。外部 AI 客户端收到的内容可能经它自己的模型服务离开本机；本段与数据流向、提示注入风险的完整说明统一放在专门的安全说明页，配对流程链接到该页。

### 4.2 两种模式

- **完整授权**：对本安装与当前数据根中的所有已保存账号和联系人生效，包含以后新增者；开放全部已登记业务能力及应用管理能力。已保存密钥明文读取和 MCP 自身授权修改是固定排除项；全量账号删除/本机数据清空须本机确认。
- **逐联系人授权**：以 `(安装/数据根, accountId, 稳定联系人 ID)` 为键，只有勾选者可进行联系人范围的读、写、分析和发送。添加新联系人默认不授权；改备注名不改变授权；删除/移除联系人时停止新访问。跨好友助手提问须对每位参与者逐一核验。外部聊天导入中尚未绑定微信的联系人使用独立主体类型，不能仅按显示名碰撞到微信联系人。
- **逐联系人模式的全局管理**：单独开关，初始关闭。开启后可管理模型、插件和应用设置，但不扩大联系人资料权限。账号级自我剖析、全局用量及其他可能包含未授权联系人内容的现成汇总，在逐联系人模式一律不返回；只有业务方法能从已授权联系人集合重新计算且标明 `scope=authorized_contacts` 时才提供子集结果。不能先读取全量结果再在输出端遮盖姓名。删除整个账号和清空本机数据仍需独立确认。

每次工具调用先验证档案和权限；读取完成返回前、写入事务提交前、模型任务开始前及发送提交前再次核对授权版本、账号与资料来源。切换模式或撤销联系人会提升授权版本，旧游标、临时文件、排队任务和一次性确认失效。已经发给外部模型的内容无法收回，撤销只阻止后续提供。

设置页应提供：总启停、客户端列表与配对/撤销、模式切换、按账号的联系人选择、全局管理、后台 Core 状态与活动连接数、最近调用记录、“立即断开所有连接”和安全说明页入口。调用记录保存时间、客户端、账号/联系人、工具、结果及用量，不记录聊天正文、模型密钥或发送正文。

### 4.3 授权判断与存储

授权判断在 Core 的同一入口进行，输入为客户端 ID、授权版本、安装/数据根身份、`accountId`、主体类型、稳定主体 ID 和业务动作。完整模式允许已登记动作；逐联系人模式要求**本次请求涉及的每个联系人**均在名单中，不能用一个联系人授权获取跨联系人结果。开启“全局管理”只增加应用管理动作，不改变前述主体检查。客户端声称的名称、工具参数中的昵称以及缓存文件路径都不能作为授权依据。

授权资料建议放在 `.local/core/mcp/` 下的独立事务存储，至少有以下记录；迁移和备份遵守现有本机数据规则：

| 记录 | 必需字段与约束 |
| --- | --- |
| 客户端档案 | 不可复用的 `clientId`、名称、启停、模式、全局管理位、授权版本、凭据校验材料、创建与最近使用时间。 |
| 联系人授权 | `clientId`、安装/数据根指纹、`accountId`、主体类型、稳定主体 ID；唯一键覆盖这些字段。 |
| 请求去重 | `clientId`、`requestId`、动作、参数哈希、状态、创建与过期时间；同 ID 不同参数拒绝。发送请求的去重记录必须先于外部提交持久化。 |
| 调用记录 | 时间、客户端、动作、账号/主体 ID、结果码和用量；限制数量与保存期，不保存正文或明文密钥。 |

凭据由本机设置页生成并交给对应客户端配置，展示一次后不回显；不要作为命令行参数写入进程列表、普通日志或 Git。Core 只保留校验材料，运行时秘密使用 Windows 用户保护机制存放。由于多个本机 AI 客户端通常同属一个 Windows 用户，此设计提供明确的客户端配置边界与撤销能力，不将它描述成对同用户恶意进程的强隔离。

## 5. MCP 协议与能力目录

本期使用客户端启动的 stdio 传输；标准输出只写 MCP 消息，诊断走标准错误且不得包含私人正文或凭据。协议版本和 SDK 在实现前对目标本机客户端做兼容测试并固定；现有内部网页 MCP 的简化服务不作为通用知己服务复制。首期以 **Tools** 承载调用，资源与提示模板仅在确定需要时补充；能力目录或档案权限变化时发送 `notifications/tools/list_changed`，避免客户端缓存过期工具列表。工具名、输入和输出使用版本化契约；`tools/list` 按档案的能力展示，具体联系人仍在每次调用时核验。[stdio 规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio) · [工具规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)

以下是目标能力目录；名称为拟定契约，实施时可在不改变权限语义的前提下细分。任何一个工具都只能调用经过明确登记的 Core/插件业务方法，不提供通用 HTTP、任意 SQL、任意文件、命令执行或任意 `plugin RPC` 工具。

| 能力族 | 拟定工具或操作 | 作用域与前提 |
| --- | --- | --- |
| 账号与联系人 | `zhiji_list_accounts`、`zhiji_find_contacts`、`zhiji_get_contact` | 完整模式可列已保存账号；逐联系人模式只列有授权主体的账号与联系人。 |
| 聊天与媒体 | `zhiji_search_messages`、`zhiji_get_message_context`、`zhiji_get_media` | 按账号、联系人和来源版本分页；媒体仅返回实际可用的受控内容，不暴露本机任意路径。 |
| 人工资料 | `zhiji_list_memories`、`zhiji_get_memory_evidence`、`zhiji_create_memory`、`zhiji_update_memory`、`zhiji_confirm_memory`、`zhiji_delete_memory`，以及联系目标、自身资料、观察的读取和修改 | 区分已确认、待确认、用户观察；修改使用现有版本条件和请求幂等键。账号级自身资料受账号级权限控制。 |
| 分析任务 | 开始/停止/查询好友分析、逐句分析、回复建议及自我剖析，读取已保存结果；修改和撤销自我剖析时间线 | 返回任务 ID，长任务按任务状态轮询；全账号汇总须遵守逐联系人模式的聚合边界。时间线修改按版本校验，和界面共用一份撤销记录。 |
| 聊天助手 | 管理助手模板与技能、讨论、草稿、排队消息；提交提问、停止、读取结果 | @好友参与者逐个授权；模型调用仍经过 Core 网关，不给 MCP 客户端模型密钥。 |
| 外部聊天导入 | 列出/管理导入素材、转录、核对记录与结果 | 未绑定微信的外部联系人单独授权；本机文件输入仍须显式选择或受限路径授权。 |
| 应用管理 | 查询/修改模型设置、插件状态、用量与资料管理；删除账号、清空数据 | 完整模式开放；逐联系人模式受全局管理开关控制。密钥只接受设置/替换，不提供明文读取；高影响删除须本机确认。 |

通用输入采用明确的 `accountId`、主体类型及稳定 ID；修改类带 `requestId` 和预期版本。响应返回操作范围、状态、资料来源/时间/覆盖范围、引用 ID 与分页游标，错误使用稳定代码（如未授权、账号未就绪、缓存不完整、版本冲突、确认过期、发送结果未知）。每次返回有界；模型生成和大量导入以任务 ID 查询进度。工具输出中的聊天文字、网页文字和导入素材都是不可信数据，不能改变授权或工具说明。

首批契约至少固定如下形状，后续工具沿用同一作用域与错误约定：

| 工具 | 关键输入 | 关键输出与限制 |
| --- | --- | --- |
| `zhiji_ping` | 无 | 返回服务与档案权限摘要，用于连通性和互不借权验证；不读取任何资料。 |
| `zhiji_list_accounts` | 无账号参数 | 仅返回当前客户端可见的账号 ID、展示信息和缓存/在线状态；逐联系人模式不列无授权主体的账号。 |
| `zhiji_search_messages` | `accountId`、稳定联系人 ID、查询条件、页大小、游标 | 有界消息摘要与引用、来源版本、覆盖范围；游标绑定客户端、账号、主体、授权版本和来源指纹。 |
| `zhiji_list_memories` | `accountId`、稳定联系人 ID、状态筛选、页大小、游标 | 记忆、证据引用和版本；待确认/已确认状态明确，不混写聊天事实。 |
| `zhiji_update_memory` | `accountId`、稳定联系人 ID、记忆 ID、预期版本、变更字段、`requestId` | 新版本或冲突；Core 在提交前重新验权和验版本。 |

读取游标、任务 ID、媒体句柄和删除确认意图均与客户端档案及授权版本绑定；不能把一个客户端取得的引用交给另一客户端继续读取。媒体访问通过受控句柄或有界内容返回，不暴露通用磁盘路径；内嵌内容设尺寸与格式上限，超限转码或返回句柄与明确错误，上限写入工具契约。所有写工具都要说明可修改的具体字段，拒绝额外字段；以更新为目的的 `requestId` 保证重试不会重复产生副作用。

## 6. 免费版能力边界

免费版不提供微信发送能力，MCP 工具目录、能力声明及 stdio 适配器中均不包含发送工具。联系人授权只约束本版已提供的数据、分析与管理能力，不能启用未交付的 Pro 插件。后续微信发送及双机 Pro 见[版本规划](editions-and-wechat-node-requirements.md)。

## 7. 高影响删除的本机确认

删除整个账号、清空本机数据及等价的全量清除先返回待确认意图。独立确认界面展示客户端、操作、账号/数据范围和不可恢复影响，不要求知己主窗口已打开。确认凭证一次性、短时有效，绑定调用参数哈希、客户端、授权版本和目标账号；确认前再次核对账号和当前数据根。无可交互桌面、超时、拒绝、参数变化或授权变化均不执行。执行前按现有账号清理流程阻止新任务并排水；执行后撤销相关游标、授权主体和缓存。

普通记忆删除、助手会话删除、导入批次管理等既有业务操作不套用全量清除的确认，但仍要求对应权限、预期版本与幂等处理。MCP 本身的授权和客户端凭据只由本机设置界面管理。

## 8. 建议实施顺序与验收

建议的代码落点如下，创建文件前先按现有模块边界核对命名：MCP 设置 UI（含安全与数据说明页）位于新插件 `plugins/kyf.mcp/`；Core 的客户端档案、作用域校验和工具分发位于 `bridge/` 的专用模块；stdio 入口与启动/租约协调位于 `scripts/` 和 Core 运行时。离线作用域要改造 [账号数据库](../bridge/core_account_db.py)、[人工资料服务](../bridge/friend_service.py)及相关资料读取入口。GUI 退出行为在[主窗口宿主](../scripts/real-client-shell.cjs)调整；新文件加入[打包清单](../scripts/stage-real-client.py)。每个插件业务能力先建立明确 Core 方法映射，再向 MCP 登记，禁止直接把现有泛用插件 RPC 暴露为工具。

| 阶段 | 交付内容 | 通过条件 |
| --- | --- | --- |
| 1. 契约和授权 | MCP 能力目录、`zhiji_ping` 探针工具、专用 Core 能力代理、档案/模式/授权版本存储、MCP 设置管理页与安全说明页 | 两个客户端互不借权（以探针验证）；完整/逐联系人跨两个账号的范围正确；撤销立即生效；密钥与 MCP 自身设置无法由工具读取/修改。 |
| 2. 无界面运行 | stdio 适配器、Core 共享租约、自动启动闩锁、离线账号作用域、GUI 退出提示与设置页后台状态 | GUI 未启动可调用；GUI 关闭不中断 MCP 且退出时给出后台运行提示；最后租约退出可安全清理；清号后不被 MCP 自动恢复；微信离线只返回明确标记的缓存。 |
| 3a. 只读资料 | 有界聊天、记忆、媒体读取 | 无账号/好友串读；逐联系人模式不泄漏跨好友汇总或未授权联系人资料；游标与授权版本绑定生效。 |
| 3b. 写入与业务任务 | 版本化人工资料修改，分析、助手、导入的受控业务工具 | @好友参与者逐个授权；逐联系人模式不泄漏跨好友汇总与外部联系人资料；重复写请求不重复生效；任务取消和迟到结果安全。 |
| 5. 全局管理与确认 | 应用管理工具、全量删除的独立确认、调用记录 | 无确认不能删除账号/清空数据；确认绑定具体意图且只用一次；模型设置可改但密钥不回显；逐联系人全局管理默认关闭。 |
| 6. 打包与兼容 | SDK/协议版本兼容、显式 staging、干净安装包及升级验证 | 指定本机 AI 客户端可稳定连接；stdout 无杂项日志；安装版能无界面启动；禁用/卸载 MCP 后无残留可调用入口。 |

定向验收至少覆盖：两个账号、两个已授权和一个未授权联系人；完整模式新账号/新联系人自动纳入、逐联系人模式不自动纳入；数据根切换；微信运行/退出；GUI 与 MCP 同时使用及先后退出；撤权与读取/写入/发送并发；重复请求和超时；跨好友助手与自我剖析；群聊拒发；发送结果未知；清除确认竞态；模型密钥、聊天正文和凭据不进入日志或 Git。真实发送只在明确的受控验收环境执行，不把合成测试等同于微信端可用性。
