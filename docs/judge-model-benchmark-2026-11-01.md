# 判断模型实测：2026-11-01 冒烟与 2026-11-02 复核

状态：仅完成合成样本冒烟，真实聊天窗口对照和筛选漏检率验收尚未开始。2026-11-02 的复核撤回了首轮“Julia-1 GGUF 中文词表损坏”和“所有候选无法运行”的结论。

## 已验证的结论

| 候选 | 运行情况 | 当前窗口筛选质量 |
| --- | --- | --- |
| Julia-1 Q8 / BF16 | b12032 的 `/v1/systemone` 可运行，中文可正确输入和解码 | 现有 10 个合成样本和判据表现不足，不能开启跳过 |
| Laya multilingual Q8 | 本机文件加载失败，日志报告不支持 `ggmlc` 架构 | 未测，不应推断模型本身的中文能力 |
| Qwen3.5-0.8B Q4 | 关闭 thinking 并提供足够输出预算后，10/10 次返回合法 JSON | 本轮判据仅答对 5/10，不能开启跳过 |
| laya-zh-v2 | 本机没有可用 GGUF | 未测 |

可以继续实现判断接口和本地运行基础设施，保留 Julia-1 作为原定本地候选进行影子评估。运行成功不代表筛选质量合格；当前不得自动跳过提取窗口，也没有依据要求用户先选择重新转换或等待上游修复。

## 首轮测试的问题与更正

1. **中文 tokenizer 根因误判。** 首轮命令行请求出现问号，却据此断言上游转换损坏。复核通过 ASCII JSON 转义发送、UTF-8 解码，`今` 得到 token `73623`，解码为 ` 今`；`今天早上去爬山了` 也正确往返。前导空格同样出现在英文 `hello world`，不能当作中文词表损坏。首轮“今 → 1654 → ?”的证据不足，不应提交上游缺陷报告。
2. **长度标注错误。** 首轮 `("今天下班……" * 80)[:6000]` 实际只有 **3280 字符**，不能将其 2504 tokens 和约 1.1 秒耗时写成 6000 字的结果。
3. **choice 统计键错误。** `choice_scan.py` 始终取 `("有", "是", "true")[0]`，导致“是/否”和“true/false”两组找不到键而被统计为概率 0。“全零”不是模型塌缩的证据。
4. **Qwen 测试没有关闭 thinking。** 只给 1 或 30 个输出 token，未检查 reasoning 和 finish reason，就把空 `content` 当成生成失败。此外缺失候选的 logprob 被设成 0，且同类 logprob 直接相加，不能据此估算“有/无”概率。
5. **准确率与漏检率尚未验收。** 10 个合成样本只能发现明显问题；“躺床刷手机”等负样本本身也可能有事件，标签需要对齐真实提取标准。不能从这组结果推断真实聊天的可用阈值。

## 复核方法和结果

使用已有权重及 llama.cpp `b12032` CPU 版，不新增下载。8 线程，`-c 8192 -ub 8192 -b 8192 -np 1`，只监听回环地址，每次使用内存中的随机 API key。测试结束自动终止子进程。样本全部为合成文本，不读真实聊天或用户模型配置。

本机复核脚本和原始结果位于 `.local/tmp/judge-phase0/review/`，不进入 Git：`recheck.py`、`q8-results.json`、`bf16-results.json`、`qwen-results.json`、`english-criteria-results.json`、`token-budget-results.json` 和 `asset-checks.json`。

### Julia-1

同一组 10 样本，以 0.5 为临时分类阈值，仅用于排查：

| 写法 | Q8 错误数 | BF16 错误数 |
| --- | --- | --- |
| 原详细 `noul` 判据 | 5/10 | 5/10 |
| `choice`：有 / 无 | 6/10 | 7/10 |
| `choice`：是 / 否 | 6/10 | 6/10 |
| `choice`：true / false（中文说明） | 5/10 | 5/10 |

补试英文说明、中文 state 的 3 组写法，仍有 6–7/10 错误。以上结果说明本轮判据与模型组合不足以用于筛选，不定位其原因，也不证明其他任务不可用。

原详细 `noul` 判据下，Q8 短样本请求中位约 29 ms，BF16 约 32 ms。修正后真正 **6000 字符**的重复中文事件样例连同问题使用 **4316 input tokens**；Q8 约 **2.30 秒**，BF16 约 **2.14 秒**（各单次观测，非性能分位数）。首次加载不计入上述耗时。

6000 字符不是 token 预算保证：另一个包含 6000 个不同中日韩表意字符的合成字符串，仅 state 的 `/tokenize` 就得到 **11778 tokens**，超过 8192 上下文。因此不能沿用“6000 字一定放得下”的首轮结论；实现必须正确处理实际上下文超限，不能静默截断后当作完整窗口的判断。

`-ub` 必须覆盖实际整题输入；该类模型按整个 prompt 一次处理。`choice`、`score` 和 `noul` 都应提供 `instructions`。服务返回的 `score` 是等级索引的加权期望，可以为小数。

### Qwen 对照

设置 `enable_thinking: false`、`chat_template_kwargs: {"enable_thinking": false}`、`max_tokens: 128`、`response_format: {"type": "json_object"}`。10 次均以 `finish_reason: "stop"` 返回可解析的 `{"noul": ...}`，每题约 0.19–0.30 秒，当前判据分类正确 5/10。

这验证了普通生成模型的 JSON 路线能够运行，不代表其自报概率经过校准，也不支持直接用 Julia 的阈值。该对照不改变产品默认本地模型。

二者都与需求文档固定值一致。哈希一致只能证明文件相同，不能证明模型质量或转换正确。

## 后续验收

- 阶段 2 可用模拟 `/v1/systemone` 和普通模型结构化输出分别验证，无须等待更换模型。
- 阶段 3 验证下载、校验、进程生命周期、格式和耗时；质量未达标时不自动启用筛选。长窗口可能超过原定 2 秒门槛，应保留行内慢速状态。

## 2026-11-02 实施后的隔离集成验收

使用临时目录的模型配置、已有且校验一致的公开 Julia-1 Q8 权重和固定运行时，实际走通了 `JudgeService.prepare` → 私有控制管道 → Node 网关 → llama-server 自测 → 内置模型登记。短合成样例自测平均约 **16.5 ms/题**，不包含加载，**不代表 6000 字窗口的时延**。`qualityVerified` 仍为 `false`，没有自动分配判断用途或开启窗口跳过。

随后只在这份隔离配置中分配判断用途，用合成执行令牌经网关请求 `/v1/systemone`：响应模型名为 `julia-1`，没有本机文件路径；该次用量为 **input 26 / output 0**，实际产生一条调用记录。公开服务字典不含 API key 或 `local` 启动配置。

删除后权重和用途分配已清除，llama-server 及其控制台子进程结束。网关关闭时退出码为 0，属于该网关的全部子进程数量归零。过程中未读取真实聊天，也未修改用户的模型配置。原始脚本和结果在本机 `review/integration.py`、`review/integration-results.json`；这是运行与生命周期验收，筛选准确度仍未达标。
