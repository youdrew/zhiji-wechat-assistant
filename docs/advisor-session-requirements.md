# 聊天助手上下文与历史会话需求

产品：知己微信助手 · Zhiji WeChat Assistant。需求版本：v0.3（2026-10-10）。状态更新：2026-11-02，已在本地 `dev` 实现。品牌名称按[当前约定](branding.md)更新。

当前状态：上下文可视化、手动与自动压缩、历史讨论、新建与删除讨论、草稿隔离及受控恢复均已有实现和验证记录，见[会话管理验证](advisor-session-validation.md)与[助手说明](advisor.md)。已有验证不等于真实模型的摘要保真度、用量准确度和延迟已经全部验收。

本文保留最初需求及其阶段措辞；“只写需求”不再表示当前未开发。第 11 节中的跨联系人讨论已另行实现，其余后续提案及共同验收事项统一见[需求待办清单](requirements-todo.md#future)。

本需求完善主动聊天助手。目标是让用户知道助手用了多少上下文，能手动压缩长讨论，并能在同一联系人下找回或新建不同讨论。本轮交付 **上下文可视化、手动压缩、历史会话、新建会话** 四项。本稿只写需求，不实施应用代码。

v0.3 新增的三项用户决定：

- 长讨论优先保留关键内容：先分段摘要；仍装不下或整理失败时，保留问题并提示重试，不自动丢弃早期讨论后继续回答。摘要可能损失细节，不承诺逐字无损。
- 已停用或删除助手的会话，通过历史列表中折叠的“其他助手历史”入口只读查看，只限当前账号与联系人。
- 顶部“更多”菜单常驻“压缩上下文”入口；没有用量读数时仍可找到，数字继续隐藏。

本版同时补齐计量验证、小窗口压缩、旧资料失效、重建去重和删除一致性的实现要求；沿用 v0.2 其他已定交互，包括回答中禁用压缩、`/reset` 并入 `/new`、单会话删除、自动重建和不同会话不限制并发数量。

## 1. 已确认的决定

| 事项 | 决定 |
| --- | --- |
| 范围 | 四项都在本轮交付；阶段划分只决定先后，不缩减范围 |
| 风格 | 简约，贴近微信电脑版；非必要元素不出现，技术细节不进入界面 |
| 上下文显示 | 输入区一行灰色小字“上次输入 / 窗口”，点击后显示三行详情和“压缩上下文” |
| 无读数时的压缩入口 | 用量数字隐藏；顶部“更多”菜单内的“压缩上下文”入口始终保留 |
| 回答中压缩 | 按钮置灰，提示“回答完成后可压缩”；不登记待执行的压缩请求 |
| `/reset` | 作为 `/new` 的兼容别名，不停止任何任务；停止任务只通过停止按钮 |
| 删除会话 | 本轮提供单会话删除（右键，需确认）；进行中的会话不可删除 |
| 原生会话不可用 | 下次提问时自动重建去重后的讨论上下文，成功后标注“已重建上下文”；仍失败则保留问题供重试 |
| 长历史装不下 | 优先分段整理以保留关键内容；仍失败则暂停本次回答，不自动舍弃早期内容继续 |
| 换模型 | 优先续用原生会话；不兼容时受控重建，保持业务会话连续；按目标模型预算处理超长历史 |
| 并发 | 不限制同时运行的会话数量；同一会话内回答与压缩互斥 |
| 历史范围 | 默认当前微信账号、当前联系人、当前助手模板；折叠“其他助手历史”只读展示该联系人下已停用或删除助手的会话 |
| 压缩摘要 | 只读，可回看；不提供编辑或撤销 |
| 草稿 | 按会话存入账号数据库，自动保存，切回恢复 |

本稿与此前版本冲突时，以本稿为准；本版不改变四项交付范围，也不授权本轮开始编写应用代码。

## 2. 范围与概念

| 概念 | 含义与边界 |
| --- | --- |
| 微信聊天记录 | 用户与联系人之间的原始消息；助手的新建、切换、压缩、删除都不修改它 |
| 助手会话 | 用户与 AI 围绕某个联系人的一段讨论；同一联系人、同一助手可以有多段 |
| 资料摘要 | 为装入模型窗口而生成的微信资料摘要；可被多段会话复用，不混入助手推测 |
| 会话压缩 | 把会话较早的讨论整理成工作摘要，保留近期讨论，供后续回答继续使用 |
| 关系记忆与目标 | 由[知己分析](friend-profile-requirements.md)管理；压缩不会确认记忆，新建或删除会话也不会删除记忆 |

本轮命令只有 `/compact`、`/new`、`/sessions`，`/reset` 作为 `/new` 的隐藏别名。命令和普通按钮调用同一业务操作。

本轮不做：移植完整 OpenCode 客户端；文件写入、命令执行、公开分享、联网搜索；跨联系人综合讨论；会话分叉、消息编辑、撤销重做；会话搜索、导出、回收站。自动三条回复建议保持独立，不出现在会话列表中，也不因新建、压缩、删除而变化。

群聊沿用现状，可以使用助手会话。群聊会话不注入关系记忆，因为按知己分析 v0.3，关系记忆只来自私聊。

## 3. 当前基础与缺口

助手使用固定的 OpenCode 1.18.34 引擎和自定义界面，已有原生多轮会话、微信资料分层摘要和后台继续生成。

| 能力 | 当前实现 | 本轮补齐 |
| --- | --- | --- |
| 自动压缩 | 原生配置启用 `auto` 与 `prune`；只发出短暂的“正在压缩”“已压缩”状态 | 改用讨论摘要提示词，保存可回看的压缩记录 |
| 上下文用量 | Runtime 只返回 input、output、reasoning，Python 不保存 | 按统一口径计算，持久保存并展示 |
| 斜杠命令 | 只识别 `/reset`，行为是停止当前任务再新建 | 受控解析本轮命令；`/reset` 改为 `/new` 的别名 |
| 历史会话 | 数据库保留旧 thread，读取和发送都只认最新 thread | 持久化当前选择，可列出、恢复、改名、删除指定会话 |
| 新建会话 | new-thread 停止当前任务后再创建 | 新建不打断任何任务 |
| 草稿 | 浏览器本地存储，按“账号＋联系人＋助手”保存 | 按会话存入账号数据库 |

### 3.1 必须验证与处理的前提问题

以下核对与修复列入本轮必做。源码可确认的行为与尚需实测的影响分开描述，不能把风险推断当成已复现故障。

1. **微信资料重复占用的风险。** 当前资料预算没有完整计入原生讨论历史，Runtime 又要求每轮完整读取资料文件。重复工具输出可能推高下一轮的有效输入；但资料较短时实际只返回相应资料，原生配置也已启用 `prune`，不能据此断言每轮都接近满窗口或必然频繁压缩，8192 也只是未配置时的回退值。用固定版本引擎和合成数据实测，确保下一轮完整输入（系统与技能、有效讨论历史、本轮资料、提问及工具开销）在可用预算内，避免在有效模型输入中重复堆入同一份资料。允许保留原生持久历史用于回看；不以物理删除旧读取作为唯一实现手段，也不删坏工具调用与结果的对应关系。
2. **讨论摘要提示词不完整。** 原生 `compaction` agent 当前使用为中立聊天证据设计的 `COMPACTOR_PROMPT`，未明确要求保留讨论目标和决定。自动与手动压缩都采用第 6.2 节的讨论摘要要求，并用合成案例验证；微信资料摘要继续使用原提示词。
3. **用量缺少缓存计量信息。** Runtime 当前未向业务层传递缓存读取和写入字段。补齐字段并验证各协议的统计口径，不能在验证前假定一套加法适用于所有网关，见第 5.2 节。
4. **换模型后讨论上下文可能断开。** 当前模型指纹（包含窗口大小）变化会清掉原生会话绑定，界面历史仍保留。改为优先兼容续用，必要时按第 8.1 节受控重建；验收业务讨论正确延续，不要求不兼容情况下仍使用同一个原生 ID。

当前工作区还有媒体接入、知己分析等未提交的改动，实施前须重新核对。

## 4. 界面与日常流程

沿用现有助手面板（宽 440），风格与微信电脑版一致：白底列表、浅灰分隔线，绿色只用于主要操作，复用现有样式变量，不加装饰卡片、徽标或重复标题。

- **顶部**：当前会话标题，旁边是“历史”“新建”和“更多”图标按钮；“更多”内常驻“压缩上下文”，不因缺少用量读数而隐藏。
- **输入区**：发送按钮旁一行灰色小字显示上下文用量，没有读数时不显示。
- **历史列表**：在助手区域内按需展开，选中后回到讨论；其中“其他助手历史”默认折叠，只读列出当前联系人下已停用或删除助手的会话，不新增常驻侧栏。

日常流程：打开联系人 → 恢复该联系人下上次选中的会话 → 提问 → 换主题时新建 → 需要时从历史列表找回旧讨论。后台另一段会话出结果，不会把用户自动切过去。

- 每段会话各自保留草稿、滚动位置、运行与错误状态，切走时暂存，切回时恢复。
- 没有历史时显示“开始新讨论”。没有可读资料、模型未配置、加载失败分别提示，不显示成空历史。
- 输入 `/` 时弹出命令菜单，每项附一句中文说明，键盘和鼠标都能选择；中文输入法组合输入时不误发送。
- 长标题省略显示，悬停可看全文。浅色、深色、小窗口下操作都可见。状态用文字表达，不只靠颜色。

## 5. 上下文可视化

### 5.1 显示内容

上下文用量指一次模型推理实际读入的内容，不是历史消息条数，也不是累计消耗的 token。

- **主视图**：灰色小字，例如“24k / 128k”。数值为估算时前面加“约”。压缩完成但还没有新读数时显示“已压缩”。
- **详情浮层**（点击小字打开）只有三行和一个按钮：
  - 上次输入：数值及记录时间；
  - 窗口：当前生效的窗口大小；
  - 最近压缩：时间，以及自动还是手动；没有压缩过则不显示这一行；
  - “压缩上下文”按钮：回答进行中置灰，提示“回答完成后可压缩”。
- 数据来源标签、调用编号、输出预留与安全余量、输入构成、媒体等其他请求的消耗，本轮都不进界面，只写入开发日志。
- 顶部“更多”菜单提供同一个“压缩上下文”操作；没有读数时隐藏数字，不隐藏该入口。尚无可压缩历史、回答中或压缩中仍按第 6 节显示真实可用状态。开发日志仅记录必要的计量与状态元数据，不记录密钥、聊天正文、媒体或摘要正文。

### 5.2 统计口径

1. **上次输入**取本会话最近一次模型调用最后一步实际读入的 token。缓存 token 仍属于输入，但须在 OpenCode 1.18.34 上以非零缓存读写的合成响应验证各协议归一化语义：仅在 `input` 确实排除缓存时采用 `input + cache.read + cache.write`；已包含的部分不能再次相加。网关字段缺失或语义不明时标为估算或隐藏，不凑出精确值。output 和 reasoning 不计入这项读数。
2. 不累加历轮用量。同一轮多次工具调用，只取最后一步，不把每一步的输入相加。
3. 每条读数都绑定会话、原生会话、模型指纹和上下文版本，按运行保存。换模型、重建原生会话或资料重建后，旧读数只作历史，不当作当前值。
4. 不为了刷新数字额外调用模型。没有服务端读数时可以保守估算并标“约”；字符数不能直接当作 token 数。缺失、负数或不合法的读数一律不显示，不能显示成 0。
5. 媒体观察先由独立的视觉请求生成，原始图片请求的 token 不计入助手会话；最终读入的观察文字计入。

### 5.3 生效窗口

目前 Python 资料预算默认 8192，Runtime 原生窗口默认 32768，未配置时两者不一致。本轮由后端在一处解析“生效配置”：总窗口、输出预留、可用输入预算和资料预算都从这里得出，前端不再硬编码默认值。窗口取值顺序是：用户配置 → 模型列表返回值 → 统一默认值。超出支持范围时明确报错，不静默截断。

自动压缩阈值与这份生效配置一致，本轮不另设固定的百分比规则。服务端返回上下文超限时，保留问题与已有结果，提示压缩或缩短输入，不自动无限重试。系统提示、技能资料或单条输入本身就超出窗口时，提示缩短相应内容，不循环压缩。

## 6. 手动与自动压缩

### 6.1 操作语义

“压缩上下文”和 `/compact` 压缩当前会话较早的讨论。压缩后仍在同一会话内继续，不新建会话、不触发新回答，也不重新分析联系人。手动压缩调用 OpenCode 对当前原生 session 的压缩能力；现有的临时 compactor 只负责微信资料摘要，不能把它的输出贴进聊天就算完成会话压缩。

- **回答进行中**：按钮置灰，`/compact` 提示“回答完成后可压缩”，不登记待执行请求。
- **压缩进行中**：本会话暂停提交新提问，发送按钮提示“正在压缩”。草稿仍可编辑，也可以浏览、切换会话。其他会话不受影响。
- **无需压缩**：还没有原生 session、历史太短，或引擎判断无需压缩时，提示“当前无需压缩”，不伪造成功。
- **离开不取消**：压缩请求被后端接受后，切换联系人、切换会话、收起面板都不会取消；切回时读取真实状态，不重新调用。
- **压缩的效果**：减少后续模型输入，原有提问、回复和微信资料仍可浏览。不承诺引擎已裁剪的工具输出仍能逐字保留。
- **时间线事件**：自动压缩与手动压缩都留下同样的折叠事件。
- **停止压缩**：执行中提供针对本次压缩的停止按钮；不停止其他会话。停止请求后先核对原生结果，若摘要已经提交则如实显示完成，不宣称已回滚；仍不确定时显示“核对中”。

### 6.2 摘要内容

会话摘要需保留：用户的问题与目标、已确认的决定、未完成事项、关键约束、待核实的假设和相关证据引用，并区分“朋友说过”“用户自己的解释”“助手建议”。自动压缩也使用这份要求（见 3.1 第 2 条）。

时间线显示一条折叠的“上下文已压缩”事件，展开后可查看引擎生成的摘要文本。这不是模型的内部思考，也不另外让模型解释思路。引擎拿不到摘要时，显示“已压缩，摘要暂不可查看”，不额外生成一份冒充。

压缩摘要不写入关系记忆候选或已确认事实。助手不能因为某句话出现在压缩摘要中，就把原来的推测升级为朋友的自述。

每次压缩保存一条记录：操作编号、所属会话与原生 session、自动或手动、开始与结束时间、状态、摘要（能取得时）、覆盖的讨论边界与资料版本（能核验时）、压缩前后读数（能取得时）。取不到的项目标为缺失，不做估算。无法核验覆盖边界的摘要可以只读展示，但不能用于自动重建时排除原问答，避免遗漏或重复。

### 6.3 失败与一致性

状态分为执行中、完成、失败、已停止、待核对；进程退出后可标记中断。只有确认原生会话压缩已完成才显示完成；HTTP 请求被接受、或模型返回了任意文本，都不算完成。只有核对确认操作未完成且已停止，才标记已停止。

- 接口超时或事件断开时，先查询原操作的结果，不立即重新提交。后端请求幂等，前端刷新不改变操作编号。
- 失败时保留显示的历史和最后已知的可用状态。引擎状态不确定时显示“核对中”，暂缓本会话的新提问。须实测固定版本引擎的失败原子性，不能假定失败一定没有副作用。
- 重试只针对失败的压缩操作，不重复提交上一条提问。
- 应用退出时不承诺在后台继续。重启后核对引擎状态：确认已完成就显示完成，否则标为中断，由用户决定是否再次压缩，不自动重放。

## 7. 会话管理

### 7.1 历史列表与恢复

- **范围**：默认列当前微信账号、当前联系人、当前助手模板下的会话；“其他助手历史”折叠区补充同一联系人下已停用或删除助手的会话，按原助手分组。会话用稳定 ID 区分，不按显示名归并。只列用户可见的业务 thread，过滤资料压缩、视觉分析、自动三候选等内部 session。
- **列表项**：标题、最后活动时间、最新内容的一行预览，以及“进行中”或“失败”状态。标题取第一条提问的前若干字，不调用模型命名；右键可改名或删除。
- **排序**：按最后活动时间。列表打开期间，后台更新只刷新状态，不让条目在用户点击时突然移位。本轮不做搜索和分页。
- **恢复**：选中后恢复该会话的记录、草稿、滚动位置和运行状态。打开列表、选择会话、浏览旧记录都不调用模型，也不重新读取全部微信历史。长会话的正文分段加载。
- **当前选择**：按“账号＋联系人＋助手”持久保存。重新打开面板时恢复上次选中的会话；只有升级后首次、还没有选择记录时，才按原来的最新 thread 设一次默认值。
- **继续旧讨论**：使用当前可用的微信资料，以及当前生效的记忆与目标；旧回复保留当时的语境，不改写。
- **模板停用或删除**：通过“其他助手历史”展开查看，输入框和生成、压缩操作禁用并说明原因，不悄悄换成别的助手。保留可识别原助手的历史名称或标识，即使所有模板都已删除，历史入口仍可访问。只读查看不覆盖正常会话的草稿或把它误记为当前可继续生成的助手；关闭只读查看后返回此前选择。会话改名与删除仍按本节的本地管理规则执行。

### 7.2 新建会话

新建按钮、`/new`、`/reset` 三者行为相同：

- 原会话的任务继续在后台运行，原会话完整保留，随时可以切回。
- 新会话不继承旧讨论或旧压缩摘要，但仍可使用这个朋友的微信资料和已确认的关系记忆。“新建”不等于忘记这个朋友。
- 新建本身不调用模型。如果当前会话已经是没有消息、没有任务、没有草稿的空会话，就直接复用。连续点击、网络重试、命令重放都只会产生一段会话。
- 旧会话的草稿保留，新会话从空白开始。命令文字不作为草稿或消息保存。创建失败时留在原会话，保留输入内容并显示错误。

### 7.3 删除会话

- 在历史列表中右键选择“删除”，确认后永久删除。本轮没有回收站。
- 进行中或压缩中的会话不能删除，菜单项置灰并提示“停止后可删除”；压缩结果待核对时提示“状态核对后可删除”，不能把未确认结束的任务当成空闲。
- 删除范围：该会话的消息、草稿、用量、压缩记录与派生恢复摘要，以及属于该会话的当前及此前换代的原生 OpenCode session。微信聊天记录、共享资料摘要和关系记忆不受影响。
- 删除的是当前会话时，切到最近活动的另一段会话；没有其他会话时，显示“开始新讨论”。
- 删除时在与任务启动共用的锁或事务边界内核对归属及空闲状态，然后持久标记为待删除，拒绝新的发送、压缩、草稿写入和迟到结果。若同时已有新任务获准运行，则删除失败并提示该会话忙碌，不能通过删除隐式停止它。
- 本地记录与原生 session 无法用同一个事务删除时，用可恢复的清理操作记录衔接。清理中把条目标为“正在删除”且不可打开；任一侧失败显示“删除未完成，可重试”，不报告永久删除成功，也不恢复成可继续聊天的会话。重复请求、应用重启和迟到事件不能重复创建或复活它。
- 完成后可保留不含正文、标题或摘要的必要操作标记，用于拒绝旧请求；这些标记也随账号清除。单会话删除不等于清理既有手工备份或提供磁盘安全擦除。

### 7.4 命令

- 只有整条输入（允许首尾空白）与命令完全一致时才执行。本轮命令不带参数。
- 其他以 `/` 开头的输入一律当作普通文字发送，不弹确认，也不调用不存在的能力。粘贴的内容里夹带命令，不会执行。
- 命令菜单就是帮助，本轮不单独提供 `/help`。命令与按钮共用同一套可用状态、失败与重试规则。

### 7.5 并发

- 不限制同时运行的会话数量。切换会话或新建会话都不会停止已接受的任务。
- 同一会话同一时间只允许一个会修改原生历史的操作，回答与压缩互斥；不同会话之间互不影响。
- 模型服务因并发返回限流或超时时，按现有的错误提示和重试规则处理，不在应用侧降低并发。
- 自动三候选保持现有的去重规则，以及“等待当前联系人手动任务”的规则。多会话下，“联系人是否忙”须检查该联系人所有会话，不能只看前台会话。知己分析后台任务的让行规则以其需求为准，但不能因此限制助手会话。

## 8. 数据身份与恢复

业务 thread 是长期稳定的用户会话；原生 OpenCode session 是它当前使用的引擎状态。两者之间有受控映射：原生 session 变化时，业务 thread、显示历史和上下文边界保持不变。

| 状态 | 隔离维度 | 要求 |
| --- | --- | --- |
| 当前选择 | 账号、联系人、助手 | 持久保存选中的 thread；窗口的展示代次单独管理 |
| 消息、草稿、运行、压缩、用量 | 账号、联系人、助手、thread | 不再只按“账号＋联系人＋助手”覆盖缓存与草稿 |
| 原生会话 | thread、来源、上下文版本 | 当前用量对应实际的原生会话；旧读数留作历史 |
| 用户操作 | 目标 thread、操作编号 | 发送、压缩、停止、新建、删除可去重，迟到响应可核对 |

- 发送请求必须指明目标 thread，并带上操作编号。thread 不会因为新建而作废，因此原有的“只有最新 thread 才能发送”的保护改为：核对 thread 归属、未进入删除流程，以及当前资料与操作版本有效。已接受请求的重试返回原结果，不复活已停止的任务；已删除会话只返回已删除状态，不重放旧正文。
- 切换视图只改变展示，不撤销已提交的任务。迟到的事件和响应只写入它所属的 thread，不覆盖其他会话，也不改变当前选择。
- 会话元数据、当前选择、草稿、运行、用量和压缩记录都保存在现有的账号数据库中，前端缓存只用于加快展示。跨窗口编辑以数据库为准，按记录和版本合并。
- 升级时，原来按“联系人＋助手”保存在浏览器本地存储的草稿，迁移到该联系人与助手下的最新 thread，因为升级前界面显示的就是它。迁移可重复执行，不产生重复消息。升级前备份本软件的数据库，保留旧消息、任务身份和已保存的原生 session。
- 清除账号时，一并清除本轮新增的会话索引、选择、草稿、用量、压缩记录、恢复摘要和删除操作记录，并排空相关任务。账号切换或清除后，旧视图立即遮蔽，旧事件不能写回。

### 8.1 原生会话的延续与重建

- **换模型或改窗口**：优先兼容续用原生会话。按目标模型重新估算下一次完整请求，包括有效讨论历史、本轮提问、最新资料、系统与技能、工具开销和输出预留；不能仅拿旧模型的上次输入读数判断是否能放下。在固定引擎中验证跨模型、连接与协议的兼容性，不兼容时受控重建。微信来源、模型连接身份和业务 thread 身份分别校验，不能通过删除账号或联系人归属检查来复用原生 ID。
- **小窗口压缩**：完整旧历史可能连目标模型的压缩请求也装不下。此时以当前已配置模型和明确的单次输入预算分段整理，再合并摘要；每次请求都满足预算，阶段数与重试有界。保持原数据与最后已验证状态，成功后才切换绑定；仍装不下或失败则保留问题并提示重试，不改用未经配置的服务，也不自动丢弃早期讨论继续回答。
- **自动重建条件**：原生 session 缺失或损坏、原生状态不兼容，或微信资料确实发生换代且原状态不能可靠续用时，下次提问自动重建，不弹选择框。区分正常追加消息的 `revision` 与资料来源或重建代次 `epoch`：普通新消息只更新本轮资料，不因此重建整个助手会话。只浏览历史不会触发重建。
- **重建内容**：优先使用具有可靠覆盖边界、资料版本仍有效的早期讨论摘要，加上该边界之后的问答和当前授权资料；同一段讨论不能既以摘要又以完整原文重复注入。旧摘要不可用或边界无法核验时，从本会话已保存问答按预算重新分段整理。中断回复标为未完成，不当作结论；不回放其他会话，不把助手推测当微信事实。原问答本身有缺失时停止无提示恢复，说明无法恢复的范围并保留问题。
- **关键内容优先**：长历史优先分段摘要，保留目标、决定、未完成事项及证据归因，成功后与近期原问答组合继续。仍装不下或整理失败时暂停本次回答，保留问题和原会话供重试，不采用“自动舍弃较早 N 轮后继续”的后备路径。摘要存在信息损失，不承诺模型逐字记得全部细节。
- **重建标注与重试**：只在恢复完成后显示“已重建上下文”，注明实际摘要覆盖范围与保留的近期范围；没有可核验边界不编造数量。重建中的状态、检查点和原问题关联同一操作，失败保留原记录与草稿，重试不重复追加提问或重复生成已完成回答。
- **归属无法确认**：来源归属无法验证时，只读显示本地历史，不跨账号、跨联系人重新绑定。
- **记忆与目标**：每轮从当前生效版本构造授权输入，按[知己分析需求](friend-profile-requirements.md)执行。仅替换系统提示不等于旧资料已失效；还须使旧工具资料、工作摘要和依赖它们的运行状态失效，可靠移除相关上下文或换代原生会话，拒绝旧版本迟到结果。重建时不能无条件回放包含过时记忆或目标的摘要、旧回复；按来源和版本排除失效材料或重新整理，旧问答仍保留在界面。删除记忆不代表从仍保留的微信原文中抹掉同一句话，但旧记忆不得继续作为已确认资料或现行指令注入。
- **配置变化中断任务**：账号共用的引擎因模型配置变化结束多个任务时，每个受影响的会话都要单独标记原因。应用关闭时正在执行的工作，重启后标为中断或待核对，不自动重复提问或压缩。

## 10. 交付顺序与验收

建议顺序：

1. 先验证并处理 3.1 的问题，统一生效窗口，并贯通用量与压缩记录的持久化。
2. 再实现按指定 thread 读取与选择、草稿迁入数据库。
3. 最后开放手动压缩、新建、删除和历史列表界面。

四项都是本轮目标。先用固定引擎和合成模型服务验证原生压缩、跨模型续用、并发边界与重建，再接入界面。真实服务的质量验证另行进行，模拟测试不能用来宣称真实 token 精度或摘要质量已验证。

| 编号 | 场景 | 验收结果 |
| --- | --- | --- |
| CTX-01 | 没有可靠服务端读数 | 无可用估算时隐藏数字，不显示 0；只有可靠估算时加“约”，不额外调用模型；更多菜单的压缩入口仍存在，按真实任务状态判断可用性 |
| CTX-02 | 各支持协议的多步调用、非零缓存读写、缺失字段与媒体观察 | 按核验后的协议语义计量最后一步实际输入；不累加、不重复计数，不含独立视觉请求；无法确认时不伪装精确值 |
| CTX-03 | 未显式配置窗口 | 前后端显示同一个生效窗口；资料预算由同一处配置得出 |
| CTX-04 | 固定合成资料、固定每轮问答长度与明确窗口，连续 10 轮 | 核对每次实际有效输入，避免完整资料随轮次重复堆叠；在事先确定无需压缩的预算案例中不因重复资料触发压缩，确实增长到阈值时正常压缩；不要求物理删除历史 |
| UI-01 | 详情浮层 | 只有上次输入、窗口、最近压缩三行和压缩按钮；不出现技术字段 |
| UI-02 | 没有用量读数，或正在回答、压缩 | 顶部更多菜单入口始终可见，与浮层及命令操作一致；回答中禁用，压缩中显示状态，均不登记待执行请求 |
| CMP-01 | 手动压缩成功 | 原提问和回复仍可浏览；后续回答使用压缩后的原生状态；没有虚构用户消息，不自动续写，不启动新回答 |
| CMP-02 | 回答进行中 | 压缩按钮置灰，`/compact` 给出提示；不登记待执行请求 |
| CMP-03 | 自动压缩 | 使用讨论摘要提示词；保存事件，切走或重启后仍可查看；没有新读数时显示“已压缩” |
| CMP-04 | 重复点击、断网、响应迟到 | 请求去重，先核对原操作；不会压缩多次，不串到其他会话 |
| CMP-05 | 压缩失败、停止或进程中断 | 原记录与草稿保留，状态真实；不显示没有发生的成功或回滚 |
| CMP-06 | 系统提示或单条输入过大 | 明确提示无法靠压缩解决，不无限重试 |
| SES-01 | A 正在回答时新建 B，并向 B 提问 | A 在后台继续；B 使用自己的上下文；两者同时运行，没有数量限制 |
| SES-02 | 同一联系人、同一助手下的 A 与 B | 草稿、滚动、停止、用量、错误、压缩记录互不覆盖 |
| SES-03 | 打开 A，关闭后再回来 | 仍恢复 A；B 的后台结果不抢占选择 |
| SES-04 | `/reset` | 与 `/new` 行为相同，不停止任何任务 |
| SES-05 | 删除会话 | 进行中的不可删；删除后消息、草稿、用量、压缩记录、原生 session 一并清除；微信记录和关系记忆不受影响；删除当前会话后正确切换 |
| SES-06 | 升级时已有多段 thread 和一份旧草稿 | 历史保留可达；草稿绑定到最新 thread；迁移重复运行不产生重复数据 |
| SES-07 | 部分或全部模板停用、删除 | 从当前联系人历史中的“其他助手历史”展开只读查看；输入和压缩禁用，不切换成其他助手继续，不覆盖原会话草稿；全部模板删除后入口仍可达 |
| SES-08 | 删除与新提问、草稿保存竞态；引擎删除失败、重试或进程退出 | 原子确定任务启动或删除先后；待删除拒绝写入，失败真实提示且可续清理，迟到请求不复活数据；相关换代 session 也被清理 |
| REC-01 | 大窗口换明显更小窗口，旧历史连压缩请求也装不下 | 按目标模型核算完整请求，必要时有界分段整理；兼容时续用，不兼容时受控重建，保持业务会话与归属；失败不丢弃早期讨论继续回答 |
| REC-02 | 原生 session 缺失或微信资料确实换代 | 下次提问自动重建，成功后显示标记与可靠的摘要、近期原文覆盖范围；浏览历史不触发重建 |
| REC-03 | 旧工具输出、压缩摘要及回复中已有记忆，再删除记忆或修改目标 | 旧资料上下文正确失效，迟到旧版本结果被拒绝；续用或重建不会把旧记忆当作已确认资料或旧目标当作当前指令，界面问答保留 |
| REC-04 | 仅追加一条普通微信消息 | 只更新本轮资料，不因 revision 改变重建整个原生会话 |
| REC-05 | 早期讨论已有带覆盖边界的摘要 | 摘要与其后的原问答无重复；边界或资料版本不可验证则重新整理，不凭猜测排除旧问答 |
| REC-06 | 分段整理失败或合并后仍装不下 | 暂停回答，原会话与问题完整保留供重试；无自动舍弃早期 N 轮的路径，重试不重复追加问题或完成的回答 |
| SCP-01 | 账号清除、同名联系人、另一窗口的迟到事件 | 作用域核对有效；旧数据不复活，不写入其他会话，不覆盖新选择 |
| CMD-01 | 命令、按钮、中文输入法、粘贴的引用 | 命令与按钮行为一致；只有完全匹配才执行；其他 `/` 开头的输入按普通文字发送 |
| AUTO-01 | 新建、浏览、删除会话期间自动三候选在运行 | 不改变自动建议开关，不混入历史，不重复生成；忙碌判断覆盖该联系人的所有会话 |

实现完成后同步更新[助手说明](advisor.md)，记录真实支持的命令、测量限制与恢复行为。本稿不能当作已实现功能的说明。

## 11. 后续

以下不在原会话管理交付范围，尚待单独设计：会话标题搜索与全文检索、历史导出、回收站、压缩摘要编辑与撤销、输入构成占比展示。跨联系人讨论已在后续版本实现，见[助手说明的“跨好友讨论”](advisor.md)；它不再列为未实现项。如果将来本地模型因并发吃紧，再讨论可选的业务会话并发上限；实际模型请求已受核心模型服务的并发额度约束。

最容易低估的工作是：有效输入的资料去重、统一 token 口径、替换最新 thread 假设、草稿与缓存细化到 thread、核对原生压缩的失败状态、跨模型续用与自动重建，以及删除的可恢复清理。这些与界面入口同属验收范围，不能只加几个按钮就算完成。
