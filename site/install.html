v2.1.0 · Windows 10/11 x64 · 本机 MCP

让 AI 帮你安装知己

把下面这句话发送给你正在使用的 AI 客户端。Agent 按本页选择安装方式、合并配置并检查连接，你在安装界面及知己授权窗口完成确认。

请阅读 https://zhiji.eugenepage.com/install.html，帮我安装知己微信助手并接入当前客户端。

给 Agent 的安装要求：引导用户完成安装和账号授权；等待用户在知己窗口确认授权后，再验证 MCP 连接。请勿代替用户确认授权。

先确认运行环境和客户端

安装与 MCP 进程运行在同一台 Windows 10/11 x64 电脑、同一个 Windows 用户下。Agent 需要能够访问网络、运行 PowerShell 和编辑该客户端的配置。仅有网页聊天、远程 Linux 或 WSL 环境时，请转到 Windows 本机执行。知己自带 Python 与 Node.js。

以当前对话所在的客户端为准。如果无法识别，请向用户询问。每个客户端使用独立连接档案。以下选择对应 v2.1.0 已发布脚本。

当前客户端安装参数配置方式
Claude Code-Client claude-code脚本合并用户级 MCP 配置
Codex-Client codex脚本合并 ~/.codex/config.toml，尊重 CODEX_HOME
Cursor-Client cursor脚本合并 ~/.cursor/mcp.json
DeepSeek Harness-Client deepseek-harness脚本合并对应的用户级 MCP 配置

其他支持本机 stdio MCP 的客户端-Client generic --name <独立连接名>按客户端官方说明合并生成的配置

Claude Code 已做真实客户端图像传递验证。Codex、Cursor 和 DeepSeek Harness 提供配置适配。WorkBuddy 路径与 stdio 格式依据官方说明，尚未完成真实 WorkBuddy 客户端验收。图片显示、新消息提示及配置热加载取决于客户端。

下载安装脚本并校验

使用官方 v2.1.0 附件。下面的 PowerShell 命令把脚本存到本机临时目录，并核对 SHA-256。该脚本还会校验它下载的 Windows 安装包。

$ErrorActionPreference = 'Stop'
$zhijiInstaller = Join-Path ([IO.Path]::GetTempPath()) ('install-zhiji-' + [guid]::NewGuid().ToString('N') + '.ps1')
Invoke-WebRequest 'https://github.com/youdrew/zhiji-wechat-assistant/releases/download/v2.1.0/install-zhiji.ps1' -OutFile $zhijiInstaller -UseBasicParsing
if ((Get-FileHash -LiteralPath $zhijiInstaller -Algorithm SHA256).Hash -ne '648b291c941968918ea7dbab7eba2d6bd59d22d281969d28bec2f122ac452d25') { throw '知己安装脚本校验失败' }

安装、配对并连接

在同一个 PowerShell 会话中，选择当前客户端的命令。如果 Agent 的命令工具每次新建 shell，请将下载校验和所选安装命令放在同一次调用中，或在后续调用使用脚本的实际绝对路径。例如 Codex 使用

powershell -NoProfile -ExecutionPolicy Bypass -File $zhijiInstaller -Client codex -Yes

Claude Code 使用

powershell -NoProfile -ExecutionPolicy Bypass -File $zhijiInstaller -Client claude-code -Yes

WorkBuddy 使用

powershell -NoProfile -ExecutionPolicy Bypass -File $zhijiInstaller -Client generic -Yes --name workbuddy

-Yes 省去脚本重复询问是否下载，安装程序和账号授权仍需用户操作。需要先看计划时使用 -WhatIf。已装 v2.1.0 会复用安装；如检测到旧版本，请先通过官方安装包升级。安装在自定义目录时可加 -InstallRoot。

保持安装任务运行，等待用户在知己窗口选择允许读取的账号并确认。默认只读。配对期间 Agent 应提示用户查看窗口，保持进程存活并等待结果。授权应由用户确认。遇到超时可重新运行同一命令。

基础查询使用当前 AI 客户端的模型。用到好友分析、自我分析等知己专项能力时，再配置知己的模型服务。

WorkBuddy 与其他客户端的配置合并

通用模式输出一个包含 mcpServers 的 JSON 片段，其中的 command 和 args 已指向安装自带的 Python、MCP 启动脚本和此次连接档案。保留输出中的完整命令与参数，使用 stdio 传输。

  1. WorkBuddy 默认使用当前 Windows 用户的 ~/.workbuddy/mcp.json。如果当前项目有 .workbuddy/mcp.json，检查同名条目是否覆盖用户配置。
  2. 修改前备份原文件，解析原 JSON，只合并本次生成的知己条目，保留其他服务器和顶层字段。写入前复查文件没有被其他进程改动，再原子替换。遇到损坏或无法解析的配置，先报告具体问题。
  3. 如果客户端限制修改配置，使用它的“插件 → MCP 服务器 → 配置 MCP”入口导入该片段。其他客户端按官方文档选择配置路径及包装格式。
  4. 客户端配置只需保存启动命令与档案名。配对凭据由知己在本机加密保存。

WorkBuddy 此时走通用模式。脚本的“连通已验证”只证明生成的 MCP 命令可用，配置合并和客户端实际加载仍要完成。

确认接入成功

脚本会实际运行 MCP 的 initialize、tools/list、zhiji_ping 与 zhiji_list_accounts。随后按客户端要求重新加载 MCP 或新开会话。在当前客户端调用 zhiji_ping，确认服务可用及授权范围。需要检查账号时只向用户报告数量和范围。

如果本轮对话无法加载新工具，明确告知“安装和配置已完成，等待重新加载后验证”，并给出重新打开会话后的验证步骤。最终成功应以当前客户端实际调用工具为准。

Claude Code 用户可选择额外添加 --install-hook，在下一次提问时收到新消息提示。其他客户端可通过 MCP 查询与补拉事件。用户可在知己“设置 → 插件 → MCP”中撤销授权。
